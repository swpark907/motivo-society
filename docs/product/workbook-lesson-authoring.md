# 워크북 수업 만들기 — 기획·원고·화면 규칙

2026-11-13 · 1-0 클래스 인트로와 1-1 AI란 무엇인가를 만들면서 승우와 정한 규칙을 한곳에 모았다. 워크북 수업이나 장면을 새로 만들거나 고칠 때 이 문서를 따른다. Codex·Claude 공용이며, Claude는 `.claude/skills/workbook-lesson/`의 스킬이 이 문서를 읽고 작업 순서를 안내한다.

결정의 원래 기록은 `AGENTS.md`의 "Workbook 경험 원칙", [1단원 기획](workbook-unit-1-plan.md), [수업 공통 레이아웃](workbook-lesson-frame-plan.md), [반응형 높이 기준](workbook-responsive-lesson-layout.md), [강의 시작 표지](workbook-lesson-covers.md)에 있다. 이 문서와 원래 기록이 다르면 원래 기록(더 최근 결정)을 따르고 이 문서를 고친다.

## 1. 기획 — 화면 흐름부터 정한다

- **수업마다 화면 흐름표를 먼저 만든다.** 열: 번호 · 제목 · 핵심 문장 · 표현 방식. 기획 문서(예: `workbook-unit-1-plan.md`)에 표로 남기고, 구현하면 "(구현됨)"과 실제 모습을 그 칸에 적는다.
- **흐름은 "왜 필요한지"로 잇는다.** 1-1 예: 만드는 AI → 코드도 글자라서 만든다 → 그래서 대화로 고쳐 가며 만든다 → 그 바탕이 LLM → 대표 LLM → 정리. 수강생이 궁금해하지 않거나 영양가가 약한 주제(일상 속 AI 나열, 다음 말 예측 원리 등)는 뺀다.
- **기획자가 주제를 내면 그 흐름을 따른다.** 에이전트의 대안 주제를 여러 번 밀지 않는다. 제안은 한두 개 대안과 고른 이유까지.
- **첫 화면은 결론부터 말하지 않는다.** 지금 서 있는 자리(앞 수업에서 한 것) → 누구나 아는 일상 장면 → 발견 순서로 다가간다. 1-5 화면 1은 처음에 "막연하게 부탁하면 AI가 짐작으로 채워요"라는 결론 제목과 AI 답 세 편을 읽게 했다가 "갑작스럽고 안 읽힌다"는 지적을 받고, 심부름 메모와 봉투 세 개로 다시 만들었다(2026-11-17).
- **한 화면에 한 가지 일.** 배우는 화면과 직접 쓰는 화면을 나눈다. 누를 것이 많으면 복잡해 보인다. 1-5 화면 2는 입력 칸 네 개 + 예시 조각 여덟 개 + 옆 미리보기를 한 화면에 넣었다가, 이름표 메모 한 장을 보여 주기만 하고 쓰기는 다음 화면으로 옮겼다.
- **예전 화면을 이어받지 않는다.** 수업을 새로 만들 때 이어 가는 것은 기록 형태와 준비 상태에 따른 갈림뿐이다. 예전 문구·구성은 주제부터 다시 정한다(1-5, 2026-11-17).
- **마지막 화면은 정리.** 배운 것 세 가지 + 단원에서 이어서 배울 것. 정리의 형식도 수업마다 바꾼다(1-1 카드 세 장, 1-2 공책 한 장, 1-3 영수증, 1-4 출입증, 1-5 메모판, 1-6 액자).
- **수업은 다섯 장 + 정리(6화면)를 기본으로 한다.** `WorkbookLessons.tsx`에서 1-1·1-2가 같은 틀을 쓴다. 퀴즈·정답 판정은 1단원 앞 수업에 두지 않는다.

## 2. 표현 방식 고르기

- **섞되 과하지 않게.** 줄글로 충분한 곳은 줄글, 장면이 이해를 돕는 곳은 장면, 그 밖에 비교 카드·표·대화 장면·직접 조작을 내용에 맞게 고른다. 형식이 화면마다 바뀌어 학습을 방해할 정도로 다양하게 쓰지 않는다.
- **큰 연출(콜라주)은 핵심 화면에만.** 한 수업에 한두 번. 1-1은 화면 1(만드는 AI)과 화면 5(대표 LLM)만 콜라주이고, 사이는 비교 · 대화 · 줄글과 그림 · 정리로 조용하게 둔다.
- **에이전트는 화면마다 "무엇을 어떻게 보여주고 어떻게 움직일지"를 먼저 제안한다.** 확정 전에는 구현하지 않고 기획자의 선택을 받는다.
- 표현 방식의 예(1-1에서 쓴 것):
  - 콜라주 장면 — `WorkbookAiEraCollage`, `WorkbookLlmCollage`
  - 나란히 비교 + 직접 눌러 보기 — `WorkbookCodeIsText` (문장과 HTML의 여는·닫는 표시를 같은 형광펜 색으로 짝짓기, "화면으로 보기")
  - 대화 장면 — `WorkbookChatGrowth` (요청 → AI가 쓰는 중 → 답 → 결과 화면이 자람)
  - 줄글 + 포함 관계 그림 — `WorkbookLlmNested`
  - 정리 — `WorkbookLessonRecap`
  - (1-2에서 더함) 결과물 그림 카드 — `WorkbookAiKinds` · 4컷 만화 — `WorkbookAgentComic` · 직접 눌러 보는 연습 창 — `WorkbookAgentTryout` · 비교표 — `WorkbookWhyAgent` · 꼬리표 + 도는 그림 — `WorkbookAgentNames` · 공책 정리 — `WorkbookToolsRecap`
  - (1-3에서 더함) 가위질 — `WorkbookTokenScissors` · 책상 장면 — `WorkbookContextDesk` · 계량컵 재생 — `WorkbookUsageCups`(컵 그림 `WorkbookUsageCup`) · 메뉴판 — `WorkbookPlanMenu` · 스위치 — `WorkbookSavingHabits` · 영수증 정리 — `WorkbookUsageRecap`

### 형식 장부 — 앞 수업과 겹치지 않게

같은 형식이 수업마다 반복되면 지루해진다(2026-11-13 사용자 지적: 1-2 초안이 1-1과 비슷했다). 새 수업을 기획할 때 아래 표에서 **바로 앞 수업의 형식**을 먼저 보고, 같은 형식(특히 큰 연출)을 연달아 쓰지 않는다. 종이·카피바라 같은 문법은 유지하고, 형식(무엇을 어떤 틀로 보여주는가)을 바꾼다. 수업을 만들면 이 표에 한 줄씩 더한다.

## 3. 원고 — 말투와 사실

- **"~해요"체, 한 화면에 생각 하나, 설명은 세 문장 안팎.** 용어는 처음 나올 때 한 번 굵게. 기획자는 문장 끝을 "~합니다", "~하죠", "~해보겠습니다!"로 섞어 쓰기도 한다(2026-11-16, 1-2: "돌려줍니다", "직접 해야 하죠"). "~해요"만 이어지면 단조로우니 설명 문장은 "~합니다"·"~하죠"를 섞고, "우리 몫이에요"·"~하는 셈이에요" 같은 에두른 표현보다 "직접 해야 하죠"처럼 바로 말한다.
- **AI식 문장을 쓰지 않는다.** 반전·대구·여운형 끝맺음("셋 다 웹이에요. 이 강의도요."), "~에서 ~로" 같은 멋 부린 대비 제목을 피하고 담백하게 쓴다. 1-1 예: "만드는 AI의 등장" 대신 "AI가 하는 일이 달라졌어요".
- **흐름을 잇는 접속어는 살린다.** "하지만", "다만," 처럼 앞 화면과의 관계를 드러내는 말은 기획자가 직접 넣기도 한다(화면 3 제목 "다만, 한 번에 완성되지 않아요").
- **긴 설명은 문단을 나눠 숨 쉴 자리를 만든다.** 한국어 줄바꿈은 `word-break: keep-all`로 단어가 잘리지 않게 하고, 끊기면 어색한 구절은 묶는다(`white-space: nowrap`).
- **"AI가 생각한다"고 단정하지 않는다.** "우리가 쓴 글을 읽고 그에 맞는 글을 새로 만든다"처럼 하는 일로 쓴다.
- **워크북 밖에서 할 일이 있는 수업은 그 사실을 먼저 말한다.** 필요한 것(기기 · 계정 · 비용)을 첫 화면에 적고, 밖에서 한 일은 학습자가 직접 찍는 도장으로 남긴다(`WorkbookSetupStamps`). 워크북이 검사한 것처럼 쓰지 않으며, 지금 못 해도 읽고 넘어갈 수 있게 한다. 막히기 쉬운 곳에는 "막혔을 때"를 접어 둔다(1-4).
- **갑자기 묻지 않는다.** 무엇을 왜 하는지 말하고 → 시범을 보이고 → "해볼까요?"로 초대한다. 정답이 없는 활동은 그렇다고 밝힌다.
- **쓸모없는 안내를 붙이지 않는다.** "미리 만든 예시 장면이에요" 같은 문구는 쓰지 않는다. 실제 결과로 오해할 수 있는 곳에서만 구분한다.
- **사실은 공식 자료로 확인한 것만 쓴다.** 서비스 공개일 같은 사실은 각 회사의 공식 발표 글로 확인하고, 근거 URL과 확인 날짜를 기획 문서에 남긴다. 모델과 서비스를 구분한다(GPT는 모델 계열, ChatGPT는 서비스).
- **양을 그림으로 보여줄 때는 숫자를 붙이지 않는다.** 토큰 조각 수·컵 높이처럼 원리를 보여주는 그림은 실제 측정값으로 읽히지 않게 "예시예요", "작업마다 달라요"를 한 줄 적는다(1-3).
- **확인 날짜 표시는 바뀌는 정보에만.** 요금제·서비스 근황처럼 시간이 지나면 바뀌는 내용에는 화면에 "○○년 ○월 기준"을 붙인다. 첫 공개일처럼 바뀌지 않는 사실에는 붙이지 않는다.
- **남의 로고를 쓰지 않는다.** 회사·서비스는 이름을 우리 글꼴로 적는다(2026-10-31 결정. OpenAI·Google 지침상 로고는 허락이나 제휴가 필요). 실존 인물 사진도 쓰지 않는다.
- **비유어는 처음 나올 때 정체를 밝히고, 화면 안에서 같은 말을 쓴다.** "누군가에게 심부름" 다음 줄에 갑자기 "조수"가 나오면 누군지 멈칫한다(1-5 화면 1). "메모를 떼어 가다"처럼 동작을 비유할 때는 실제 동작(복사)을 같이 적는다.
- **이름표와 풀이는 같은 뜻이어야 한다.** "하지 말 것"의 풀이를 "넘겨짚지 않았으면 하는 것"으로 적었다가 뜻이 어긋나 "하지 않았으면 하는 것"으로 고쳤다.
- **두 뜻으로 읽히는 말을 피한다.** "쓰는 만큼도 아낄 수 있어요"는 '글을 쓰다'로도 읽힌다 → "사용량". 앞 수업의 제목(1-3 "AI를 쓰는 만큼")을 줄임말처럼 쓰지 않는다.
- **지시어에는 대상을 적는다.** "답은 그대로 두고"가 아니라 "Claude 앱의 답은 닫지 말고 띄워 둔 채". "작업 폴더를 확인해요"가 아니라 "Code 탭 오른쪽 '환경' 칸에서". 어디서 무엇을 하는지 한 번에 알 수 있게 쓴다.
- **이유를 모를 단계는 이유를 한 마디 붙이거나 뺀다.** 파일을 만들지 않는 요청에 "작업 폴더 확인"만 있으면 왜 하는지 모른다 → "다음 수업에서 쓸 폴더로 둬요".
- **워크북 밖에서 할 일은 끝까지 적는다.** "고칠 곳을 적어요"에서 멈추지 말고 "적은 글을 Claude 앱의 같은 대화에 보내고, 브라우저에서 새로고침해요"까지 쓴다(1-6 화면 4).
- **앞 수업에서 배운 원칙을 다음 수업의 예시가 어기지 않는다.** 1-5에서 "지어내지 마"를 배웠는데 1-6 메모가 "없으면 AI가 새로 써요"였다 → "글 자리만 비워 둬"로 고쳤다.
- **같은 메모·예시는 화면이 바뀌어도 같은 글이다.** 화면 3에서 메모에 문장이 슬쩍 더해지면 화면 2에서 배운 것과 달라 보인다. 필요한 문장은 처음 보여 줄 때부터 넣는다.
- **단정하지 않는다.** "AI는 잘된 문장까지 전부 새로 써요" → "잘된 문장까지 바뀔 수 있어요". AI의 동작은 늘 그런 것처럼 쓰지 않는다.
- **같은 성격의 표시는 이름을 하나로.** 연습용 답·메모에는 "(연습)"을 붙인다(1-5는 "(예시)", 1-6은 "(연습)"이었다가 통일).
- **목록 항목은 형태를 맞춘다.** 한 줄은 문장, 나머지는 조각이면 어색하다. 조각이면 모두 조각("세 문장", "편하고 친근한 말투").
- **Windows · Mac은 실제로 다를 때만 나눈다.** 띄어쓰기만 다른 순서를 고르게 하지 않는다(1-6 화면 3, 2026-11-18 사용자 지적). 단축키(Ctrl/⌘)처럼 한 줄로 같이 적을 수 있으면 같이 적는다.
- **AI 도구의 확인 절차는 "승인"으로 쓴다.** "허락을 묻습니다"는 어색하다는 지적(2026-11-18). "AI가 승인 여부를 묻습니다", "둘 다 맞으면 승인해요"처럼 쓴다. 설정에 따라 달라지는 동작은 "기본 설정에서는"을 붙인다.
- **단원을 마쳤다는 말은 실제로 마쳤을 때만.** 정리 화면의 "1단원을 마쳤어요"처럼 진행 상태를 말하는 문구는 진행 기록을 보고 띄운다.
- **읽으며 따라가는 사람에게 "내 파일"을 묻지 않는다.** 실습 방식을 고르는 수업이면 방식에 따라 칸 · 도장을 바꾼다(1-5 화면 5, 1-6 화면 3 · 4).
- **막아 둔 버튼보다 눌렀을 때 이유를 알려 준다.** 순서가 있는 연습에서 아직 누를 때가 아닌 버튼은 흐리게 막지 말고, 누르면 "아직 … 않았어요. 먼저 …"라고 답한다(1-6 화면 4 새로고침).
- **줄이지 말고 풀어 쓴다(2026-11-18, 2-1 화면 1 사용자 수정).** 만드는 사람 머릿속의 줄임말이 그대로 나오면 학습자는 뜻을 메워 읽어야 한다. 고친 예:
  - 생략된 말 → 온전한 문장: "○○ 찾는데… 아직 없네요." → "○○ 알고 싶은데, 이 페이지엔 아직 그 내용이 없네요."
  - 동작 비유 → 평이한 말: "누가 여느냐에 따라" → "이 페이지를 보는 사람에 따라", "다시 꺼냈어요" → "다시 가져와 봤어요".
  - 화면 부품 나열 → 수업의 목적: "○○의 눈으로 제목·버튼·담을 것을 골라요" → "이 홈페이지를 누가 방문할지 생각해 보고, 그 목적에 맞게 여러 시각적 요소들을 구성하는 것을 기획해 볼게요."
  - 쓰기 전 점검: 주어·대상·이유가 문장 안에 있는가, 내가 지은 이름("담을 것", "~의 눈")을 처음 보는 사람도 아는가, "이번 수업에서는"으로 시작하는 문장은 할 일 목록이 아니라 무엇을 왜 하는지 말하는가.
- **예시 소재에 브랜드·실명을 쓰지 않는다.** 학습자 소개 페이지 제목을 "안녕하세요, 모쏘입니다"로 적었다가 어색해 "나를 소개합니다"로 바꿨다. 화면에 이미 있는 글과 겹치지 않는 문구로 써야 바뀐 것이 보인다.
- **예시 소재는 수업 안에서 이어 쓴다.** 1-1은 "창가 책방"을 화면 2·3에서 같이 쓴다. 가상의 가게·장소라 실제 정보처럼 보이지 않게 한다.

## 4. 연출과 모션

- **새 자세가 필요하면 그림을 만든다.** 확정 캐릭터 시트를 첨부해 chatgpt.com에서 같은 캐릭터의 새 자세를 투명 배경으로 생성하고, 한 장에 여러 자세를 받아 잘라 쓴다(1-2: `public/images/workbook/lesson-1-2/` 부탁·난감·엄지). 같은 표정 연출(?→전구 등)을 수업마다 반복하지 않는다.
- **카피바라는 학습자 쪽 인물이다.** 요청하는 쪽, 카드를 보며 갸웃하거나 전구가 켜지는 쪽. 조수(AI) 역할을 맡기지 않는다. 확정 캐릭터 시트의 그림(`public/images/workbook/lesson-1-1/capy-back.png`·`capy-turn.png`)을 쓴다.
- **채팅 장면의 프로필:** 카피바라는 원형 안에 얼굴만(머리 전체가 원 가운데 오도록 이미지 위치를 맞춘다), AI는 로봇 얼굴 그림. 말풍선 안에 "카피바라", "AI" 같은 발신인 글자를 넣지 않는다(화면 읽기용 이름은 프로필에).
- **진짜처럼 보이게 움직인다.** 대화는 요청 → 점 세 개로 약 2초 "쓰는 중" → 답 → 결과 창 새로고침(주소 줄 진행선) → 바뀐 곳만 형광펜처럼 표시했다가 빠짐.
- **모션은 들어올 때 한 번.** 반복 재생하지 않는다. 다시 보고 싶으면 "다시 보기"를 둔다. 첫 요청처럼 화면 진입 시 한 번 재생하는 것은 장면 한정 예외로 기획 문서에 적는다.
- **모션 줄이기에서는 완성 화면 또는 같은 순서의 정지 전환.** `prefers-reduced-motion`에서 애니메이션을 끈다.
- **따라 하는 단계의 그림은 "어디를 누르는지"를 보여준다.** 단계 이름을 되풀이하는 그림(캐릭터 자세, 일반 아이콘)은 귀여워도 도움이 되지 않는다. 화면 약도에 누를 곳 하나만 강조색으로 표시한다(1-4 설치 화면). 확인한 화면만 실제 배치대로 그리고, 확인하지 못한 화면은 어느 버전에서도 틀리지 않게 일반적으로 그린 뒤 기획 문서에 적어 둔다.
- **도식은 개념의 차이가 그림에서 보여야 한다.** 비교하는 두 그림은 같은 것(같은 인물·같은 자리)을 두고 달라지는 것만 바꾼다. 1-4의 로컬·클라우드는 처음에 집과 건물로 그렸다가 "건물만 바뀌었다"는 지적을 받고, 같은 책상에서 폴더가 내 컴퓨터에 있을 때와 인터넷 선 너머 컴퓨터에 있을 때로 다시 그렸다.
- **새 그림 전에 있는 컷을 먼저 본다.** 1-5 화면 4의 카피바라 리액션(땀 → 엄지)은 1-2의 `capy-puzzled`·`capy-thumb`으로 만들었다. `public/images/workbook/lesson-*/`를 먼저 확인한다.
- **손글씨는 짧은 말에만.** 머리말 · 짐작 · 빨간 펜 · 포스트잇처럼 짧은 말에 쓰고, 메모 본문처럼 여러 줄을 읽어야 하는 글은 인쇄체로 쓴다. 같은 메모가 화면마다 글씨체가 바뀌지 않게 한다.
- **누르는 곳은 바뀌는 대상 가까이.** 메모를 "조수에게 ⇄ AI에게"로 바꾸는 단추는 메모 머리에 둔다(1-5 화면 2). 모바일에서 누른 결과가 화면 밖에 생기면 누른 자리 근처에 "↓ 아래에 더해졌어요" 같은 한 줄을 띄우거나 그쪽으로 따라 내려간다.
- **한 화면에 주황(강조색)은 한 곳.** 콜라주의 주황 종이 조각, 정리 화면의 번호처럼 한 곳에만 쓰고 나머지 강조는 검정·종이색으로.
- **색은 토큰으로.** 먹 · 종이 · 메모지 색은 `WorkbookClass.module.scss`의 `--workbook-ink` · `--workbook-paper` · `--workbook-memo` · `--workbook-memo-line`을 `$ink: var(--workbook-ink, #2b2925);`처럼 받아 쓴다. 화면에 한 번 쓰는 색(봉투, 포스트잇 등)만 파일 안에 둔다.
- **콜라주 기법:** 가위로 자른 테두리는 `src/components/WorkbookClass/workbook-collage.ts`의 `scissorCut(seed, depth, steps)`를 쓴다. 두꺼운 흰 스티커 테두리는 SVG 필터(`feMorphology`+`feDisplacementMap`+`feFlood`)로, 망점·종이 결은 배경 이미지로 만든다. 손글씨는 `Nanum_Pen_Script`.

## 5. 화면 구현

- **수업 화면 연결:** 1-1처럼 여러 장을 펼치는 첫 단계는 `WorkbookLessons.tsx`의 `part`(화면 번호)로 나눈다. 화면을 늘리거나 줄이면 `lastPart`, `totalScreens`, 이어지는 단계의 `currentScreen` 계산을 함께 고쳐 하단 점 개수를 맞춘다.
- **수업 번호를 숫자로 적지 않는다.** 수업을 가리킬 때는 `src/lib/workbook-course.ts`의 `workbookLessonId`(`usage`·`setup`·`firstRequest`·`firstFile`·`project`…)를 쓴다. 수업을 더하거나 순서를 바꿔도 그 파일만 고치면 된다.
- **화면 하나 = 컴포넌트 하나.** `WorkbookXxx.tsx` + `WorkbookXxx.module.scss`. 상호작용이 있을 때만 `"use client"`를 쓰고 이유를 파일 머리에 적는다. 화면 안 상태 중 다른 화면에 다녀와도 남아야 하는 것(대화 진행 등)은 `useWorkbookLessonState`에 둔다.
- **짧은 화면은 세로 가운데.** `data-lesson-wide` 화면 하나만 있는 본문은 넓은 화면에서 내용이 짧으면 세로 가운데에 놓인다(`WorkbookLesson.module.scss`). 따로 여백을 넣어 맞추지 않는다.
- **폭 고르기:**
  - 화면 전체를 무대로 쓰는 연출 장면: 최상위 요소에 `data-wide-scene` (16:9 장면이 본문 높이·너비 안에 맞춰 들어간다).
  - 비교·대화·정리처럼 넓게 펼칠 화면: `data-lesson-wide` (본문 가운데 최대 1120px를 쓴다).
  - 줄글 위주 화면: 기본 읽기 폭.
- **수업 공통 글자 규칙을 덮을 때는 선택자를 한 단계 깊게.** 목록은 공통 `ul` 규칙의 들여쓰기가 남지 않게 `.kinds ul.cards`처럼 요소 이름까지 붙인다. `.lesson .lessonBody p` 같은 공통 규칙이 이기므로 `.pair .card .sample`처럼 컴포넌트 안쪽 클래스를 두 단계 이상 붙인다. 공통 버튼 호버색이 주 동작색(주황)이라, 보조 버튼은 `--workbook-button-hover: var(--workbook-button-neutral-hover)`를 지정한다.
- **본문 안 버튼의 크기·모서리를 바꿀 때:** 공통 규칙 `.lesson .lessonBody button:not(.choice):not(…):not(…)`이 최소 높이·안쪽 여백·모서리를 정하고 우선순위가 높다. 원형 핀처럼 다른 모양이 필요하면 `.tour .sketch button.pin[data-pin][aria-pressed][type]`처럼 선택자를 그보다 길게 쓴다. 비활성 버튼은 공통으로 흐려지므로(`opacity: 0.45`), 흐려지면 안 되는 상태(이미 찍은 도장)는 따로 덮는다.
- **다음 수업 표도 정본에서 읽는다.** 정리 화면의 "다음 수업 1-6 첫 코드 만들기"처럼 번호·이름을 직접 적지 않고 `workbookCourse[0].lessons[workbookLessonId.xxx]`의 `number`·`title`을 쓴다.
- **기록은 학습자가 직접 쓴 것만.** 예시 메모·예시 답을 학습자의 기록(`practice`)으로 저장하거나 복사하지 않는다. 예시 메모는 예시 답의 문장 번호를 말하므로, 직접 실습한 사람이 붙여 넣으면 자기 답과 맞지 않는다(1-5 화면 5). 근거가 비면 대신할 문장을 지어 넣지 않고 기록하지 않는다(1-6 마침). 이름도 사실대로: 보냈는지 워크북이 모르면 "다시 부탁한 말"이 아니라 "적어 둔 수정 요청".
- **도장은 되돌릴 수 있어야 한다.** 도장을 다 지우면 "컴퓨터에서 실습" 표시도 풀고, 이미 "확인됨"으로 남은 기록은 "시도함"으로 낮춘다. 도장 상태는 그려질 때의 값이 아니라 최신 기록에서 계산한다(`useFirstFilePractice`).
- **직접 실습한 사람에게도 할 일을 준다.** 예시로 연습하는 화면에서, 실제로 보낸 사람은 자기 결과를 어디서 확인하는지 같이 보여 준다(1-5 화면 4의 "내 답도 이 네 가지로 맞춰 봐요").
- **복사 버튼은 실패도 준비한다.** 자동 복사가 막히면 붙여 넣을 글만 담은 상자를 골라진 채로 보여 준다(`WorkbookCopyFallback`). 글을 고치면 상자를 닫아 입력 중에 커서를 뺏지 않게 한다.
- **지도의 기록 칸에는 쓴 것만 보인다.** 방식을 고르지 않았으면 "예시 복습"이라고 적지 않는다.
- **보조 동작은 작게.** "처음부터 다시 보기", "다시 보기"처럼 다시 재생하는 버튼은 밑줄 글자 버튼으로 두고 주 동작처럼 보이게 하지 않는다.
- **제목(h2)은 화면마다 하나, `id="lesson-screen-title"`.** 콜라주 장면은 제목을 장면 안 종이 띠로 붙이되 실제 h2로 둔다.
- **화면 읽기 도구:** 바뀌는 곳을 읽어 주는 `aria-live`는 화면에 한 곳만 둔다(두 곳이 같이 바뀌면 겹쳐 읽힌다). `aria-controls`는 실제로 그려진 요소만 가리킨다(접힌 내용이면 펼쳤을 때만).
- **이미지:** 장식 그림은 `alt=""`와 `aria-hidden`. 의미가 있는 그림·도식은 실제 글자(목록·제목)로 같은 정보를 준다.

- **`pnpm check` 통과.**
- **e2e:** 진행 표시(`현재 학습 단계`)의 글자는 "2 / 11"처럼 숫자만이다("화면" 없음). 수업 흐름을 바꾸면 해당 e2e(1-1은 `e2e/workbook-ai-slide.spec.ts`)를 같이 고친다. "다음으로" 버튼의 이름은 화살표가 붙어 `/^다음으로/`로 찾는다. 같은 폴더에서 `next dev`가 이미 떠 있으면 `PW_BASE_URL=http://localhost:3000 pnpm exec playwright test ...`로 그 서버를 쓴다(포트는 떠 있는 서버에 맞춘다).
- **기획 문서 갱신.** 화면 흐름표의 해당 칸을 "(구현됨) 실제 모습"으로 바꾸고, 새로 정한 규칙이 있으면 이 문서에도 추가한다.
- **커밋은 기획자가 끝났다고 할 때.**

## 7. 수업을 다 만든 뒤 — 전수 점검

여섯 화면을 다 만들면 한 화면씩 볼 때는 안 보이던 문제가 나온다. 1-5에서 실제로 19가지 + 문구 14가지가 나왔다(2026-11-17~18). 아래 순서로 점검하고, 묶음마다 기획자에게 보고한 뒤 고친다.

1. **사실과 다르게 남는 것:** 예시가 학습자의 기록·복사로 들어가지 않는지, 근거 없는 기록이 남지 않는지, 지도·정리 화면의 이름이 사실대로인지, 수업 번호를 직접 적지 않았는지, 문서가 코드와 맞는지(위 5절).
2. **흐름과 내용:** 화면 사이가 이어지는지(앞 화면이 "다음 화면에서 함께 확인해요"라고 했으면 실제로 그런지), 직접 실습한 사람에게 할 일이 있는지, 앞 수업의 원칙을 어기는 예시가 없는지, 단정한 문장이 없는지.
3. **표현과 디자인:** 같은 글의 글씨체, 누르는 곳의 위치, 모바일에서 결과가 보이는지, 색이 뜻별로 구분되는지, 정리 화면의 짜임.
4. **접근성과 동작:** 복사 실패, 화면 읽기 겹침, `aria-*`가 가리키는 대상.
5. **문구만 따로 한 번:** 화면의 글자를 모두 뽑아(`grep`으로 한글 문구만) 처음 보는 사람 입장에서 읽는다. 위 3절의 원고 규칙(비유어 · 풀이 · 두 뜻 · 지시어 대상 · 이유 · 끝까지 · 같은 글 · 단정 · 이름 통일 · 목록 형태 · OS 구분 · 실명)을 하나씩 대 본다.
6. **코드 리뷰:** 마지막에 `/code-review`(Codex는 자체 리뷰). 기록 · 상태 계산(최신 값에서 계산하는지, 되돌릴 수 있는지)을 특히 본다.

점검에서 새로 나온 종류의 문제는 이 문서의 해당 절에 규칙으로 더한다.
