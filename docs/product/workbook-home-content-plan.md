# 워크북 홈 콘텐츠 구성 제안

2026-10-17. 사용자와 논의한 방향을 확인하기 위한 `/demo/workbook-home-next` 시안. 기존 `/workbook` 홈을 대체하거나 정식 콘텐츠 발행을 확정한 문서가 아니다.

## 방문 상황과 역할

- 처음 온 사람: 만들고 싶은 일이 생기거나, AI를 어디서 시작할지 몰라 방문한다. 가능한 제작 범위와 시작점을 보여준다.
- 써보다 막힌 사람: 자기 문제에 맞는 구체적인 도움을 찾는다. 기존 글을 상황별로 묶는다.
- 다시 온 사람: 하던 일을 이어가고 남긴 기록을 확인한다. 이어하기와 작업 공간을 연결한다.

대표님이 별도 작업 중인 흥미로운 사이트·독특한 콘텐츠 소개 영역과 역할이 겹치지 않도록, 워크북은 직접 만들고 배우는 과정에 집중한다. 짧은 실험·퀴즈를 홈의 필수 독립 섹션으로 넣지 않는다.

## 추천 순서와 자료 상태

| 순서 | 영역                  | 기존 활용                                    | 새로 필요한 자료                                  |
| ---- | --------------------- | -------------------------------------------- | ------------------------------------------------- |
| 1    | 통합 히어로           | 기존 카피바라 이미지와 홍보 진입 구조        | 대표 콘텐츠를 정한 뒤 실제 제목·이미지·링크       |
| 2    | 이어하기·내 작업 공간 | 방문 중 수업 진행과 작성 기록, 카피바라 세계 | 수집품 획득 조건·전시 슬롯·향후 회원 저장 정책    |
| 3    | 실제 제작 이야기      | 클래스의 기획·제작·수정 흐름                 | 실제 요청, 초기·수정 화면, 수정 이유, 제작자 확인 |
| 4    | 클래스                | 기존 웹 클래스 및 커밍순 카드·전체 목록      | 새 커밍순 클래스를 이용 가능하다고 표시하지 않기  |
| 5    | 지금 필요한 글        | 기존 여섯 테스트 글                          | 상황별 짧은 소개만 추가                           |
| 6    | 변화 해설             | 기존 아티클 렌더러·작성 기준                 | 직접 확인한 새 변화가 생길 때 작성                |

히어로가 제작기를 소개하면 아래 제작기 영역은 같은 대형 홍보를 반복하지 않고 과정 일부를 보여준다. 클래스 캐러셀 자체는 기존 구현을 활용하며 데모의 간단한 클래스 진입 링크는 카드 구조 확정을 뜻하지 않는다. 이어하기가 없는 방문자에게 빈 진도 영역을 크게 노출하지 않는다.

## 기존 여섯 글을 세 상황으로 연결

1. **생각한 것과 다르게 나왔나요?** — `describe-the-result`, `show-the-screen`. 원하는 결과 설명과 수정 지점 전달.
2. **만들다가 멈췄나요?** — `report-the-error`, `leave-a-handoff`. 오류 설명과 작업 재개.
3. **이대로 써도 괜찮을까요?** — `check-the-source`, `test-the-awkward-cases`. 근거와 예상 밖의 사례 확인.

기존 글의 slug와 내용은 유지한다. 이 여섯 편은 정식 발행 검증을 마친 운영 아티클이 아닌 프론트 테스트 글이라는 표시를 유지한다.

## 제작기 시안의 정직한 표현

시안 제목은 ‘첫 화면이 나온 다음, 무엇을 고쳤을까?’이며 실제 제작 완료를 주장하는 글이 아니다. 다음 세 항목의 구조를 보여주고 ‘제작기 구성 시안’, ‘취재·실제 제작 자료 준비 중’을 표시한다.

- 목적·독자·최초 제작 범위
- 초기 화면과 개선 화면, 수정 판단
- 막힌 부분과 다시 한다면 바꿀 것

자료가 확보되면 과정·결과의 사실 확인을 거쳐 실제 제작기로 작성한다. 검증 전 수치, 소요 시간, 완성 결과나 체험담을 만들어 채우지 않는다. 시안에서는 가짜 ‘읽기’ 버튼도 제공하지 않는다.

## 새 소식은 빈 슬롯 대신 편집 판단

아직 확인된 해설 콘텐츠가 없으므로 ‘새 소식 준비 중’ 섹션을 홈에 반복해서 만들지 않는다. 새 기능 자체보다 독자의 작업 변화가 분명할 때 ‘무엇이 바뀜 → 누구에게 필요 → 직접 확인한 범위 → 다음 행동’을 담아 아티클로 추가한다. 모든 글을 수강 유도로 끝내지 않는다.

## 구현 경계

`WorkbookHomeContentPreview`는 `WorkbookReadingSummary[]`를 받아 기존 글 링크를 조합하는 독립 서버 컴포넌트다. 실제 홈, 수업, 글, 저장소나 인증을 변경하지 않는다. 작업 공간의 수집·꾸미기는 별도 데모 경계에서 논의하며, 데모 완료를 운영 보상 정책 확정으로 해석하지 않는다.

## 후속 결정 · 기존 홈 유지 (2026-10-17)

사용자는 현재 워크북 홈 콘텐츠 구성을 유지하고 필요한 내용만 추가하기로 했다. 이 문서의 섹션 재배열·제작기 대형 시안·상황별 글 재배치는 홈 교체안으로 적용하지 않는다. 기존 히어로·클래스 캐러셀·짧은 실험·여섯 글·기록·캘린더를 보존한다. 작업 공간은 작은 진입 카드로 추가하고 큰 화면에서 별도 탐색한다. 실제 제작기와 변화 해설은 자료가 준비된 뒤 기존 콘텐츠 체계에 추가할 후보로 남긴다.
