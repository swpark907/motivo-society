# 워크북 홈 재구성 비교안

## 2026-10-05 선택 및 적용

사용자가 B안을 승인해 홈에 적용했다. 실사 히어로·동일 크기 클래스 카드 3개·짧은 실험 2개·읽을거리·내 기록 구성이다. 클래스 2개와 칼럼 2개는 명시적인 기획 예시로 비클릭 카드다. 실제 소개 아티클과 기존 데모만 연결한다. 상단 이어하기는 기존 모바일 실험의 브라우저 진도가 있을 때 표시하며 구매한 클래스나 계정 진도로 오인하지 않도록 체험 기록이라고 표시한다. 구매 기반 이어하기는 인증·권한 연동 후 별도 구현한다. 새 실사 표지를 홈과 클래스 소개에 적용했으며 픽셀 지도는 체험 안에 유지했다. 디자인 시각 검토는 사용자 승인 대기다.

2026-10-05. 사용자는 기존 실사·시네마틱·고급스러운 톤의 클래스 썸네일 제작과, 여러 클래스·콘텐츠가 존재하는 상황에서 홈 구성 방안 비교를 요청했다. 아래 목록의 새 클래스·칼럼 제목은 구성 검토용 가상 예시이며 출시·판매 확정이 아니다. 홈 레이아웃 교체는 제안 단계다.

## 공통 방향

홈은 여러 배움의 입구이고 게임 세계는 개별 클래스 안에 있다. 실사 작업실 이미지 안의 모니터에 픽셀 마을을 담아 자연스러운 연결을 만든다. 클래스 소개에서는 실제 픽셀 플레이 화면도 별도 미리보기로 공개한다. 학습 콘텐츠를 실사로 다시 만들 필요는 없다.

클래스는 구매 단위, 칼럼은 읽을거리, 짧은 실험은 직접 해보는 콘텐츠다. 카드에 콘텐츠 종류와 접근 조건을 표시한다. 무료·유료·구매함 표시는 실제 정책·권한에만 따른다. 방문 기록을 구매 권한으로 간주하지 않는다. 예시를 실제 서비스에 공개할 경우 준비 중 또는 예시임을 표시한다.

## 추천안 B의 구체 구성

1. 첫 방문: 기존 실사 히어로를 낮은 높이로 유지하고 ‘만들고 싶은 것에서 시작해요’와 클래스 탐색 CTA를 둔다. 구매 후 진행이 있으면 같은 상단 자리에 작고 명확한 이어하기 카드: 클래스명·다음 활동·마지막 기록. 대형 히어로와 이어하기를 둘 다 크게 쌓지 않는다.
2. 클래스 둘러보기: 데스크톱 3열 정도의 같은 크기 16:9 썸네일 카드, 제목·만들 결과 한 줄·입문 조건·판매 상태·상세 진입. 확정된 가격과 구성만 표시한다. 많아지면 전체 보기와 분야 필터를 제공한다. 모바일은 1열 목록과 전체 보기로 찾기 쉽게 한다.
3. 짧게 해보기: 긴 클래스를 시작할 여유가 없을 때 들어가는 작은 실험 카드. 기존 책상 배치 실험 같은 실제 체험을 배치하고 정식 클래스 진도와 구분한다.
4. 읽고 가져가기: 활동과 연결되는 칼럼 2~3개. Library·Article의 기존 정본 링크를 재사용하고 워크북용으로 같은 글을 복제하지 않는다. 미발행 가상 제목은 기획 시안에서만 사용한다.
5. 내 메모·보관함: 학습 기록이 있을 때 보조 동선으로 제공한다. 초기 방문자에게 빈 캘린더·체크리스트를 크게 차지하게 하지 않는다. 모바일에서는 주 콘텐츠 뒤에 배치한다.

좌측 레일 후보: 둘러보기 / 내 클래스 / 내 기록. 구현된 목적지가 생겼을 때만 노출한다. 클래스 개별 이름을 전역 메뉴의 주 항목으로 고정하면 클래스가 늘 때 확장하기 어렵다.

## 검토용 예시 콘텐츠

- 클래스: 바이브코딩 웹개발(현재 제작 중), AI와 만드는 작은 브랜드(확장 예시), AI와 쓰는 나의 첫 글(확장 예시).
- 실험: 책상 정리로 배치 감각 익히기(기존 데모), 같은 화면을 다른 방문자에게 보여주기(기획 중).
- 칼럼 주제 예시: ‘만들기 전에 정해두면 좋은 세 가지’, ‘AI의 완료 메시지 뒤에 확인할 것’. 실제 발행된 글로 오인하지 않게 한다.

가상의 평점·수강생 수·개인화 추천·진도는 넣지 않는다. 검색은 충분한 콘텐츠가 쌓여 필요할 때 추가하고 지금은 명확한 섹션과 전체 보기부터 검증한다.
