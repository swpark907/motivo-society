# 워크북 소재 정리와 단계별 설명 — 2026-10-25

## 승인 범위

사용자 요청에 따라 소재 불일치와 반복 설명을 먼저 정리하고 1-1·1-4·2-2에 단계적으로 펼치고 직접 반응하는 설명을 적용한다. 기존 학습·실제 결과 판정, 퀴즈 정답의 의미와 위치, 실습 방식 선택·기록 조건, 외부 파일 작업과 예시의 구분을 유지한다. 3~5단원의 실험 구조 개편·회원 저장·배포는 하지 않는다.

## 반영

- 장소 메모·소개문·첫 파일·기획 기본 예시를 `workbook-learning-example.ts`에 연결했다. 기본 기획은 ‘혼자 책 읽기 좋은 세 곳’이며 가상 장소를 담은 연습용 페이지다. 기존 사용자 기록과 목적별 선택 자료는 덮어쓰지 않는다.
- 1-2 글·이미지·웹 화면 사례를 장소 소개로 맞췄다. 창가와 책 SVG는 설명용 벡터 자산이며 실제 장소나 AI 생성 성과로 표현하지 않는다.
- 1-5의 제목 수정과 예시 목록도 장소 소개로 연결했다. ‘준비 중’ 대신 가상 장소 목록으로 첫 결과를 읽을 수 있게 했다. 실제 실습의 체크·관찰·결과 판정은 그대로다.
- 2-3의 동적 독자 문장은 ‘읽을 사람: …’ 형식으로 바꿔 조사 충돌을 없앴다. 5-3은 소재에 관계없이 쓸 수 있는 ‘추가 내용’으로 표현을 정리했다.
- 모드 선택·예시 결과 근처의 경계 안내를 남기고, 초반 수업의 중복 해설·정리 문구를 줄였다. 실제 AI 실행·파일 제작으로 오인할 안내는 추가하지 않았다.

## 상호작용

| 수업 | 행동과 화면 반응                                                                                                                        | 기존 기록과의 경계                                                                                                                                           |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1-1  | 메모 세 개 → 소개문 펼침 → 메모와 문장 연결. 자리·독서·혼잡을 고르면 해당 표현과 설명이 바뀐다. 전체 설명을 바로 볼 수 있다.            | 정답·완료 조건과 무관한 방문 UI 상태. 다음 화면 왕복 시 펼침과 선택을 유지한다.                                                                              |
| 1-4  | 읽을 사람·장소 정보·길이 조건을 추가하면 이전 요청 문장은 남고 준비된 답변 예시가 바뀐다. 조건 제거·처음부터 비교·전체 보기를 제공한다. | 조건별 사전 제작 결과임을 표시. 뒤의 직접 쓴 첫 요청과 수정 요청을 바꾸거나 자동 전송하지 않는다.                                                            |
| 2-2  | 기획 항목을 고르거나 다음 연결로 이동하면 현재 요청의 대응 문장을 발췌해 강조한다. 전체 연결도 펼칠 수 있다.                            | 원문 textarea는 계속 직접 편집 가능. 원문에 없는 값은 찾지 못했다는 안내를 보여주며 복원하지 않는다. 선택으로 기획 기준·학습 완료·실제 결과를 바꾸지 않는다. |

설명에 필요한 조작은 기존 수업 진행의 필수 조건으로 추가하지 않는다. 키보드로 조작 가능한 일반 버튼을 사용하고 선택은 선·밑줄과 문장 설명으로 구분한다. 자동재생·타이핑 지연·드래그·외부 AI 호출은 없다. 모바일에서는 두 열을 한 열로 쌓고 기존 하단 진행 영역을 유지한다.

## 검증 기록

- 순수 발췌 함수: 다중 행, 직접 편집 후 불일치, 빈 값, HTML 형태의 일반 문자열, 제목·독자에 중복 단어가 있는 경우를 포함한 4개 테스트 통과.
- 새 UI: 단계별 반응·조건 제거·원문 보존·기존 진행 조건과 320px 가로 넘침을 PC·모바일에서 검사한다.
- 기존 흐름: 예시/컴퓨터 실습, 기록 편집, 기본 17수업과 최종 정리를 회귀검수한다.
- 변경 전후 8개 수업 컴포넌트의 완료/진행 판정식, 버튼 비활성 조건, 기존 입력 바인딩을 구문 트리로 비교해 동일함을 확인했다.
- 새 UI와 갱신된 예시·입력 보존·너비 비교의 PC/모바일 검사 28건 통과. 마지막 중복 단어 대응 보정 뒤 새 UI와 기본 17수업 전체 진행 8건을 다시 실행해 통과했다.
- 저장소 전체 E2E 336건 중 335건 통과. 관리자 사진 편집 버튼 대기에서 시간 초과한 모바일 자동 저장 1건은 단독 재실행에서 4.3초에 통과했다. 이때 관리자 코드는 변경하지 않았다.
- 최종 `pnpm check` 통과: 타입 생성/TypeScript·ESLint·전체 포맷 검사 및 Vitest 33개 파일 115개 테스트 통과. 임시 Playwright 설정 파일은 제거했다.
- 실제 브라우저에서 PC 1280×720, 모바일 390×844·320×740로 세 장면을 확인했다. 1-4 펼침 후 중복 줄바꿈과 불필요한 카드 높이를 줄였고, 2-2 모바일은 같은 값을 두 번 표시하지 않게 보정했다. 기존 하단 진행 영역과 키보드 조작을 확인했다.
- 자체 검토에서 직접 편집한 요청의 항목이 사라지면 추측해 복원하지 않는 것을 확인했다. 제목·독자에 같은 단어가 있어도 표준 요청의 해당 항목에서 찾도록 보정했다. 다른 표현의 요청은 연결 예시에서 찾지 못할 수 있지만 원문과 기존 진행 조건은 유지한다.
