# 플랫폼 백로그 — 회원 여정(L) · 호스트 여정(H)

절차는 [LOOP.md](LOOP.md). 위에서부터 하나씩. 표기: `[ ]` 할 일 · `[~]` 진행 중 · `[x]` 완료 · `결정 대기` 사람 결정 필요.

목표: 처음 온 사람이 **가입 → 발견 → 활동 상세 → 신청(무료·유료) → 내 일정 → 챌린지 인증 → 클럽 가입**까지 막힘없이 할 수 있는, 실제 서비스 같은 화면. 데이터는 로컬 Supabase, 로그인은 이메일 매직링크(로컬 Mailpit).

호스트 여정(만들기·명단·출석·정산 화면의 정식판)은 다음 loop. 그전까지 운영·호스트 동작은 시험장(`/demo/platform`)으로 확인한다.

## 두 번째 loop: 호스트 여정 (2026-11-09 승우 승인)

[호스트 편의 기능 제안](../platform-host-convenience.md)의 순서 그대로: 지난 활동·가져와 만들기 → 이미지 보관함 → 장부·정산 → 연락·명단·출석 → 클럽 회비. 장부는 기본으로 호스트만 보고, 공개는 호스트가 고른다(승우 승인).

들어오는 사람: 호스트 자격이 있거나, 클럽에서 활동을 만들 권한이 있거나, 활동 진행자인 사람. "나"에서 `/host`로 들어간다(IA). 시험장의 대시보드 시안(`/demo/platform/host`)과 만들기(`/demo/platform/new`)는 그대로 둔다.

## 결정 대기

- 클럽 회비 수납 방식(대표 · 법률·세무). 후기 사진을 표지로 쓸 때의 동의 방식(승우).
- 이미 시작한 시즌에 중간 합류한 사람의 환불 기준(대표). 지금은 첫 회차 시작일 기준이라 합류 직후 환불이 0원이다. 남은 회차 기준·합류 후 며칠 전액 같은 규칙이 필요하다. 중간 합류 가격(전액인지 남은 회차만큼인지)도 같이.

## 후속 (loop 중 생긴 일)

- 닉네임 규칙(2~12자, 한글·영문·숫자·밑줄, 대소문자 무시 중복 불가)과 관심사 목록 10개는 제안 기본값·시안 값이다. 예약어(운영·모쏘 등) 막기와 관심사 확정은 승우 결정.
- 프로필에서 닉네임·관심사 바꾸기는 아직 없다("나" 화면은 "준비 중"으로 표시).
- 카드에 참가자 얼굴(시안의 아바타 줄)을 보여 줄지: 비로그인에게 참가자 닉네임을 공개하는 일이라 승우 결정. 지금은 남은 자리 숫자만.
- 발견 검색창(시안에 있음)은 백로그에 없어 넣지 않았다. 필요하면 항목으로.
- 신청 질문(활동별 최대 3개, 명세 5절)은 아직 받지 않는다. 활동 만들기에 질문이 생기면 신청 확인 단계에 붙인다.
- 대기 순번(몇 번째인지)은 보여 주지 않고 대기 인원만 보여 준다. 순번은 DB 함수가 필요하다.
- 배포 전에 `metadataBase`(사이트 주소)를 정해야 OG 이미지 주소가 실제 도메인으로 나간다(지금은 개발 주소).
- 활동 상세의 "클럽 보기"와 회원 홈의 클럽 카드는 L11부터 클럽 상세로 간다.
- 오렌지 버튼은 브랜드 행동 색이라 확정 화면의 "활동 화면으로"만 오렌지다. 확정 알림(메일·푸시)은 알림 기능 때.
- 회원 홈의 "오늘 인증이 아직이에요"는 L09부터 상세의 참여 영역(`#today`)으로 바로 간다.
- 회원 홈 "내 사람들"의 좋아요·댓글은 범위 밖.
- 비로그인 홈의 옛 Yard(콘텐츠 파일) 줄은 "이번 주 모쏘에서 열리는 것"(실제 활동)으로 바꿨다. `/yard/[slug]` 옛 글 주소는 그대로 열린다.
- 워크북 e2e 136건 실패는 이 loop 이전부터 있던 것(기준 커밋 `ec17b56`에서도 같은 실패 확인). 최근 워크북 개편(1-1 여섯 화면, 강의 인트로, 공통 이동 바) 뒤 e2e가 갱신되지 않았다. 워크북 담당 작업에서 정리한다.
- 내 일정의 "캘린더에 추가"(시안의 버튼, .ics 내보내기)는 넣지 않았다. 필요하면 항목으로.
- 내 일정은 확정 전(대기·승인 대기·입금 대기) 시즌을 회차로 펼치지 않고 가장 가까운 회차 날짜 하나로 보여 준다. 회차 정보는 확정 참가자에게만 열리기 때문이다.
- 지난 일정의 결과 표시는 출석·불참(진행자가 기록한 경우)과 챌린지 완주·인증 수뿐이다. 후기·사진은 후기 기능 때.
- 사진 인증은 DB에 사진 칸이 없어 받지 않는다. 사진을 허용한 챌린지에는 "사진 인증은 준비 중"이라고 쓴다. 이미지 저장소(호스트 편의의 이미지 보관함과 같은 결정)와 함께 붙인다.
- 인증 반려는 진행자 도구(호스트 화면)가 생길 때 붙인다. 지금은 반려된 인증이 참가자에게 사유와 함께 보이는 것까지.
- 함께한 기록의 반응·댓글은 범위 밖(명세 7절의 응원).
- 로그인·가입하는 e2e도 `platform-flows.spec.ts`로 옮겼다(다른 파일의 초기화가 세션·프로필을 지워 생기던 실패). 옮긴 것은 데스크톱에서만 돈다.
- 환불 돈을 어느 계좌로 보낼지 회원에게 받지 않는다. 지금 화면은 "송금은 운영진이 처리해요"까지만 말한다. 환불 계좌를 받을지(받으면 언제·어떻게 보관할지)는 결정 필요(대표).
- 시험장 페르소나 중 주문이 있는 사람은 없다. 주문 화면을 보려면 처음온사람으로 유료 모임(프롬프트 클리닉·AI 도구 실습 워크숍)에 신청하고 시험장 운영 화면(`/demo/platform/ops`)에서 모쏘운영으로 입금 확인한다.
- 환불 금액이 0원이면(시작 직전 등) 요청 버튼을 두지 않고 "규정상 돌려받을 수 있는 금액이 없어요"라고만 쓴다. 이 경우의 문의 창구는 없다.
- 초대 링크 화면이 어느 클럽인지 보여 주려고 DB 함수 `club_invite_preview`를 더했다(새 마이그레이션 `20261109000000`). 코드를 가진 사람에게 클럽 주소·이름·소개·멤버 수와 쓸 수 있는지만 준다.
- 가입 신청 승인·거절, 초대 링크 목록·취소, 멤버 전체 명단·레이어 관리는 운영 도구(호스트 화면) 몫이다. 지금은 시험장(`/demo/platform/clubs`)에서 한다.
- 승인 대기 중인 가입 신청을 회원이 스스로 취소하는 기능은 DB 함수가 없어 넣지 않았다.
- 개발 서버 기준 e2e: 오래 떠 있던 `next dev`는 메모리가 불어나 화면 하나에 수십 초가 걸린다(L13에서 확인). 플랫폼 e2e 전체를 돌리기 전에는 개발 서버를 새로 띄운다. 운영 빌드(`next start`)는 시험장 로그인·운영 화면이 개발 전용이라 쓸 수 없다.
- 0원 환불을 운영진이 승인하면 주문은 "결제 완료"로 남고 참가·이용권만 풀린다(DB `refund_decide`). 화면이 0원일 때 요청을 막아 지금은 생기지 않지만, 운영 도구를 만들 때 0원 요청을 받을지와 함께 정리한다.
- 클럽 상세는 열린 활동 전체를 불러온 뒤 그 클럽 것만 거른다. 활동이 많아지면 클럽으로 걸러 묻는 조회로 바꾼다.
- 서버 액션의 slug·주문 번호 검사가 파일마다 복사돼 있다. 한 곳(lib/platform)으로 모은다.
