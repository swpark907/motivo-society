# 월드 1 — 아이디어를 첫 화면으로

## 2026-10-05 진입 부담에 따른 개정 논의

기존 8개 장소 표는 이전 기획안이다. 사용자 피드백에 따라 장소명보다 ‘홈페이지 기획하기’처럼 직접적인 활동명을 전면에 두고 AI 설치·기초·첫 대화를 보강하는 안을 검토한다. 필수 서론 축소·이야기 선택형 전환도 함께 논의 중이다. 최신 논의는 `workbook-idea-log.md`의 ‘서론 축소와 AI 입문 보강’ 절에 기록한다. 새 순서의 최종 확정·맵 배치·코드 반영은 아직 하지 않았다.

## 플랫폼에서의 진입 구조

2026-10-04 사용자 정정: 워크북은 여러 구매 가능한 클래스를 보여주는 공간이며 결제 단위는 개별 클래스다. 현재 기획은 그중 ‘바이브코딩 웹개발 클래스’의 내용이다. 워크북 전체 이용권이나 워크북 홈 자체의 구매 잠금을 전제하지 않는다. 해당 클래스 구매 후 시작 시 도입 이야기를 보고 월드에 진입한다. 재방문에는 이어하기를 제공하는 안이다. 실제 회원·결제 연동과 가격·이용 기간은 별도 결정이다.

2026-10-04. 기본 4월드 + 선택 심화 1월드는 사용자 확정. 아래 1월드의 세부 순서·이야기·활동은 이번 제작안이며 피드백으로 조정한다. 이 문서는 실제 학습 기능 구현 완료를 뜻하지 않는다.

## 전체 여정 속 위치

1. 기획과 첫 제작: 목적·대상·범위와 첫 화면.
2. 화면과 사용 경험: 구조·스타일·반응형과 사용성. 기존 모바일 소개 페이지 실험을 이곳으로 연결한다.
3. 동작과 데이터: 상태·요청·저장·접근 권한. 프로젝트에 불필요한 로그인·DB를 억지로 붙이지 않는다.
4. 공개와 운영: 공유 주소·배포·운영 점검과 개선.
5. 선택 심화, AI와 일하는 방식: 규칙·스킬·MCP·반복 작업 자동화.

월드는 큰 맵, 학습 지점은 월드 안의 개별 활동을 뜻한다. 4+1은 총 학습 활동이 다섯 개라는 뜻이 아니다.

## 이야기와 결과

주인공 설정 확정: 일상에 작은 쉼을 주는 웹 경험(차 따르기·호흡 맞추기·돌 정원)을 AI와 만드는 카피바라. 흩어진 작업을 소개할 홈페이지가 필요해 여행을 시작한다. [첫 구간 스토리보드](workbook-world-1-storyboard.md)에 실제 대사·선택지 제작안을 기록한다.

### 도입 이야기의 전체 여정 — 사용자 방향 확정

2026-10-04. 사용자는 초반 카피바라 이야기 안에서 기획→화면 제작→필요한 백엔드→배포로 이어지는 제작 한 사이클과, 이후 바이브코딩 생활을 풍성하고 효율적으로 만드는 확장 학습을 안내하도록 요청했다. 앞서 제안한 ‘상황→행동→결과’로 활동 이유를 전달하는 방식도 승인했다.

에이전트 연출안: 선착장에서 카피바라가 ‘내 작업을 소개할 홈페이지를 만들고 싶어’라고 말하며 여행 지도를 펼친다. 다섯 지역이 짧은 장면으로 이어진다. 기획 마을에서는 방문자와 목적을 정하고, 화면 마을에서는 생각을 보고 쓸 수 있는 화면으로 만들며, 동작·데이터 도시에서는 필요할 때 저장과 서버의 역할을 익힌다. 공개 항구에서는 다른 사람도 접속할 수 있게 배포하고 실제 이용을 확인한다. 마지막 AI 공방은 반복 작업을 줄이고 더 다양한 작업을 시도하는 선택 확장 지역이다.

초반에 용어 설명을 몰아넣지 않는다. ‘누구를 초대하지? → 무엇을 보여주지? → 입력한 것을 남기려면? → 친구도 열어볼 수 있을까? → 다음에는 더 편하게 만들 수 있을까?’라는 질문과 장면으로 연결한다. 백엔드는 모든 홈페이지의 필수 조건으로 오해하지 않게, 저장·계정 등의 기능이 필요할 때 검토하는 것으로 표현한다. 5월드는 선택 확장이고 배포 후에도 확인·개선하며 앞 단계로 돌아올 수 있다.

도입 마지막에는 지도에서 1월드를 가까이 보여주며 ‘우선, 누구를 위한 곳인지부터 정해볼까?’로 찻집 활동에 연결한다. 설명 영상은 강제 시청하지 않고 짧은 넘김 장면·정적 글로도 같은 내용을 전달한다. 실제 대사와 장면 수는 제작 시 다듬는다.

### 활동의 이유 전달 — 2026-10-04 보완 제안

사용자 요구: ‘갑자기 이걸 왜 하지?’라는 느낌이 없도록 필요성을 부담 없이 전달한다. 직접 안내·이야기 등 형식 제한은 없다. 아래는 에이전트 제안이며 방식 자체는 채택 전이다.

기본 리듬은 ‘앞 장면의 작은 문제 → 이번 행동 → 달라진 결과’다. 매번 실패를 강제하지 않고 대화·비교·짧은 목적 문장 중 필요한 것을 사용한다. 활동 제목 아래 한 줄로 실제 목적을 알리고, 선택형 ‘이게 어디에 쓰여요?’에서 설명과 AI 요청 예시를 제공한다. 필수 팝업·긴 영상으로 진행을 막지 않는다.

| 장소   | 필요성을 느끼는 장면                                          | 행동의 의미                                                                                     |
| ------ | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 찻집   | 같은 작업실을 보면서 방문자마다 다른 정보를 찾는다.           | 대상에 따라 먼저 보여줄 정보가 달라진다.                                                        |
| 장터   | 첫 요청에 로그인·결제까지 붙어 만들 범위가 커진다.            | 먼저 쓸 수 있는 작은 버전의 범위를 고른다. 임의의 일정·비용 수치는 제시하지 않는다.             |
| 정자   | 방문자가 작업 사진을 보고도 연락할 곳을 찾지 못한다.          | 배치가 방문자의 행동에 영향을 준다. 한 배열만 정답으로 강요하지 않는다.                         |
| 서점   | 화면에 ‘소개 문구를 입력하세요’가 남아 있다.                  | 재료를 넣어야 내 작업의 화면이 된다. 임시 내용은 임시라고 표시한다.                             |
| 우체국 | 같은 ‘깔끔하게’에서 나온 서로 다른 사전 제작 예시를 비교한다. | 원하는 부분을 짚어야 요청이 구체화된다. 실시간 AI 생성처럼 표시하지 않는다.                     |
| 공방   | ‘버튼이 안 보인다’와 ‘눌러도 반응이 없다’를 구분해야 한다.    | 구조·스타일·동작을 조작한 뒤 HTML·CSS·JS 이름을 연결한다. 이 웹 기초 활동 추가는 아직 제안이다. |
| 온실   | AI의 완료 메시지 이후 처음 정한 행동을 직접 해본다.           | 완료 메시지와 실제 결과를 구분한다. 일부러 오류를 만들어 실패를 강제하지 않는다.                |

앞 단계의 결과를 다음 단계에서 재사용한다. 예: ‘찻집에서 고른 방문자를 기준으로 기능을 골라볼까요?’와 사용자의 대상 선택 표시. 설명을 읽었는지 체크시키기보다 다음 행동에서 목적을 활용하는지 사용자 테스트로 확인한다. 매 활동마다 이유를 서술하도록 강제하지 않는다.

카피바라가 동네에서 작은 작업을 소개하려는데, 친구에게 보낼 페이지가 없다. 동료들과 마을을 돌며 만들 이유와 보여줄 것을 모으고 첫 화면을 만든다. 공통 예시는 작은 작업실 소개 페이지다. 자기 프로젝트가 있다면 같은 질문을 자기 작업에 적용한다. 카피바라는 정답을 알려주는 선생이 아니라 함께 선택하고 고치는 동료다.

마지막에 남는 것은 기획 한 장, 첫 제작 요청, 첫 화면, 확인한 문제 하나와 수정 요청이다. 배포는 월드 4에서 다루므로 공개 URL을 여기서 요구하지 않는다.

곁길 B는 4~5 사이에서 제안한다. 같은 소개 화면에 ‘협업을 의뢰할 사람’과 ‘행사에 방문할 사람’을 번갈아 대입하고 첫 화면에서 먼저 보여줄 정보를 골라본다. 방문자가 달라지면 정보의 우선순위도 달라진다는 점을 경험하며, 본 프로젝트의 선택은 자동으로 바꾸지 않는다. 풀지 않고 쉬었다 돌아가도 된다. 기존 연못 쉼터 아이디어를 이 벤치의 휴식·선택 응용으로 구체화한 것이다.

이미지의 길은 학습 연결 그래프와 완전히 같지 않다. 특히 공방→온실은 직접 연결된 길이 없어 기존 길을 되짚어 오른쪽 길로 올라가야 한다. 코드 적용 전 배경에 짧은 연결길을 보완하거나 복귀 구간 이동을 줄여야 한다. 지금 원화를 완전히 연결된 최종 이동 맵으로 간주하지 않는다. 여러 길이 보이더라도 UI는 다음 주 지점과 선택 지점의 목적을 명확히 안내한다.

### 학습 흐름과 완료의 의미

1~3은 ‘무엇을 만들지’, 4~6은 ‘어떻게 설명할지’, 7~8은 ‘만들고 확인하기’의 세 묶음으로 나눈다. 각 묶음 끝에서 쉬었다 이어갈 수 있다. 기획 선택은 언제든 고칠 수 있고 뒤 활동의 초안에 반영한다. 이미 편집한 요청을 자동으로 덮어쓰지 않고 변경된 기획을 확인하도록 한다.

공통 예시로 연습한 완료와 자기 도구에서 실제 제작한 기록은 구분한다. 예시 연습으로도 다음 월드에 갈 수 있으며, 외부 유료 도구 설치·결제를 전체 학습 진입의 필수 조건으로 만들지 않는다. 실제 제작 여부는 사용자의 확인 기록이고 자동 검증으로 표현하지 않는다.

핵심 확인 질문은 세 가지다. ‘누가 어떤 행동을 하게 만들었나?’, ‘AI에게 어느 부분을 어떻게 바꾸라고 할 수 있나?’, ‘바뀐 결과가 맞는지 무엇으로 확인했나?’ 정답률이나 모든 장소 방문 횟수보다 이 세 가지와 남긴 결과물을 완료 판단에 사용한다.

- 도구 준비소: 도구와 모델의 차이, 프로젝트 열기·미리보기 준비를 필요한 사람만 확인한다. 공방에 들어가기 전에 언제든 갈 수 있다. 특정 도구의 가격·설치 절차는 배포 시점에 다시 확인한다.
- 연못 쉼터: 지금까지 선택한 내용을 다시 읽고 바꾸는 공간. 연속 접속·속도 보상·실패 벌점은 없다.
- 경험자는 같은 핵심 질문에 자신의 프로젝트로 답하고 설명을 접을 수 있다. 클릭 횟수로 숙련도를 추정하지 않는다.
- 오답이면 이유와 바뀐 결과를 보여주고 다시 선택한다. 목적이 여러 가지일 수 있는 선택형 기획을 하나의 정답으로 채점하지 않는다.

## 맵 제작안

사용자 추가 보완: 포인트는 단순히 길 위에 얹은 원형 표시가 아니라, 길이 둥글게 넓어진 원형 땅의 중심에 놓는다. 각 주요 장소 앞에 작은 원형 공터를 만들고 좁은 길이 이어지는 형태다. 실제 배경에는 공터를 포함하고, 상태를 나타내는 작은 중앙 마커는 코드로 분리하는 방향이다.

사용자 추가 확정: 각 학습 지점은 고전 플랫폼 게임의 월드 맵처럼 원형 포인트로 표시한다. 시안에서는 시작점 오렌지·나머지 크림색을 제안한다. 실제 구현에서는 현재·완료·아직 진행 전을 색 외 테두리·아이콘·접근성 이름으로 구분한다. 원화에는 마커 없는 버전을 남기고 코드의 원형 버튼을 올린다. 원형 포인트가 있는 이미지는 시각 검토용이다.

따뜻한 저채도 픽셀 아트의 한 섬. 좌하단 선착장에서 시작해 아래쪽 마을→오른쪽 언덕→중앙 서점·우체국→왼쪽 공방→위쪽 온실로 이어지는 S자 주 경로다. 8개 주요 건물과 2개 작은 곁길을 구분한다. 장소 번호·이름·진도는 이미지에 굽지 않고 코드로 올리는 것이 구현 원칙이다.

배경 원화의 지점 좌표는 그림 검수 후 확정한다. 프롬프트의 좌표를 그대로 실제 클릭 영역으로 쓰지 않는다. 모바일에서는 그림 전체를 지나치게 축소하지 않고 현재 구역을 보여주는 맵과 같은 순서의 장소 목록을 함께 제공하는 안이다.

장소 클릭→경로를 따라 천천히 이동→도착 후 활동을 여는 기존 방향을 유지한다. 캐릭터는 양손으로 배낭 어깨끈을 잡고 다리로 걸으며, 모션 줄이기에서는 즉시 이동한다. 불필요한 이동을 반복 강제하지 않도록 활동 다시 열기도 제공한다.

## 콘텐츠 표현과 구현 경계

대화·선택·분류·배치·비교·실제 제작으로 활동을 바꿔 지루함을 줄인다. 핵심 문장을 누르면 관련 화면이 반응하게 하되 본문 전체가 계속 움직이지 않는다. 모션이 없어도 같은 정보를 제공한다.

이번 산출물은 상세 순서와 새 맵 원화, 캐릭터 자세 시안이다. 기존 `/workbook/journey`는 모바일 실험 프로토타입으로 보존한다. 새 8개 활동이 연결되기 전에는 기존 진도를 새 월드 완료로 전환하지 않는다. 실제 AI 호출·외부 프로젝트 자동 검증은 구현 확정 사항이 아니다. 예시 결과는 ‘미리 만든 예시’라고 표시한다.
