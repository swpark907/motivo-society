# 첫 수업 제작안 — AI 이해하기

2026-10-06. 완전 입문자를 위한 실제 원고·활동 초안. 학습 순서는 사용자 합의를 반영했으며 세부 원고는 검토 전이다. 사이트에 발행하거나 구현하지 않았다. 특정 제품의 기능·가격·설치 절차는 다루지 않는다. 사실 설명은 발행 전 별도 검증한다.

## 수업의 목표와 경계

학습자는 AI에게 맡길 수 있는 일 하나와 결과에서 직접 확인할 부분 하나를 말할 수 있다. AI의 모든 종류와 기술 구조를 한 번에 이해하는 것이 목표는 아니다. 생성형 AI를 중심으로 시작하고, 모델·도구의 구분은 다음 수업에서, 에이전트는 도구 준비와 첫 대화 실습 이후 수업에서 다룬다. 예상 시간은 사용자 테스트 전에는 표시하지 않는다.

카피바라는 작업실에서 자신의 웹 작업을 소개하려는 동료다. 별도 출발 이야기 없이 아래 사례의 한 문장으로 등장한다. 지도에서는 ‘01 AI 이해하기’를 표시한다. 컷씬 시청이나 이동을 수업 완료 조건으로 삼지 않는다.

## 화면 1 — 제목과 배울 내용

**AI 이해하기**

AI에게 무엇을 부탁할 수 있고, 어떤 부분은 내가 확인해야 하는지 알아봐요.

오늘 할 일:

- AI와 생성형 AI라는 말의 의미 알아보기
- 짧은 소개문 예시에서 도움이 된 부분과 확인할 부분 찾기
- 내 작업에서 부탁할 일 하나 정하기

버튼: **설명부터 살펴보기**

## 화면 2 — 실제 설명 원고

**AI는 무엇인가요?**

AI는 인공지능을 뜻해요. 언어를 다루거나, 이미지에서 특징을 찾거나, 다음 결과를 예측하는 등 여러 작업을 수행하는 기술과 시스템을 넓게 부르는 말이에요. AI가 모두 대화하거나 그림을 만드는 것은 아니에요.

이 클래스에서는 주로 **생성형 AI**를 사용할 거예요. 생성형 AI는 요청과 주어진 정보를 바탕으로 글·이미지·코드 같은 결과를 만들어내는 AI예요. 우리가 문장으로 설명한 것을 소개문이나 웹 화면의 코드로 만드는 데 활용할 수 있어요.

그렇다고 내 의도를 전부 알고 있거나, 결과가 항상 맞는 것은 아니에요. 내가 알려주지 않은 내용을 그럴듯하게 덧붙이거나 사실과 다른 답을 낼 수 있어요. 그래서 **부탁할 내용을 알려주고, 나온 결과를 확인하고, 필요한 부분을 고치는 과정**이 함께 필요해요.

보조 펼침 ‘코드는 무엇인가요?’: 컴퓨터가 할 일을 표현한 글이에요. 웹에서는 화면에 무엇을 놓고 어떻게 보이게 할지, 버튼을 눌렀을 때 무엇을 할지 등을 코드로 정할 수 있어요. 지금은 코드를 읽거나 외울 필요가 없어요.

다음 연결 문장: 실제 예시에서 AI가 도와준 부분과 확인해야 할 부분을 나눠볼까요?

## 화면 3 — 짧은 상황과 비교 자료

카피바라: “내가 만든 작은 웹들을 소개하고 싶은데, 첫 문장이 잘 안 써져.”

**AI에게 알려준 내용**

“나는 차 따르기, 숨 고르기, 돌 쌓기를 해보는 작은 웹 경험을 만들었어. 처음 보는 사람이 어떤 작업인지 알 수 있게 소개문 두 문장을 써줘.”

**AI 응답을 가정한 학습 예시**

“차를 따르고, 숨을 고르고, 돌을 쌓으며 잠깐 쉬어갈 수 있는 작은 웹 경험을 만듭니다. 이미 1만 명이 선택한 공간에서 오늘의 여유를 만나보세요.”

※ 이 문장은 확인 연습을 위해 미리 만든 예시예요. 실제 이용자 수를 나타내지 않아요.

‘예시 결과 보기’를 누르면 미리 만든 응답이 펼쳐진다. 요청과 응답은 동시에 비교할 수 있게 보여준다. 사용자가 직접 요청하거나 수정하는 활동은 없으며 실제 AI 실행을 흉내 내는 로딩도 쓰지 않는다. 숫자에 자동 오류 표시를 먼저 하지 않는다. 그림은 작은 작업실 삽화 한 장이면 충분하며 별도 대화 넘김은 없다.

## 화면 4 — 활동: 확인할 부분 찾기

질문: **알려준 내용만으로 확인할 수 없는 부분은 무엇인가요?**

선택지:

1. 차를 따르고, 숨을 고르고, 돌을 쌓는 웹 경험
2. 잠깐 쉬어갈 수 있는 소개 방식
3. 이미 1만 명이 선택했다는 내용

3번 피드백: “맞아요. 요청에는 이용자 수가 없어요. 그럴듯한 문장이어도 이 숫자는 근거를 확인해야 해요. 확인할 자료가 없다면 소개에서 빼는 것이 좋겠어요.”

1번 피드백: “이 작업들은 요청에 직접 알려줬어요. 답변이 그 내용을 잘 반영했는지 확인하는 것은 필요하지만, 새로 덧붙인 정보는 아니에요.”

2번 피드백: “‘잠깐 쉬어간다’는 소개 방향이에요. 내 의도와 맞는지 판단할 부분이지요. 선택지 중 구체적인 실적을 새로 주장한 부분을 찾아보세요.”

틀린 선택에도 벌점·실패 연출을 주지 않는다. 이유를 읽고 다시 선택할 수 있다. ‘AI의 답은 전부 틀린다’고 일반화하지 않도록 아래 설명을 이어서 표시한다.

**AI는 소개문 초안을 만드는 데 도움을 줬어요. 다만 덧붙인 실적까지 사실로 받아들이면 안 돼요. 문장이 마음에 드는지와 내용이 사실인지는 따로 확인해야 해요.**

## 화면 5 — 핵심 정리와 내 작업 연결

**오늘 배운 것**

1. AI는 여러 작업을 수행하는 기술과 시스템을 넓게 부르는 말이에요. 생성형 AI는 글·이미지·코드 같은 결과를 만들 수 있어요.
2. AI에게 초안을 부탁할 수 있지만, 내가 주지 않은 사실이 추가됐는지는 확인해야 해요.
3. 어떤 도구를 쓸지 알아보고 준비한 다음, 직접 요청하고 수정하는 방법을 연습할 거예요.

짧은 적용: **내 작업에서 AI에게 부탁하고 싶은 일은?**

‘소개문 초안 만들기 / 흩어진 메모 정리하기 / 웹 화면 만들기 / 직접 적기’ 중 선택. 이어서 **‘결과에서 내가 확인할 것은?’**에 사실·누락·의도와의 일치 같은 예시를 제공하고 한 가지를 고르거나 작성한다. 자유 서술을 자동 정답 판정하지 않는다. 이후 수업에서 다시 볼 메모로 활용한다.

마지막 카피바라 대사: “초안은 함께 만들고, 내 작업에 맞는지는 직접 확인하는 거구나.”

다음 수업 안내: **AI의 종류와 도구 알아보기 — 하고 싶은 일에 맞는 AI는 어떻게 고를까요?**

## 완료와 접근성

짧은 예시의 확인 활동을 마치고 정리하면 수업 완료. 요청 작성·수정 실습은 도구 준비 뒤의 ‘AI와 첫 대화하기’에서 진행한다. 개인 메모는 선택이며 개인정보 입력을 요구하지 않는다. 이미 아는 사람은 ‘확인 문제부터’로 화면 4에서 시작하고 설명으로 돌아갈 수 있다. 이야기 감상 여부와 이동 애니메이션은 진도와 무관하다.

선택지는 실제 버튼·라디오로 제공하며 키보드로 선택한다. 피드백은 텍스트로 읽을 수 있고 색에만 의존하지 않는다. 정답을 맞힌 뒤 자동으로 다음 화면으로 넘기지 않는다. 설명은 언제든 다시 펼쳐볼 수 있다.

## 검토 질문

- AI를 처음 접한 사람이 생성형 AI를 ‘정답을 찾아주는 검색창’으로만 이해하지 않는가?
- 수강생이 실제로 배운 것은 무엇이라고 말하는가? 카피바라 이야기만 기억하지 않는가?
- 요청과 결과를 비교하는 데 어떤 단어에서 막히는가?
- 선택지를 외워 맞히는 것을 넘어, 다른 예시에서 확인할 부분을 찾을 수 있는가?
- 글의 양과 그림이 이해에 도움이 되는가? 화면 수는 테스트 후 줄이거나 합친다.
