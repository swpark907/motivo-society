# 워크북 2단원 — 기획하고 첫 화면 만들기

2026-11-18 · 승우와 정한 2단원 다시 만들기(A안). 1단원과 같은 방식으로 화면 하나씩 제안 → 선택 → 구현한다. 수업 수(3개)와 제목·주소(`page-planning`·`page-request`·`page-building`)는 그대로다. 수업 만들기 규칙은 `docs/product/workbook-lesson-authoring.md`를 따른다.

## 목표

1단원 1-6에서 만든 `my-first-web/index.html`(제목 "내 소개" + 붙여 넣은 소개 글)을 그대로 이어서, 읽을 사람을 정하고 → 그 사람에게 맞게 같은 파일을 고쳐 달라고 부탁하고 → 고친 화면을 기획과 맞춰 본다. 새 폴더나 새 예제를 만들지 않는다.

## 계정 기록·권한을 위한 경계 (구현됨, DB 연결 전)

- `src/lib/workbook-lesson-records.ts` — 방문 상태를 수업별 행 `{classSlug, lesson(slug), status, mode, fields}`로 바꾸는 한 곳. 1단원 순번 → 수업 이름 변환도 여기뿐이다. 학습자가 쓴 칸만 담는다. `isUnitOneDone`·`unitOneRemaining`도 여기 있다.
- `src/lib/workbook-access.ts` — 단원을 열 수 있는지 확인하는 한 곳. 지금은 무료 체험이라 전부 연다. 진도 해금(앞 단원 완료)은 여기서 보지 않고 완료 기록에서 계산한다.
- 화면 상태(`lessonUi`: 펼침·선택·고른 이름표)는 저장하지 않는다. 기획 칸은 `ProjectRecord`(제목·읽을 사람·목적·소개·내용·나중에 채울 것)에 있다.

## 수업 넘어가기 (구현됨, 1·2단원 공통)

2026-11-18 승우 결정("합친 방식"). 1단원은 정리 → "학습 마치고 단원 지도로" → 지도에서 다음 수업, 2-1은 정리 → 바로 다음 수업으로 서로 달랐다. 이제 모든 수업의 정리 화면 하단은 주 버튼 **"다음: n-m 수업 이름 →"**(좁은 화면 "다음 수업 →")과 옆의 작은 **"단원 지도로"**다. 둘 다 누르는 순간 이 수업을 마친 것으로 기록한다. 단원 마지막 수업은 다음 단원을 열 수 있으면 "n단원 시작하기 →"(지도 도착 장면), 아니면 "학습 마치고 단원 지도로 →". 공통 컴포넌트 `WorkbookLessonFinish`.

## 2-1 홈페이지 기획하기 (구현됨 · 2026-11-18 세 번째 구성)

1차(입력 칸 다섯 곳)는 "입력받는 게 많고 레거시하다", 2차(고르기 다섯 화면)는 "배운 것이 없다 · 기획은 큰 주제라 더 넣을 것이 있다 · 그릴링 스킬을 소개하자"는 승우 피드백을 받았다. 지금은 1단원 수업처럼 다섯 화면 + 정리이고, 정리 제목도 1단원과 같은 "오늘 알게 된 것"이다. **입력 칸은 정리 화면의 "직접 고쳐 쓰기"(선택) 하나뿐이다.**
