# 두 번째 수업 제작안 — AI 종류와 도구 알아보기

2026-10-06. 합의된 입문 순서를 따른 원고·활동 초안. 세부 구성은 에이전트 제안이며 아직 화면에 구현하거나 발행하지 않았다. 제품 예시는 공식 문서를 참고했으나 설치 실습·사람의 발행 검증은 별도로 필요하다.

## 목표와 범위

수업을 마치면 ‘내가 만들 결과 → 필요한 기능 → 사용할 도구’ 순서로 생각할 수 있고, 모델과 도구가 같은 뜻은 아니라는 점을 설명할 수 있다. 제품 순위나 모델 이름 암기는 평가하지 않는다. 설치·직접 요청·수정 실습은 다음 수업으로 넘긴다.

‘AI 종류’는 이 수업에서 용도에 따라 살펴보는 묶음이다. 기술적으로 서로 배타적인 분류라고 가르치지 않는다. 한 도구가 여러 종류의 작업을 지원할 수 있다. 에이전트는 뒤 수업에서 다룰 작업 방식이며 여기에 별도의 제품 종류로 섞지 않는다.

## 화면 1 — 무엇을 만들고 싶은가요?

**AI 종류와 도구 알아보기**

AI 이름이 많아도 전부 외울 필요는 없어요. 먼저 내가 어떤 도움을 받고 싶은지부터 살펴봐요.

오늘 배울 것:

- 글·이미지·웹 제작에 필요한 기능의 차이
- AI 모델과 우리가 사용하는 도구의 관계
- 다음 실습에서 사용할 도구를 고르는 기준

카피바라: “소개 글도 쓰고 그림도 넣고 싶은데, 어디서 시작하면 좋을까?”

짧은 대사 한 줄 이후 바로 학습 자료를 보여준다. 별도 컷씬이나 세계관 설명은 없다.

## 화면 2 — 만들 결과부터 살펴보기

**어떤 결과가 필요한가요?**

아래 세 탭을 누르면 같은 홈페이지에 필요한 서로 다른 결과 예시가 나타난다. 기본으로 첫 탭이 열려 있다. 모두 사전 제작한 학습 자료라고 표시한다.

| 탭        | 요청을 가정한 예시                              | 보여줄 결과                                | 설명 원고                                                                                                         |
| --------- | ----------------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 소개 글   | 내 작업을 소개하는 짧은 글을 쓰고 싶어요.       | 소개문 두 문장                             | 대화로 생각을 정리하고, 글의 초안을 만들거나 표현을 고치는 도움을 받을 수 있어요.                                 |
| 표지 그림 | 작업실 분위기의 그림이 필요해요.                | 작업실 그림 한 장                          | 이미지를 만들거나 바꾸는 기능이 필요해요. 글로 그림을 설명받는 것과 실제 이미지 파일을 만드는 것은 다른 결과예요. |
| 웹 화면   | 소개 글과 그림이 있는 웹페이지를 만들고 싶어요. | 웹 화면과 파일의 관계를 보여주는 정적 예시 | 웹 제작에서는 코드를 만드는 것에 더해, 파일에 반영하고 화면에서 결과를 확인할 수 있는지도 살펴봐요.               |

보조 문장: AI는 이 밖에도 음성·영상 등 여러 작업에 쓰여요. 지금은 웹 만들기에 연결되는 세 가지를 먼저 살펴볼게요.

**한 도구가 글과 이미지 작업을 함께 지원하기도 해요. 이 세 가지는 서로 다른 제품을 꼭 세 개 써야 한다는 뜻이 아니에요.**

학습자는 탭을 전부 누르지 않아도 다음으로 갈 수 있다. 클릭 횟수를 이해의 증거로 기록하지 않는다.

## 화면 3 — 모델과 도구는 어떻게 다른가요?

**쓰는 화면과 그 안의 AI를 구분해봐요.**

‘모델’은 입력을 처리하고 결과를 만들어내도록 학습된 AI의 핵심 부분이에요. ‘도구’는 우리가 그 기능을 이용하는 웹사이트나 프로그램이에요. 요청을 입력하는 창, 파일을 올리는 기능, 결과를 저장하는 기능 등이 함께 제공될 수 있어요.

예시 그림은 ‘사용자 → 도구의 입력창 → AI 모델 → 도구에서 결과 보기’로 표시한다. 단순화한 관계도임을 밝히며 내부 작동 전부를 표현한다고 설명하지 않는다.

**도구에 따라 여러 모델 중 하나를 고를 수 있고, 같은 모델이 여러 도구에서 사용되기도 해요.** 그래서 모델 이름만 같다고 사용할 수 있는 기능까지 모두 같지는 않아요.

조작: ‘입력창·파일·저장 기능 보기’ / ‘결과를 만드는 모델 보기’ 두 버튼으로 해당 영역만 강조한다. 전체 설명은 처음부터 읽을 수 있게 두며 조작이 본문을 잠금 해제하지 않는다.

이름이 헷갈린다면: “지금 여는 것은 어떤 도구이고, 그 안에서 사용하는 모델은 무엇인지” 두 질문으로 나누면 돼요. 서비스와 모델에 비슷한 이름을 쓰는 경우도 있어서 이름만으로 구별하지 않아도 괜찮아요.

## 화면 4 — 실제 제품에서는 어떻게 보이나요?

본문과 분리한 ‘실제 예시 펼쳐보기’. 추천 순위·구매 안내가 아니며 읽기는 선택이다.

- Adobe Firefly의 이미지 생성 화면에서는 글로 설명해 이미지 결과를 만들 수 있어요. 도구 안에서 사용할 모델을 선택하는 예도 볼 수 있어요.
- GitHub Copilot은 코드 편집기 안에서도 사용할 수 있어요. 대화로 코드 작업을 돕거나 파일을 다루는 기능처럼 작업 환경과 연결된 기능이 있어요.

두 제품을 실습 도구로 확정한 것은 아니다. 설명 옆에 공식 출처를 연결한다. 제품 버전·플랜별 기능과 이용 가능 여부는 실제 안내 시 재확인한다. 로고나 이름을 보고 맞히는 문제는 만들지 않는다.

## 화면 5 — 필요한 기능 고르기

**작업실 그림을 ‘이미지 파일’로 받고 싶어요. 무엇을 먼저 확인하면 좋을까요?**

1. 그림을 말로 설명해줄 수 있는지
2. 이미지를 생성하고 저장할 수 있는지
3. 가장 최신 모델 이름이 붙어 있는지

2번 피드백: “맞아요. 원하는 결과가 이미지 파일이므로 생성과 저장 기능을 확인해요. 그다음 분위기나 수정 기능이 작업에 맞는지도 살펴볼 수 있어요.”

1번 피드백: “설명은 그림을 구상할 때 도움이 돼요. 하지만 지금 필요한 것은 실제 이미지 파일이에요. 그 결과를 만들 수 있는 기능을 찾아볼까요?”

3번 피드백: “이름만으로는 원하는 작업을 지원하는지 알기 어려워요. 먼저 필요한 결과를 만들 수 있는지 살펴봐요.”

추가 확인: **한 도구가 글과 이미지를 모두 만들 수 있을까요?**

‘그럴 수 있다’ 선택 시 “맞아요. 용도가 겹칠 수 있으니 작업마다 무조건 새 도구를 설치할 필요는 없어요.” ‘반드시 따로 써야 한다’ 선택 시 같은 설명과 화면 2로 돌아가는 링크를 제공한다.

오답은 바로 설명하고 다시 선택할 수 있게 한다. 시간제한·생명·점수 경쟁은 없다. 정답 이후 화면은 사용자가 직접 넘긴다.

## 화면 6 — 정리와 다음 수업

**도구 이름보다 먼저, 필요한 결과를 생각해요.**

1. 무엇을 만들지 정해요. 글인지, 이미지인지, 웹 화면인지 살펴봐요.
2. 필요한 기능이 있는지 확인해요. 생성뿐 아니라 파일 반영·저장·결과 확인도 작업에 따라 중요해요.
3. 모델은 AI의 핵심 부분, 도구는 그 기능을 이용하는 웹사이트나 프로그램이에요.

카피바라: “우선 소개 글을 함께 다듬을 도구부터 준비해보자.”

**다음 수업: 사용할 도구 준비하기**

“다음에는 이 클래스에서 안내하는 도구 하나를 준비해요. 웹으로 접속하는 경우와 프로그램 설치가 필요한 경우를 구분하고, 준비가 끝나면 첫 대화를 해볼 거예요.”

첫 도구는 아직 미선정이다. 제작 시에는 학습자에게 여러 제품 중 혼자 고르게 하기보다 기본 경로 하나를 구체적으로 안내하는 방안을 제안한다. 선택을 넓히는 기준을 가르치되 시작 단계의 선택 부담은 줄인다.

## 제작·검토 기준

- 원고의 ‘화면’은 학습 묶음이며 여섯 번의 페이지 이동을 강제하지 않는다. 제목·학습 순서·이전 설명으로 돌아가기를 제공한다.
- 탭·선택지는 키보드로 조작하며 결과 피드백은 텍스트로 전달한다. 모바일에서는 표를 카드로 풀어 읽는다.
- 강조는 사용자가 누른 부분에만 작게 적용한다. 새로운 모션 연출은 구현 전 디자인 규칙과 별도로 검토한다.
- ‘종류를 안다’는 제품명 암기가 아니라 작업에 필요한 기능을 설명하는 것으로 확인한다. 모델/도구 구분은 “쓰는 프로그램이 같아도 모델 선택이 달라질 수 있다”를 자신의 말로 설명하는 선택형 복습을 제공한다.
- 기본 도구 선정 전 확인할 것: 첫 대화와 수정 연습 가능 여부, 한국어 안내의 명료함, 계정·비용 조건, 학습자 환경, 다음 코딩 실습으로 연결할 때의 추가 준비. 특정 유료 플랜을 전제로 확정하지 않는다.
- 진행 저장·제품 추천·AI 호출 기능을 이 문서만으로 구현 확정하지 않는다.
