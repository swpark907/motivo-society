# 모쏘 커뮤니티 플랫폼 기능 명세 (초안)

2026-11-02. [대략 기획](platform-community-plan.md)을 DB 설계가 가능한 수준까지 구체화한 문서다. 영역마다 **사용자가 하는 일 → 입력하고 보는 정보 → 상태 → 규칙** 순으로 적는다.

- **제안 기본값**: 따로 정하지 않으면 이렇게 간다는 제안이다. 확정이 아니다.
- **결정 필요**: 사용자(승우)나 대표가 정해야 DB가 달라지는 지점이다.
- 범위: 웹 단계 1~6(대략 기획 6절). "나중"으로 표시한 것은 자리만 남긴다.
- 용어는 모두 가칭이다.

---

## 0. 공통 규칙

- **공개 범위**: 클럽, 모임, 시즌, 챌린지, 공간마다 `누구나 / 멤버만`을 정한다. 기본값은 누구나(열림 원칙).
- **삭제 대신 보관**: 참여 기록·결제가 걸린 것(모임, 주문, 클럽)은 지우지 않고 취소·보관 상태로 남긴다. 글과 댓글은 "삭제된 글"로 표시하고 내용만 지운다.
- **누가 언제**: 상태를 바꾸는 행동(승인, 확정, 입금 확인, 강퇴, 정지)은 누가 언제 했는지 기록한다.
- **시간대**: 모든 일시는 한국 시간 기준으로 보여 주고 저장은 표준시로 한다.

## 1. 계정과 프로필

**사용자가 하는 일**

- 가입하고 로그인한다.
- 가입 직후 닉네임과 관심사를 고른다.
- 프로필을 꾸미고, 다른 사람의 공개 프로필을 본다.
- 알림 수신을 설정한다.
- 탈퇴한다.

**정보**

| 구분      | 항목                                    | 필수            | 공개   |
| --------- | --------------------------------------- | --------------- | ------ |
| 기본      | 닉네임, 관심사(1~5개)                   | 필수            | 공개   |
| 꾸미기    | 프로필 사진, 한 줄 소개, 링크(최대 3개) | 선택            | 공개   |
| 본인 정보 | 이메일                                  | 가입 시         | 비공개 |
| 본인 정보 | 실명, 전화번호, 출생 연도               | 필요한 순간에만 | 비공개 |

- 실명·전화번호가 필요한 순간: 유료 신청, 호스트 자격 신청, 연령 제한 모임.
- 공개 프로필 페이지: 닉네임, 소개, 관심사, 참여 중인 클럽(본인이 공개를 허용한 것만), 공유한 결과물.

**규칙**

- 관심사 목록은 플랫폼(소유자)이 관리한다. 사용자가 새로 만들지 않는다.
- 탈퇴하면 본인 정보는 지운다. 작성한 글은 "탈퇴한 사용자"로 남긴다. 결제 기록은 법정 보관 기간 동안 남긴다.
- 클럽 관리자이면 양도하기 전에는 탈퇴할 수 없다.

**결정 필요**

- **로그인 방식 (2026-11-02 확정): 카카오 로그인 + 이메일.** 운영 중인 형제 서비스는 이메일+비밀번호(`signInWithPassword`)를 쓰므로 기존 회원은 그대로 로그인한다. 같은 이메일의 카카오 계정은 하나의 계정으로 연결한다(연결 방식은 구현 때 확인).
- 닉네임 중복 허용 여부. 제안 기본값: 허용하지 않음.

## 2. 호스트 자격

**사용자가 하는 일**

- 호스트 자격을 신청한다. 무엇을 열고 싶은지, 자기소개, 참고 링크를 적는다.
- 승인되면 클럽을 만들거나 클럽 밖 모임을 열 수 있다.

**상태**: 신청 → 승인 / 반려 → (정지)

**단계**

| 단계        | 할 수 있는 일                              | 추가로 받는 정보                       |
| ----------- | ------------------------------------------ | -------------------------------------- |
| 기본 호스트 | 클럽 만들기, 클럽 밖 무료 모임·챌린지 열기 | 없음                                   |
| 유료 호스트 | 유료 모임·시즌·챌린지 열기                 | 실명, 연락처, 정산 계좌, (사업자 정보) |

**규칙**

- 소유자가 승인한다.
- 정지되면 새로 열 수 없고, 이미 연 모임은 소유자가 처리한다.
- 클럽 안에서 모임을 여는 데는 호스트 자격이 필요 없다. 클럽 레이어 권한으로 연다.

**결정 필요**

**확정 (2026-11-02)**

- 클럽 만들기에도 호스트 자격이 필요하다(초기 품질 관리). 나중에 문을 넓힐 수 있다.
- **계좌이체 단계에서도 승인된 호스트가 유료 모임을 연다.** 참가비는 모쏘가 받고, 모쏘가 호스트에게 수동으로 정산한다. 그래서 정산 기록(9절)이 처음부터 필요하다.

**결정 필요**

- 유료 호스트 승인 조건과 받을 정보(실명, 연락처, 정산 계좌, 사업자 여부).
- 수수료율과 정산 주기. 대표 승인 사항이다.
- 모쏘가 대신 받는 돈의 법적 성격(판매자인지 중개자인지), 호스트에게 줄 때의 세금 처리(원천징수 등). 운영 전에 법률·세무 확인이 필요하다.

## 3. 클럽

**사용자가 하는 일**

- (호스트) 클럽을 만든다.
- 클럽을 찾아 가입한다. 가입 질문에 답한다.
- 초대 링크로 들어온다.
- 탈퇴한다.

**클럽 정보**: 이름, 한 줄 소개, 소개 본문, 대표 이미지, 관심사 태그(1~3), 활동 지역(선택, 온라인 클럽은 비움), 가입 방식(바로 가입 / 승인 후 가입), 가입 질문(승인 방식일 때 최대 3개), 공개 범위, 멤버 정원(선택).

**클럽 상태**: 운영 중 → 보관(관리자가 닫음) / 정지(소유자 조치)

**멤버 상태**: 가입 신청 → 멤버 → 탈퇴 / 강퇴(재가입 차단)

**레이어(역할)**

- 고정: 관리자(최상위, 최소 1명), 멤버(최하위)
- 기본 제공: 운영진(이름 변경 가능)
- 관리자가 그 사이에 레이어를 추가한다. 최대 6개.
- 권한 목록(플랫폼이 정의):

| 묶음 | 권한                                             |
| ---- | ------------------------------------------------ |
| 클럽 | 클럽 정보 수정, 공간 만들기·설정                 |
| 사람 | 가입 승인, 강퇴, 레이어 지정, 초대 링크 만들기   |
| 활동 | 모임·시즌·챌린지 열기, 공지 쓰기, 글 고정·숨기기 |
| 민감 | 참가자 연락처 보기, 참가 확정·취소 처리          |

- 안전 규칙: 자기보다 아래 레이어만 관리하고, 자기가 가진 권한만 남에게 준다. 마지막 관리자는 양도하지 않고는 나갈 수 없다. 레이어를 지우면 그 사람들은 멤버로 내려간다.

**초대 링크**: 만든 사람, 만료일(선택), 사용 횟수 제한(선택). 링크로 들어오면 승인 방식이어도 바로 가입된다.

**결정 필요**

- 관리자 탈퇴 시 자동 승계를 할지. 제안 기본값: 양도를 요구하고, 관리자 계정이 탈퇴·정지되면 다음 레이어에서 가장 오래된 사람이 승계한다.
- 한 사람이 가입할 수 있는 클럽 수 제한. 제안 기본값: 없음.

---

## 4. 공간(클럽 안의 게시판)

**사용자가 하는 일**

- 클럽 안의 공간(예: 공지, 자유, 질문, 결과물)에 글과 댓글을 쓴다.
- 반응(좋아요)을 누른다.
- 신고한다.

**공간 정보**: 이름, 설명, 순서, 보기 권한(누구나 / 멤버), 쓰기 권한(멤버 / 특정 레이어 이상), 종류(일반 / 공지 / 결과물)

**글 정보**: 제목(선택), 본문, 이미지(최대 10장), 링크. 결과물 글은 결과물 링크·대표 이미지가 필수다.

**규칙**

- 새 클럽에는 공지·자유 공간이 기본으로 생긴다.
- 공지 공간에 글을 쓰면 멤버에게 알림이 간다.
- 권한 있는 레이어는 글을 고정(최대 3개)하거나 숨긴다.
- 결과물 글은 소유자가 "큐레이션 후보"로 표시할 수 있다. 아티클·라이브러리로 옮기는 일은 기존 발행 절차를 따른다.
- 웹 단계는 비동기만 한다. 실시간 채팅은 없다.

## 5. 모임

**사용자가 하는 일**

- (주최자) 모임을 만들고, 진행자를 지정하고, 참가자를 관리하고, 출석을 체크한다.
- 모임을 찾아 신청하고, 취소하고, 대기한다.
- 모임 대화에서 질문하고 후기를 남긴다.

**모임 정보**

| 묶음      | 항목                                                          |
| --------- | ------------------------------------------------------------- |
| 소개      | 제목, 소개, 대표 이미지, 관심사 태그                          |
| 주최      | 클럽 또는 호스트 개인, 진행자(여러 명 가능)                   |
| 형식      | 오프라인: 장소 이름, 주소, 지도 링크 / 온라인: 화상 링크      |
| 일정      | 시작·종료 일시, 신청 마감                                     |
| 인원      | 최대 정원, 최소 인원(선택)                                    |
| 대상      | 누구나 / 클럽 멤버 / 특정 이용권 보유자(예: 클래스 수강자)    |
| 참가 방식 | 바로 확정 / 주최자 승인                                       |
| 비용      | 무료 / 유료(금액) + 현장 비용 안내 문구(예: "음료 각자 결제") |
| 신청 질문 | 선택, 최대 3개                                                |

**모임 상태**: 초안 → 모집 중 → 모집 마감 → 종료 / 취소

**참가 상태**: 신청 → (승인 대기) → (입금 대기) → 확정 → 참석 / 불참. 언제든 취소(본인 또는 주최자). 정원이 차면 대기.

**규칙**

- 온라인 화상 링크는 확정된 참가자에게만, 시작 30분 전부터 보인다.
- 오프라인 상세 주소도 확정된 참가자에게만 보이게 할 수 있다(설정).
- 확정자가 취소해 자리가 나면 대기자 전원에게 알림이 가고, 먼저 신청한 사람이 확정된다.
- 리마인드: 전날과 1시간 전.
- 출석은 진행자가 체크한다. 온라인도 링크 클릭만으로 출석 처리하지 않는다.
- 최소 인원에 미달하면 마감 시점에 주최자에게 알리고, 주최자가 진행 또는 취소를 고른다. 취소하면 유료는 전액 환불한다.
- "다음 주 같은 시간으로 복제"로 반복 모임을 만든다. 반복은 만들기 편의 기능이며 각 모임은 독립적이다.
- 후기는 참석 처리된 사람만 쓴다(본문, 사진).

**모임 대화(스레드)**

- 참가자 대화: 확정된 참가자와 진행자만 보고 쓴다. 준비물 질문, 공지, 끝난 뒤 사진.
- 공개 문의: 신청 전에 누구나 질문한다(로그인 필요).

**결정 필요**

- 노쇼 기록을 남겨 다음 신청에 반영할지. 제안 기본값: 기록만 남기고 지금은 제재하지 않는다.
- 공개 문의를 둘지, 참가자 대화 하나만 둘지.

## 6. 시즌(다회차)

**사용자가 하는 일**

- (주최자) 회차 일정을 정해 시즌을 연다.
- 시즌에 등록하면 모든 회차에 참가자로 들어간다.

**시즌 정보**: 제목, 소개, 대표 이미지, 주최, 회차 목록(각 회차는 5절의 모임), 등록 기간, 최대·최소 인원, 비용(시즌 단위), 중도 합류 허용 여부.

**상태**: 초안 → 등록 중 → 진행 중 → 종료 / 취소. 등록 상태는 모임 참가와 같은 흐름이다.

**규칙**

- 등록하면 각 회차 모임에 확정 참가자로 자동 등록된다. 회차를 개별 신청하지 않는다.
- 회차별 출석이 모여 시즌 출석률이 된다.
- 최소 인원 미달 시 처리는 모임과 같다(주최자가 진행·연기·취소 선택).
- 형제 서비스의 오프라인 클래스(4주 과정)는 모쏘 공식 주최 시즌으로 옮긴다.

**나중**: 다른 시즌 회차 한 번 체험하기(동행클럽의 놀러가기형), 회차 중간 환불 계산.

**결정 필요**

**확정 (2026-11-02)**: 시즌과 챌린지 모두 클럽 밖에서 호스트 개인이 열 수 있다.

---

## 7. 챌린지

**사용자가 하는 일**

- (주최자) 기간, 미션, 인증 방식을 정해 챌린지를 연다.
- 참가 신청하고, 기간 동안 인증을 올리고, 다른 참가자를 응원한다.
- 진행 현황과 완주 여부를 본다.

**챌린지 정보**: 제목, 소개, 대표 이미지, 주최, 시작·종료일, 인증 규칙(매일 / 주 N회 / 기간 중 총 N회), 미션(날짜별 미션 목록 또는 자유 미션 하나), 인증 형식(글 / 사진 / 링크 중 허용할 것), 완주 조건(인증 N회 이상), 대상(누구나 / 클럽 멤버 / 이용권 보유자), 정원(선택), 비용.

**인증 정보**: 몇째 날 또는 어느 미션의 인증인지, 본문, 사진, 링크, 올린 시각.

**상태**: 초안 → 모집 중 → 진행 중 → 종료 / 취소. 참가 상태는 모임과 같고, 종료 시 완주 / 미완주가 정해진다.

**규칙**

- 인증은 해당 날짜(한국 시간 자정까지) 안에 올려야 인정된다. 다음 날 수정은 할 수 없다.
- 인증은 올리면 바로 인정된다. 주최자는 부적절한 인증을 반려할 수 있다(사유 기록).
- 참가자끼리 서로의 인증을 보고 반응·댓글을 단다.
- 현황판: 참가자별 인증 횟수와 완주까지 남은 수.
- 시작 후 신청은 기본적으로 막는다(주최자가 허용 가능).

**나중**: 완주 시 참가비 환급(포인트), 완주 뱃지.

**결정 필요**

- 인증을 다른 참가자에게 공개할지, 주최자에게만 보일지 선택하게 할지. 제안 기본값: 참가자에게 공개(함께 해내는 감각).

## 8. 클래스와 진도

**사용자가 하는 일**

- 클래스를 살펴보고 구매(또는 무료 시작)한다.
- 수업을 진행하면 진도와 작성 기록이 저장된다. 다른 기기에서도 이어서 한다.
- 수강자 전용 챌린지·시즌·클럽에 들어간다.

**클래스 정보**: 이름, 소개, 단원·수업 구성(지금은 코드의 `workbook-course.ts`가 정본), 가격, 이용 기간(무제한 / N일), 무료로 열어 두는 수업 범위(선택).

**진도 정보**: 수업별 완료 여부와 완료 시각, 수업 안 현재 위치, 작성 기록(기획, 관찰, 요청 등), 첨부한 결과 화면 이미지.

**규칙**

- 수강 권한은 이용권으로 판정한다.
- 진도와 작성 기록은 지금 브라우저 메모리·IndexedDB에 있는 구조를 서버로 옮긴다. 처음에는 "수업 완료 기록 + 사용자별 클래스 상태 묶음"으로 시작하고, 필요한 항목부터 따로 뺀다.
- 수료 기준은 필수 수업 완료다. 실제 제작·배포 성공은 자동 판정하지 않는다(기존 원칙).

**결정 필요**

- 웹 클래스의 판매 방식(가격, 이용 기간, 무료 범위). 대표 승인 사항이다.
- 비로그인 체험 범위. 제안 기본값: 1단원 앞부분은 로그인 없이, 진도 저장은 로그인 후.

## 9. 주문, 결제, 이용권

**사용자가 하는 일**

- 유료 모임·시즌·챌린지·클래스를 신청하면 주문이 생기고 입금 안내를 받는다.
- 입금하면 운영진 확인 후 확정 알림을 받는다.
- 현금영수증을 요청한다.
- 취소·환불을 요청한다.

**주문 정보**: 주문자, 대상(모임 / 시즌 / 챌린지 / 클래스), 금액(서버가 계산), 결제 수단(지금: 계좌이체), 입금자명, 입금 기한(24시간), 현금영수증 요청 정보, 확인한 운영진과 시각.

**주문 상태**: 입금 대기 → 결제 완료 → (환불 요청 → 환불 완료). 기한 초과 시 만료, 입금 전 취소 시 취소.

**이용권 정보**: 누구에게, 무엇에 대해, 출처(주문 / 무료 신청 / 초대 / 운영 부여 / 수료), 시작·종료, 상태(유효 / 만료 / 회수).

**규칙**

- 결제 완료가 되면 이용권이 생기고, 참가 상태가 확정이 된다.
- 무료 참가도 이용권을 만든다. 모든 참여 권한 판정을 한 곳에서 하기 위해서다.
- 환불하면 이용권이 회수되고 참가가 취소된다.
- 환불 금액은 대상 종류별 환불 규정과 요청 시점으로 계산한다. 규정은 버전으로 관리하고, 주문에 적용된 규정을 남긴다.
- 입금 대기 중에도 자리는 잡아 둔다. 기한이 지나면 풀린다.
  **호스트 정산 (계좌이체 단계, 2026-11-02 확정 방향)**
- 정산 대상: 호스트 주최의 결제 완료 주문.
- 정산 기록: 호스트, 대상 기간, 포함된 주문, 매출 합계, 환불 차감, 수수료, 지급액, 지급일, 처리한 운영진.
- 상태: 정산 예정 → 지급 완료. 지급 뒤 환불이 생기면 다음 정산에서 뺀다.
- 주문에는 그 시점의 수수료율을 함께 남긴다.
- 나중: PG 결제, 자동 정산.

**결정 필요**

- 환불 규정(종류별 표). 대표 승인 사항이다. 벤치마킹 참고: 동행클럽은 시작 14일 전 100% ~ 4일 전 0%, 인프런은 7일 이내·진도 7% 미만.
- 입금 대기 중 자리 확보 여부. 제안 기본값: 확보한다(형제 서비스와 같음).

## 10. 알림

**종류**: 가입 승인, 참가 확정·대기 자리, 입금 확인, 리마인드, 클럽 공지, 내 글의 댓글·반응, 호스트 자격 결과, 신고 처리 결과.

**경로**: 사이트 안 알림함 + 이메일. 웹 푸시는 나중, 앱 푸시는 앱 단계에서.

**규칙**

- 사용자가 종류별로 이메일 수신을 끌 수 있다. 결제·확정처럼 거래에 필요한 알림은 끌 수 없다.

## 11. 발견과 검색

- 홈: 관심사 기반 추천(클럽, 다가오는 모임, 모집 중 챌린지) + 모쏘 공식 픽.
- 목록 필터: 관심사, 온라인 / 오프라인, 지역, 날짜, 무료 / 유료, 모집 중.
- 검색: 이름과 소개 텍스트.
- 링크로 들어온 상세 페이지는 그 자체로 완결된다(AGENTS.md의 DM 진입 원칙). 공유 미리보기(OG)를 갖는다.

## 12. 신뢰와 운영(소유자)

**사용자가 하는 일**

- 사용자, 클럽, 모임, 글, 댓글, 인증을 신고한다(사유 선택 + 설명).

**소유자가 하는 일**

- 신고를 처리한다: 숨김, 경고, 기간 정지, 영구 정지.
- 호스트 자격을 심사한다.
- 입금을 확인하고 환불을 처리한다.
- 클럽을 정지한다.
- 관심사 목록과 공식 픽을 관리한다.
- 결과물 큐레이션 후보를 본다.

**규칙**

- 모든 조치와 개인정보 열람은 기록한다.
- 이의신청은 나중.

**결정 필요**

- 사용자 간 차단 기능을 웹 단계에 넣을지. 제안 기본값: 넣는다(차단하면 서로의 글이 숨겨지고 같은 모임 신청은 막지 않는다).
