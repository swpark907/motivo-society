# 카피바라와 작업 공간 · 수집품 제안

## 최신 구현 — 고정 자리 작업실

**2026-10-18 현재 기준:** 학습과 성취를 우선한다. 학습 중 수집 목표·공통 도착 배너는 제거하고, 단원 완료 지도에 짧은 기념 안내만 둔다. 클래스 소개는 하단의 접힌 상세로 낮추며 작업실 내부 기능은 유지한다. 아래의 수집 목표 관련 기록은 변경 이력이고, 문서 마지막 ‘학습을 먼저, 작업실은 학습의 흔적으로’ 절이 이를 대체한다.

홈 미리보기 후속: 홈 작업실 카드도 `WorkbookRoomScene` 공통 렌더러로 실제 저장 배치(테마·풍경·수집품)와 현재 카피바라 행동을 보여준다. 저장 상태·현재 행동은 `WorkbookSpaceLauncher`, 편집 초안은 `WorkbookSocketRoom`이 소유한다. 저장하지 않은 배치는 큰 화면에만 보이며 취소하면 마지막 저장 배치로 돌아간다. PC·모바일 시각 검수와 관련 E2E 14개 통과. 영상 제작이나 서버·브라우저 영속 저장은 추가하지 않았다.

테마 확장 후속: 나무/도시 방 2종과 낮의 바다/정원 풍경, 라디오·돌 위 작은 나무를 추가했다. 테마마다 배치와 풍경을 독립 보존하고 저장/취소한다. 호환되지 않는 물품은 안내와 함께 선택을 제한한다. 리소스 등록·제작·검수는 [관리 규격](../design-references/workbook-room/resource-management.md)을 따른다. 현재 벽·바닥·가구는 테마 묶음이며 임의 개별 조합 기능은 아니다.

접촉 보정 후속: 작업 자리와 독서 자리는 가구·캐릭터·도구를 함께 그린 세트로 교체한다. 독립 캐릭터를 의자 위에 덧씌우지 않는다. 작업/빈 의자 × 도구 3상태, 독서/빈 의자 × 쿠션 2상태로 제한하며 기존 소품 선택 UI를 유지한다. [제작·구현 기록](../design-references/workbook-room/contact-sets.md).

2026-10-17 사용자 승인으로 `/workbook`의 작은 작업실 진입 카드에서 선택 캐릭터(둥근 선글라스·검은 넥타이)를 사용하는 고정 자리 시안이 기본으로 열린다. 책상 도구·책상 한쪽·벽·바닥 한쪽·휴식 공간 5자리와 체험 소품 7개, 작업·독서·쉬기 3개의 독립 정지 장면이다. 고르기 → 즉시 미리보기 → 저장/취소, 비워두기를 지원한다. 저장은 방문 메모리이며 회원·보상과 연결하지 않는다. 모바일은 가림 문제를 피하려고 방과 수집함이 함께 스크롤되고 ‘방 보기’로 돌아온다. 이전 자유 배치와 초기 구조 실험은 별도 비교 탭에 남겼다. 아래 획득 정책과 이전 자리 구성은 기획 이력이며 최신 시안의 실제 지급 기능을 뜻하지 않는다. 자산·프롬프트는 [고정 자리 제작 기록](../design-references/workbook-room/slots.md).

2026-10-17. 사용자 요청으로 기존 웹 클래스 기준의 수집품·전시·꾸미기와 홈 콘텐츠를 병렬로 구체화했다. 이 문서는 제안이며 실제 보상 지급·계정·저장·새 클래스 정책을 확정하지 않는다. 비교 화면은 `/demo/workbook-home-next`다. 현재 `/workbook`과 수업 진도는 변경하지 않는다.

## 수집함과 전시

수집 소유권과 배치를 분리한다. 하나의 물건은 한 자리에만 놓으며 다른 책상 자리로 옮기면 기존 자리는 비운다. 전시를 해제해도 소유권·연결 기록은 사라지지 않는다. 수집함은 전시 중/보관 중/미획득을 구분하고, 미획득 물건에서도 조건을 확인할 수 있다. 시안의 획득 상태는 고정 예시이며 실제 완료에서 계산하지 않는다.

자리는 책상 왼쪽·오른쪽, 벽, 작은 선반, 작업 전시대의 다섯 곳이다. 작업 전시대는 최종 모니터 자산을 제작하기 전의 임시 액자 표현이다. 처음부터 자유 좌표·회전·크기 조절을 제공하지 않는다. 꾸미기 → 자리 선택 → 호환 수집품 선택 → 미리보기 → 저장/취소. 빈 자리로 두기도 가능하다. 모바일에서는 자리 선택 버튼을 장면 바깥에도 제공해 작은 그림만 눌러야 하는 부담을 줄였다.

## 클래스 세계와 홈의 연결

클래스 안 픽셀 지도에서 받는 물건과 홈 작업실 물건에 같은 식별자·이름·표지 문양·색을 사용한다. 장소 명칭은 현재 지도 이름을 따르며 새로운 세계관 장소를 임의로 추가하지 않는다. 홈은 실사/시네마틱, 클래스는 픽셀 표현을 유지한다. 같은 카피바라의 귀환 공간이며 별도 펫을 추가로 키우는 구조를 요구하지 않는다.

시안에는 기존 작업실·책·머그 이미지와 코드로 만든 단순 소품을 재사용했다. 배경에 이미 그려진 책·램프 등은 고정 미술이며 소유한 수집품이 아니다. 레이어를 분리한 정식 공간, 픽셀 대응 소품, 카피바라 상호작용·액세서리는 후속 미술 작업이다. 현재 화면이 그 모든 자산과 육성 기능을 구현했다는 뜻은 아니다.

## 운영 구현 경계

향후 소품 정의, 회원별 획득 기록, 회원별 자리 배치, 실제 콘텐츠 기록의 참조를 분리한다. 연결 기록의 권한은 원래 콘텐츠 권한을 따르고, 배치만으로 유료 내용을 노출하지 않는다. 이번에는 DB·인증·브라우저 영속 저장·실제 보상 지급을 구현하지 않는다. 활동 캘린더는 기존 확정 정책을 유지하며 이 시안에서는 중복 목업을 추가하지 않았다. 통합 시 캘린더는 날짜, 공간은 남긴 물건을 보여주는 보조 영역으로 묶는다.

## 시안 확인

작업 공간 / 수집함 / 단원별 수집품을 전환할 수 있다. 수집품 설명과 예시 연결 기록, 미획득 조건, 호환 자리, 자리 간 이동, 전시 해제, 배치 저장·취소를 시험한다. 새로고침하면 초기화한다. 획득 시각은 실제 기록이 없으므로 꾸며 표시하지 않는다. 정식 수집함에서는 실제 획득일을 제공한다.

## 2026-10-17 후속 수정 · 콘텐츠 우선 홈과 상세 공간 분리

사용자는 현재 워크북 홈의 클래스·실험·글·기록·캘린더 구성을 유지하고 추가만 하는 방향을 선택했다. 대형 작업 공간 및 제작기·상황별 글로 홈을 교체했던 비교안은 홈 적용안에서 제외한다. `/workbook`에는 우측 보조 영역의 작은 작업실 카드만 추가하고 누르면 큰 모달에서 작업 공간·수집함·꾸미기를 연다. 모바일에서는 기존 콘텐츠 뒤의 보조 영역에 진입 카드가 나온다. `/demo/workbook-home-next`도 동일한 기존 홈을 재사용한다. 기존 히어로 이미지·카드·글 목록을 대체하지 않는다.

### 썸원 참고와 배치 재설계

공식 FAQ(2026-10-17 확인): https://sumone.co/faq/ 및 https://sumone.co/faq-en/ . 테마별 오브제와 구매/소유, 인테리어 영역 선택·배치 흐름을 참고한다. 공식 한국어 FAQ의 ‘원하는 위치에 오브제를 배치하고 싶어요’에는 오브제별 지정 위치만 지원한다고 명시되어 있다. 따라서 자유 좌표·미세 조정은 썸원의 확인된 기능이 아니라 우리 사용자의 별도 요구로 설계한다. 실제 앱의 제스처와 최신 화면을 직접 실행해 검증한 것은 아니다. 포인트 경제·광고·구매 조건을 우리 정책으로 그대로 가져오지 않는다.

사용자는 현재의 고정 다섯 자리보다 세밀한 배치를 원한다. 기존 자리는 상호작용 검증용 임시 도구이며 최종 배치 체계가 아니다. 다음 배치 설계에서는 소유 수집품과 배치 인스턴스를 나누고, 바닥/벽/책상 면의 배치 가능 범위, 면 안의 위치, 발밑 기준점, 앞뒤 겹침, 방향·회전 허용 범위를 소품별로 정한다. 드래그 및 터치 이동과 키보드/버튼 미세 이동을 함께 제공하는 안을 검토한다. 소품마다 그림 속 크기를 통일하고 접지·원근·가림이 맞아야 한다. 사진 배경 위에 정면 소품을 얹는 현 시안의 시각적 한계를 먼저 해결해야 하므로 이 단계에서 임의 자유 드래그를 최종처럼 구현하지 않는다.

정식 미술은 카피바라·벽·바닥·책상·가구를 레이어로 분리하고, 수집품의 시점과 스케일을 통일한다. 선택한 물건의 위치 조정, 겹침 조정, 제자리/보관, 배치 전후 비교, 저장·취소를 큰 작업실 화면에서 제공하는 방향이다. 실제 획득·포인트·회원 저장은 기존 보류 상태를 유지한다.

## 통합 공간 원화 01 — 2026-10-17

사용자 요청으로 사진 합성 시안과 구별되는 통합 원화를 만들었다. 고정된 높은 3/4 시점과 따뜻한 손그림 미술로 책상 작업/창가 휴식/선반 수집의 세 영역을 구성했다. 카피바라는 책상과 의자에 맞춘 크기로 노트북 앞에 앉아 있다. 원화는 큰 작업실의 기본 화면이며 ‘그림 크게 보기’로 작은 화면에서도 디테일을 볼 수 있다. 기존 수집함과 고정 자리 실험은 ‘수집·배치 구조’ 탭에 남겨 새 미술의 실시간 배치와 혼동하지 않게 한다. 홈의 콘텐츠 구성과 작은 진입 방식은 유지한다. 생성 프롬프트·자산 경로·후속 레이어 제작 기준은 `docs/design-references/workbook-room/README.md`에 기록했다.

## 레이어 조작 시안 — 2026-10-17

사용자가 같은 시점·분위기의 레이어 분리와 실제 소품 이동, 독립 카피바라 액션을 요청했다. `WorkbookLayeredRoom`에서 방 배경/고정 가구 묶음/카피바라/개별 소품을 실제 별도 PNG 레이어로 합성한다. 수집함에는 새 화풍의 기획 노트·머그·스탠드 3개를 예시 지급했다. 기존 7개 보상 기획 전체의 최종 미술 완성을 뜻하지 않는다.

- 소품별 x·y·너비는 방 좌표의 백분율로 유지한다. pointer capture로 마우스/터치 드래그, 방향키와 Shift 미세 이동, 버튼 이동을 지원한다.
- 크기·방향·앞뒤 순서·보관/전시를 조정하고 미리보기→저장/취소한다. 전시를 해제해도 수집함에는 남는다. 저장은 모달을 닫아도 이번 마운트 동안 유지되며 새로고침·페이지 이탈 시 초기화한다.
- 작업하기/책 읽기/낮잠 자기는 각자 다른 투명 캐릭터 원화와 고정 접지 위치를 사용한다. 자동 재생·동작 간 연결 애니메이션이 아니다. 가구 숨기기로 방/가구 분리를 확인할 수 있다.
- 가구는 현재 하나의 고정 레이어이며 개별 가구 이동·충돌·책상 면 스냅·실시간 물리·조명 재계산은 구현하지 않았다. 소품이 자연스럽게 놓이도록 사용자가 크기와 위치를 조정하는 배치 시안이다.
- 기존 홈 콘텐츠와 작은 진입은 유지한다. 큰 작업실 기본 탭은 실제 조작 시안, 원화는 비교 탭, 이전 고정 자리 실험도 별도로 유지한다. 실제 계정·진도·포인트·지급 연동은 추가하지 않는다.

자산 목록과 내장 image_gen 생성 프롬프트는 `docs/design-references/workbook-room/layers.md`에 있다.

## 2026-10-17 · 첫 수집품과 브라우저 보존 구현

- 기본 제공 8종과 활동 수집품 ‘첫 노트북’을 분리했다. 최초 배치는 아이디어 노트다.
- 웹 클래스의 컴퓨터 모드에서 ‘내 홈페이지 기획하고 만들기’를 완료하면 도착 안내가 뜬다. 예시 복습은 제외한다. 수집함에서 받기 → 노트북 선택 → 배치 저장으로 연결한다. 받기만 하면 기존 배치를 바꾸지 않는다.
- 테마별 배치·창 풍경·현재 행동·노트북 획득 가능/보유 상태는 `motivo.workbook.room.v1`로 브라우저에 저장한다. 이후 기획을 고쳐도 기념 수집품은 남는다. 클래스 진도 자체는 저장하지 않는다.
- Zod와 자리별·테마별 호환 검증으로 손상되거나 알려지지 않은 저장은 기본 상태로 복구한다. 저장 공간을 사용할 수 없으면 현재 방문 동안만 유지한다고 안내한다.
- 회원 계정·기기 동기화·서버 보상 검증은 포함하지 않는다. 브라우저 데이터는 사용자가 바꿀 수 있으므로 운영 보상의 근거로 사용하지 않는다.
- PNG 원본과 크롭 WebP 산출물을 분리했다. 좌표 복원으로 홈과 편집 화면이 같은 배치를 렌더링한다. export 절차는 [리소스 관리](../design-references/workbook-room/resource-management.md)를 따른다.

검증: PC·모바일 작업실 회귀 10개 통과, 최종 안내 영역 수정 후 수령·복원 4개 재통과. PC의 포트폴리오 목적 전체 클래스 여정에서 컴퓨터 제작 완료 → 첫 노트북 도착 안내를 확인했다. 시각 검수는 1440×1000과 390×844에서 크롭 정렬·수집함·고정 저장 도구를 확인했다. 자체 리뷰에서 도착 안내가 지도 조작을 가리는 문제를 발견해 고정 오버레이를 제거하고 본문 흐름에 배치했다.

## 2026-10-17 · 다른 단원으로 연결 확장

현재 정책은 이 절을 따른다. 새로 시작하는 작업실에는 기본 5종과 활동 수집품 4종이 있다.

| 단원             | 수집품            | 완료 활동과 의미                                                                                                 |
| ---------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| 기획과 첫 제작   | 첫 노트북         | 컴퓨터에서 첫 홈페이지 제작을 완료한 본인 기록. 예시 복습 제외.                                                  |
| 화면과 사용 경험 | 초록 잎 포스터    | 관찰·개선 요청·PC/모바일 전후 비교 완료. 화면 구성과 여백을 벽에 남기는 기념품.                                  |
| 동작과 데이터    | 작은 라디오       | 입력/버튼 반응·저장 전후·다른 기기/서버 판단 완료. 조작과 반응을 기억하는 기념품.                                |
| 공개와 운영      | 돌 위의 작은 나무 | 공개 전 점검·주소 확인·문제 기록과 수정 전후 확인 완료. 공개 후에도 돌보는 일의 기념품. 나무 테마 바닥에만 배치. |

뒤의 세 단원은 수업의 예시·시뮬레이션 완료도 포함한다. 실제 제작·외부 배포를 인증하지 않는다. UI에서 이 차이를 설명한다. AI 입문에는 별도 잠금 물품을 추가하지 않고 기본 물품으로 시작한다.

- 정의는 `src/lib/workbook-room-rewards.ts` 한 곳에서 관리한다. 단원 완료 상태를 연결하되 별도의 유사 완료 판정이나 학습 체크를 추가하지 않는다.
- 해당 자리의 수집품 설명에서 완료할 활동·물건의 의미·상태를 읽고, 완료 후 받기→물건 선택→배치 저장 순서로 진행한다.
- 기본 5종: 아이디어 노트, 쉬어가는 머그, 해 질 녘 액자, 작은 고무나무, 오렌지 쿠션.
- 이전 v1 저장의 추가 목록이 없으면 기존 기본 지급품 3종을 보유 처리한다. 기존 배치를 없애지 않는다. 새 상태는 빈 목록을 명시해 구별한다.
- `available`과 `owned`는 추가 수집품의 도착/수령 목록이다. 기존 노트북 필드와 저장 키는 호환을 위해 유지한다. 획득 후 단원 기록을 바꿔도 물건은 남는다. 서버·회원 보상 체계로 확대하지 않는다.

확인: `pnpm check`의 61개 순수 로직/기존 검사, PC·모바일 작업실 E2E 14개, 포트폴리오 목적의 전체 클래스 흐름 PC·모바일 2개를 통과했다. 단원 학습 기록을 변경한 이후에도 세 수집품의 도착 상태가 남는 것을 검사했다. 수업 자체의 데이터 비저장 검사는 승인된 작업실 저장 키만 제외하고 유지한다. 실제 화면은 1440×1000/390×844에서 수집 조건·잠금 상태·링크 분리·기존 배치 조화를 확인했다. 자체 리뷰에서 새 저장 필드의 이전 v1 호환과 중복 수령 방지·수령 전 배치 차단을 검토했다.

## 2026-10-17 · 홈 수집품 바로가기

홈의 작은 작업실 카드에 아직 받지 않은 도착 물품의 개수와 이름별 받기 버튼을 표시한다. 새 조건을 만들지 않고 기존 획득 가능·보유 상태로 계산한다. 받을 물품이 없으면 이 영역을 숨긴다.

물건을 누르면 현재 작업실 꾸미기로 전환하고 해당 자리(책상 도구·벽·책상 한쪽·바닥 한쪽)를 선택해 획득 안내 영역으로 스크롤·키보드 포커스를 옮긴다. 물건을 받거나 배치하는 조작은 자동 실행하지 않는다. 수령 후 홈 개수와 버튼은 즉시 갱신된다. 모달을 닫으면 눌렀던 버튼으로 복귀하고, 수령해서 버튼이 사라졌으면 작업실 기본 버튼으로 복귀한다. 기존 미저장 배치와 테마는 유지한다.

검증: PC·모바일 18개 E2E에서 미도착 숨김, 네 물품 각각의 자리·수령 안내 바로 열기, 다른 시안에서 복귀, 키보드 진입·닫기 포커스 복귀, 수령 후 표시 제거와 새로고침 보존, 기존 배치 저장을 확인했다. 실제 브라우저의 기본 카드·모달 복귀를 PC/모바일에서 확인하고, 도착 4개 테스트 상태의 두 화면 크기 캡처에서 표시와 수령 버튼의 위치를 검수했다. 자체 리뷰에서 중첩 버튼을 피하고, 수령으로 진입 버튼이 제거됐을 때의 포커스 복귀와 이미 도착한 물건의 상태 문구를 보정했다.

## 2026-10-17 · 수령 확인에서 바로 놓기

수집함에서 받기를 누르면 보유 상태를 저장한 뒤 해당 물건을 크게 보여주는 수령 확인 화면을 연다. 기존 투명 소품 원본의 서비스 산출물을 재사용한다. 단원과 물건의 의미를 보여주며 ‘작업실에 놓기’와 ‘수집함에 보관’을 선택할 수 있다.

- 놓기: 해당 자리의 초안을 교체하고 방 미리보기로 스크롤·포커스를 옮긴다. 기존 물건은 수집함에 남고 저장은 별도다. 변경 취소를 해도 수령한 물건은 회수하지 않는다.
- 전용 테마: 작은 나무를 도시 작업실에서 받으면 나무 작업실로 전환한다고 미리 알린다. 놓기를 눌렀을 때 전환하고 나무 테마 초안에 놓는다. 도시 테마의 배치·풍경은 보존한다.
- 보관/Escape: 수령 화면만 닫고 해당 수집 안내로 포커스를 돌린다. 배치는 바꾸지 않는다. 바깥 작업실 모달은 계속 열린다.
- native dialog를 사용해 수령 확인 중 포커스를 가두고 배경 작업실의 조작을 막는다. 수집품 획득 조건·브라우저 저장 범위는 변경하지 않는다.

검증: PC·모바일 기능 E2E 24개가 통과했다. 수령 후 바로 놓기·저장 전 취소와 재배치·저장 복원, 보관과 Escape의 부모 모달 유지, 전용 테마 전환 및 다른 테마 보존을 포함한다. 자체 리뷰에서 수령 저장과 배치 초안을 분리하고 native dialog의 닫기/포커스 복귀를 검토했다. 사용자 승인 후 PC·모바일 실제 렌더링 캡처를 검수하고 수령 화면의 안쪽 여백과 한글 줄바꿈을 보정했다.

## 2026-10-17 · 놓은 위치 안내

수령 화면에서 바로 놓기를 누르면 방으로 돌아와 해당 물품 둘레와 ‘물건 이름 · 여기 놓았어요’를 약 3.5초 표시한다. 실제 소품의 원본 경계·배치 좌표로 강조 영역을 계산하며 물품 자체를 덮지 않는다. 방 오른쪽의 물건은 이름표를 오른쪽 끝에 맞춰 모바일에서도 잘리지 않게 한다. 표시 끝의 불투명도 전환은 약 120ms이고 모션 줄이기에서는 정적으로 유지 후 제거한다.

강조는 임시 편집 상태이며 홈 이미지·보유·배치 저장에 포함하지 않는다. 표시가 끝나도 놓은 물건은 남고, 배치 취소·물건 교체·테마 변경 시 즉시 강조를 해제한다. 연속으로 다른 수집품을 놓으면 새 물건의 표시와 타이머로 교체한다. 스크린리더에는 기존 배치 상태 안내로 물건 이름·자리를 전달하고 시각 이름표는 중복 읽지 않는다.

PC·모바일에서 네 수집품의 위치 표시, 자동 종료, 배치 취소, 모션 줄이기 및 기존 수령·보관·저장 흐름을 검사한다. 시각 검수에서 노트북의 접촉 세트와 독립 포스터/나무의 테두리 정렬, 모바일 이름표의 화면 경계를 확인했다.

### 보유 물품을 다시 놓을 때

수집함의 보유 물품 선택도 새 수령품과 같은 위치 강조와 방 미리보기 이동을 사용한다. 기본 제공 물품도 포함한다. 같은 물건을 다시 누르면 3.5초 타이머와 시각 효과를 새로 시작한다. 빈 자리 선택·변경 취소·테마 변경은 강조를 해제한다. 배치 저장 정책은 그대로이며 이미 놓인 물건을 다시 확인하는 조작만으로 새 저장 변경을 만들지 않는다.

보유품 확장 검증: PC·모바일 E2E 28개 통과. 가상 시계로 같은 물품 재선택 후 3.5초가 새로 유지되고 종료되는지 확인했고, 비워두기·변경 취소 시 해제도 검증했다. 실제 브라우저 1440×1000/390×844에서 기본 보유품 노트를 선택해 방으로 이동하고 강조가 표시되는 것을 확인했다. 자체 리뷰에서 타이머와 CSS 표시가 함께 다시 시작하도록 선택 순번을 두었고, 홈·저장 상태와 임시 표시가 섞이지 않는 것을 검토했다.

## 2026-10-17 · 방의 물건을 눌러 확인

현재 방 배치에 있는 물품 위에 클릭/키보드 영역을 제공한다. 물품의 기존 배치 경계를 재사용하고 터치 영역은 최소 44px로 확보한다. 물건을 누르면 해당 자리의 수집함으로 이동해 획득 안내에 포커스를 둔다. 활동 물품은 기존 단원·완료 활동·물건의 의미를 보여주고, 노트·머그·액자·고무나무·쿠션은 ‘기본 제공 물품’과 별도 활동이 필요 없다는 안내를 보여준다. 이미 놓인 물건의 수집함 버튼은 배치 중 상태를 유지한다.

## 2026-10-18 · 학습 중 작은 수집 목표

지도·수업·학습 기록에서 목표 물건 이름, 목표 단원의 확인 수, 지금 해야 할 기본 활동을 작은 두 줄 안내로 표시한다. 클릭하면 기존 선행 학습 판정을 재사용해 첫 미완료 수업으로 이동하며 같은 수업에서도 제목으로 포커스를 돌려준다. 입력 내용과 수업 내부 단계는 초기화하지 않는다. 진행 수는 선행 과정 전체가 아닌 목표 단원의 수임을 ‘목표 단원’으로 명시했다.

`/demo/workbook-completion`에 독립된 테스트 페이지를 둔다. 기획·첫 제작 / 화면·사용 경험을 선택해 같은 완료 요약과 확대·비교·첨부 컴포넌트를 바로 연다. 샘플 기록임을 명시하고 실제 제작 성과로 표현하지 않는다. `WorkbookProgressPreviewProvider`는 학습 Context만 만들고 작업실 Provider를 사용하지 않으므로 수집품 해금이나 저장을 발생시키지 않는다. 단원 전환에는 첨부를 유지하며 ‘첨부한 화면 초기화’·새로고침으로 다시 시작한다. 검색 색인은 제외하고 본편 메뉴에는 테스트 진입을 추가하지 않는다.

검증: 테스트 페이지와 본편 전체 학습 여정의 PC·모바일 E2E 4개가 통과했다. 실제 화면에서 단원 전환, 확대창, 모바일 첨부 조작, 버튼과 안내의 가독성을 확인했다. 테스트 중 작업실 브라우저 저장 값이 변경되지 않는 것도 확인했다. `pnpm check` 통과. 자체 검토에서 기본 학습 Provider의 빈 초기값을 유지하고, 미리보기 전용 기록과 작업실 해금 경로가 분리되어 있음을 확인했다.

### 2026-10-18 · 크게 읽는 결과 화면과 테스트 진입

기존 3열 중 한 칸·132px 높이에 머물던 결과 미리보기를 주 영역으로 확장했다. PC에서는 큰 페이지/전후 화면과 오른쪽 학습 설명·기록으로 나누고, 모바일의 전후 예시는 크게 세로로 읽는다. 첨부 이미지의 종횡비는 보존한다. 본편도 완료한 기획·화면 비교 단원에 한해 요약 높이 제한을 풀고 지도를 아래로 이어 읽는다. 미완료 지도와 학습 조건·기록은 변경하지 않는다.

검증: 완료 테스트·본편 전체 학습 여정 4개, GNB 임시 목록·기존 홈 이동 8개의 PC·모바일 E2E가 통과했다. 320px/390px 모바일과 PC 실제 화면에서 큰 미리보기·메뉴 폭·목록 조작을 확인했다. `pnpm check` 통과(61개 단위 테스트). 자체 검토에서 정식 메뉴 정의와 개발용 목록이 분리되고, production의 임시 버튼 숨김과 기존 학습·수집 기록이 유지됨을 확인했다.

### 완료 예시의 변경 지점 · 테스트 메뉴 정리 (2026-10-18)

- 모바일 수정 전의 잘리는 경계는 점선, 수정 후 화면에 맞춘 경계는 실선으로 표시한다. 고정 560px에서 화면 너비에 맞춘 변경과 읽기 개선을 짧게 설명한다.
- 완료 요약과 확대 화면에 같은 표시를 사용한다. PC 예시에서는 경계 강조를 빼고 두 화면 모두 560px인 이유를 안내한다. 실제 첨부 화면의 자동 차이 분석은 제공하지 않는다.
- 개발용 GNB에는 현재 진행 중인 단원 완료·결과물 미리보기만 남긴다. 완료된 시안 링크는 제거하되 페이지는 보존한다.

### 직접 첨부 화면의 개선 기록 (2026-10-18)

수정 전후 각각 한 영역을 마우스·손가락으로 표시하고 개선 설명을 240자까지 작성한다. 완료 요약에도 이미지 위 표시와 설명을 함께 보여준다. 키보드로는 가운데 영역 추가 후 방향키로 이동하고 Shift+방향키로 크기를 조절한다. 사진 교체·삭제는 해당 표시를 지우되 작성한 설명은 유지한다. 상태는 기존 첨부처럼 방문 중에만 유지하며 학습 기록·수집품 상태와 분리한다.

### 여러 변경 영역과 개별 설명 (2026-10-18)

이전 단일 영역·공통 설명을 화면별 여러 영역·개별 설명으로 확장했다. 각 화면의 추가 순서대로 번호를 붙여 완료 요약의 설명 목록과 연결한다. 영역 삭제 시 남은 영역 번호만 다시 정리하며 설명은 해당 영역에 유지한다. 사진 교체·삭제는 그 사진의 영역과 설명을 함께 지운다. 상태는 방문 중 메모리만 사용한다.

### 영역 번호와 설명의 왕복 이동 (2026-10-18)

첨부 편집 화면에서 번호는 해당 설명 입력칸으로 이동하고 포커스를 준다. 설명 위의 ‘영역 화면에서 보기’는 영역으로 돌아가 1.8초 동안 테두리·옅은 면을 강조한다. 완료 요약에서도 번호는 설명으로, 설명 버튼은 영역으로 연결된다. 강조 타이머는 새 선택으로 갱신하며 컴포넌트 해제 시 정리한다. 이동은 즉시 수행하며 설명 입력 중에는 화면으로 강제 이동하지 않는다.

### 변경 영역 직접 이동·크기 조절 (2026-10-18)

첨부 편집 화면에서 영역 내부 드래그는 이동, 네 모서리 손잡이는 크기 조절로 작동한다. Pointer Events와 포인터 캡처를 사용해 마우스·터치에 같은 비율 좌표를 적용한다. 이미지 바깥 이동과 역전된 사각형을 막고 포인터 취소 시 원래 좌표를 복구한다. 영역 id와 설명은 그대로 유지하며 요약에는 수정된 배치만 반영한다. 번호 클릭의 설명 이동과 기존 키보드 조절을 유지한다.

### 영역 편집 실행 취소·다시 실행 (2026-10-18)

방문 상태에 수정 전후 영역 편집 기록을 함께 보관한다. 포인터 드래그 시작부터 종료까지 한 단계, 설명 입력 포커스부터 벗어날 때까지 한 단계로 기록하며 변경이 없는 동작은 기록하지 않는다. 영역 삭제·모든 표시 지우기도 설명을 포함해 복원한다. 최대 100단계이며 사진 교체·삭제는 기록 경계다. 취소된 포인터는 원래 상태로 돌아가고 기존 다시 실행 기록을 보존한다. 완료 요약은 복원된 상태를 그대로 표시한다.

### 영역 편집 키보드 단축키 (2026-10-18)

직접 첨부한 전후 화면을 편집할 때 Ctrl+Z/Cmd+Z와 Shift 조합을 각각 실행 취소/다시 실행으로 연결했다. 설명 입력칸·input·select·contenteditable·textbox와 IME 조합에서는 기본 동작을 유지한다. 예시 화면이나 닫힌 편집창에서는 단축키를 가로채지 않는다. 버튼에 aria-keyshortcuts와 짧은 안내를 제공한다.

### 실행 취소·다시 실행 고정 (2026-10-18)

영역 편집 기록 버튼을 팝업의 sticky 헤더에 통합했다. PC는 제목·기록 버튼·닫기를 한 줄로, 작은 화면은 제목/닫기 아래 기록 버튼 한 줄로 표시한다. 긴 단축키·초기화 안내는 본문에 남겨 고정 영역을 줄인다. 헤더 z-index를 영역과 크기 손잡이보다 높게 유지한다.

### 첨부 결과 브라우저 임시 저장 (2026-10-18)

이미지·영역·설명을 IndexedDB의 버전 1 형식으로 자동 저장한다. 실제 클래스 `vibe-web`과 테스트 `demo:vibe-web`은 별도로 관리한다. 복원 완료 전 빈 상태를 저장하지 않으며 스키마로 이미지 형식과 좌표를 확인한다. 이미지가 바뀌지 않은 편집은 영역 메타데이터만 기록한다. 저장은 순서대로 처리하고 transaction 완료 후에만 완료 상태를 표시한다. 용량·권한 실패 시 마지막 저장본을 유지하고 재시도 버튼을 제공한다. 복원 실패 또는 다른 탭의 revision 충돌은 덮어쓰기를 중지한다.

실행 취소 기록·학습 진도·수집품 상태는 이 임시 저장에 포함하지 않는다. 테스트 초기화는 빈 첨부·영역 상태를 저장해 다음 방문에도 초기화 상태를 유지한다. 브라우저 데이터 삭제 시 소실되며 서버 업로드·기기 간 동기화는 제공하지 않는다. 이전의 첨부 방문 메모리 한정을 대체한다.
