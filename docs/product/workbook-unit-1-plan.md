# 1단원 기획 — AI 도구 준비하기

2026-10-31 · 사용자와 논의해 정한 1단원 구성. 이 사용자는 1단원까지 기획하고, 2단원 이후는 다른 작업자가 이어서 맡는다. 화면 단위 원고는 수업별로 이어서 정한다. 현재 코드의 1단원(5수업)은 이 기획이 확정된 뒤 바꾼다.

## 원칙

- **갑자기 묻지 않는다.** 무엇을 왜 하는지 먼저 말하고, 시범을 보인 다음, "해볼까요?"로 초대한다. 정답이 없는 활동은 그렇다고 밝힌다.
- **말투는 인트로와 같게.** "~해요"체, 한 화면에 생각 하나, 설명은 세 문장 안팎, 용어는 처음 나올 때 한 번 굵게. 반전·여운형 문장은 쓰지 않는다.
- **실제 실행처럼 속이지 않되, 쓸모없는 안내는 붙이지 않는다.** 실제 AI를 부르지 않는 화면을 실제 실행이라고 말하지 않는다. 다만 "미리 만든 예시 장면이에요" 같은 문구는 수강자에게 쓸모없어 붙이지 않는다(2026-10-31 사용자 판단). 실제 결과로 오해할 수 있는 곳에서만 구분한다.
- **시간이 지나면 바뀌는 내용**(서비스 이름, 에이전트 근황, 요금제)은 화면에 "○○년 ○월 기준"을 표시하고, 직접 확인한 범위만 말한다. "유료 플랜이 필요하다"는 실제 실습으로 확인한 만큼만 쓴다.
- **공통 틀:** 강의 시작 표지 → 종이 카드 본문 → 하단 바(← 이전 · 점 · 다음 →). 오른쪽 패널은 없다.

## 단원을 꿰는 비유: AI 조수

| 수업 | 개념                        | 비유                                                                          |
| ---- | --------------------------- | ----------------------------------------------------------------------------- |
| 1-1  | AI(LLM)                     | 말로 일하는 조수. 많이 읽어 빠르고 아는 게 많지만, 가끔 모르는 걸 아는 척한다 |
| 1-2  | 코드 에이전트               | 손이 생긴 조수. 직접 파일을 열고 고친다                                       |
| 1-3  | 토큰·컨텍스트·요금제        | 조수가 한 번에 볼 수 있는 책상 크기, 일할 수 있는 양                          |
| 1-4  | 프로젝트 폴더·로컬/클라우드 | 조수에게 내준 작업 책상 / 내 책상과 다른 건물의 작업실                        |
| 1-5  | 프롬프트                    | 조수에게 건네는 작업 메모                                                     |

1-1에서 "AI는 사람이 아니라 프로그램이에요. 이해하기 쉽게 조수에 빗댄 거예요"를 한 번 분명히 한다.

**카피바라(시도):** 수업 본문에서 카피바라를 조수가 아니라 **조수에게 일을 맡기는 쪽(학습자 쪽)**으로 등장시켜 본다. 1-1 시안에서 확인 후 유지 여부를 정한다.

### 1-1 첫 화면 (확정)

예전 AI("이 사진은 고양이예요" — 고르는 AI)와 요즘 AI("고양이 그림을 그려줘" — 만드는 AI)를 나란히 보여준다. 문제로 시작하지 않는다.

#### 1-1 화면 1 콜라주 시안 (2026-10-31)

실제 1-1의 첫 화면(이전 "AI = 인공지능" 메모→소개문)을 시안으로 교체했다(`WorkbookAiEraCollage.tsx`). 나머지 화면은 아직 이전 내용이다.

- 그레인 있는 어두운 판 위에 종이 카드 두 장이 툭 붙는다: "판단하는 AI"(흑백 고양이 사진 → "고양이예요", 판단해서 답해요) → "만드는 AI"(말풍선 "창가에서 낮잠 자는 고양이를 그려줘" → 그림, 새로 만들어요). 고양이 사진·그림은 SVG로 직접 그린 종이 조각이다.
- 카피바라는 흰 테두리 스티커처럼 판 아래에 서서, 첫 카드 뒤엔 갸웃 + 물음표, 두 번째 카드 뒤엔 손을 들고 전구가 켜진다. 약 3.6초, "다시 보기" 제공, 모션 줄이기에서는 완성 장면.
- 손글씨 라벨은 Google Fonts의 Nanum Pen Script(`next/font`)를 시안용으로 썼다. 폰트 추가 여부는 확정 전이다.
- 카피바라 컷은 확정 캐릭터 시트(`docs/design-references/workbook-character-v4/selected-character-sheet.png`, 밝은 갈색 털)의 뒷모습과 3/4 모습을 잘라 배경을 지웠다(`public/images/workbook/lesson-1-1/capy-back.png`, `capy-turn.png`). 첫 카드엔 뒷모습으로 고개를 갸웃(살짝 기울임) + 물음표, 두 번째 카드엔 3/4로 돌아보며 전구. 처음 쓴 주황 톤 컷은 인트로 픽셀 시안용 시트에서 잘라 색이 확정 캐릭터와 달라 교체했다(사용자 지적). 엄지·땀방울 같은 표정은 시트에 없어 필요하면 새로 그려야 한다.
- 콜라주 색은 시안이라 파일 안에 직접 적었다. 확정되면 토큰으로 옮긴다.
- 종이 질감 보강(사용자 레퍼런스 반영):
  - 카드·라벨·색 종이는 가위로 자른 듯 울퉁불퉁한 가장자리를 쓴다. 고정 시드 `clip-path`라 매번 같은 모양이다.
  - 카피바라와 생각 스티커에는 두껍고 살짝 거친 흰 테두리를 붙인다(SVG 필터, `feMorphology` + `feDisplacementMap`). 뒤에는 골판지색 종이를 댄다.
  - "예전 AI" 사진은 신문처럼 흑백 망점이고, 뒤에 오렌지 색 종이 한 장을 깔았다. 이 화면의 오렌지는 이 한 곳뿐이다(사용자 선택 A: 브랜드 오렌지).
  - 말풍선은 굵은 검은 선을 흔들어 손그림처럼 보이게 했다.
  - 장면 전체에 종이 결을 얹었다.
- 화면 전체를 쓰는 배치(사용자 선택 B, 2026-10-31):
  - 장면이 읽기 폭(960px) 대신 수업 본문 영역 전체를 무대로 쓴다. 16:9 장면을 화면 높이와 너비 안에 맞추고, 최대 폭은 1280px이다. 장면 루트에 `data-wide-scene`을 붙이면 본문이 이 배치로 바뀐다(`WorkbookLesson.module.scss`).
  - PC 배치는 왼쪽 위 제목 띠 → 왼쪽 아래 "예전 AI" → 가운데 "요즘 AI" → 오른쪽 설명 쪽지 순서다. 카피바라는 두 카드 사이 아래에 선다.
  - 제목은 실제 `h2`다. 신문 헤드라인을 오린 것처럼 검정 띠와 종이 띠 두 줄로 붙였다.
  - 설명은 테이프로 붙인 깨끗한 종이 쪽지이고, 본문 글꼴을 쓴다. 장면 조각이 다 붙은 뒤 마지막으로 붙는다.
  - 모바일은 제목 띠 → 장면 → 설명 쪽지 순서로 쌓는다.
  - 이 배치는 모든 화면의 공통 틀이 아니다. 화면마다 줄글·연출 장면·표·비교·직접 조작 중 내용에 맞는 것을 고르고, 형식이 학습을 방해할 만큼 자주 바뀌지 않게 한다(사용자 원칙).
  - 제목은 대구형("예전 AI는 골랐고, 요즘 AI는 만들어요")이 AI 말투라 "AI가 하는 일이 달라졌어요"로 바꿨다. 판단하는 AI는 지금도 쓰이므로 "옛날 AI"로 읽히지 않게 카드 이름표를 "판단하는 AI / 만드는 AI"로 한다(2026-10-31).
  - "미리 만든 예시 장면이에요" 안내는 수강자에게 쓸모없어 뺐다. "다시 보기"만 남긴다.

### 1-2 종류 소개 범위 (간략)

글·대화, 이미지, 영상, 3D 모델링, 웹사이트를 만들어 주는 온라인 서비스(예: 노코드 빌더·디자인 도구의 사이트 제작 기능), 코드 에이전트. 서비스 이름은 발행 전에 실제 존재·기능을 확인하고 기준 날짜를 붙인다(사용자가 예로 든 Bubble, Figma Sites 포함 확인 필요). 각 종류는 한 줄 소개와 예시 화면 정도로 짧게 다루고, 수업의 중심은 코드 에이전트로 넘어간다.

### 1-3 화면 흐름 (확정)

1. AI가 읽고 쓰는 단위, **토큰** — 문장이 조각으로 나뉘는 모습. 서비스는 이 조각 수로 사용량을 센다.
2. 한 번에 볼 수 있는 범위, **컨텍스트** — 조수의 책상 크기. 대화가 길어지면 앞 내용을 놓칠 수 있는 이유.
3. 코드 에이전트는 더 많이 읽는다 — 파일을 읽고 고치느라 조각을 많이 쓰고 한도에 빨리 닿는다.
4. 그래서 요금제가 나뉜다 — 쓸 수 있는 양과 모델의 차이, 이 클래스 실습에 필요한 정도(기준 날짜 표시, 직접 확인한 범위).
5. 아껴 쓰는 습관 — 새 대화로 시작, 작업 쪼개기, 필요한 파일만 알려주기.
