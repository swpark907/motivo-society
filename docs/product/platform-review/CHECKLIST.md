# 검수 체크리스트

[LOOP.md](../platform-loop/LOOP.md) "사용성 체크리스트"를 검수용으로 펼친 것. 발견을 FINDINGS에 적을 때 **체크 ID**를 붙인다.
`[자동]`은 [audit-snippet.js](audit-snippet.js)가 숫자로 준다. 나머지는 스크린샷과 조작으로 본다.

근거 규칙: AGENTS.md "디자인"의 **플랫폼 제품 화면 예외**와 기준 시안 [L01b](../../design-references/platform/service-draft-l01b.md). 홈 `/` 비로그인의 시네마틱 히어로는 브랜드 화면이라 브랜드 규칙으로 본다.

## C · 창의적인 디자인과 모션 (과하지 않게)

규칙 안에서 고칠 수 있는 것은 고친다. **규칙을 넘는 아이디어**(120ms보다 긴 움직임, 위치·크기가 바뀌는 움직임, 새 일러스트·연출)는 만들지 않고 FINDINGS "디자인 제안"에 남겨 승우 결정을 받는다. 판단 기준은 AGENTS.md "디자인"과 "모션은 작게"다.

| ID  | 기준                                                                                                                                                                                                              | 보는 법                                 |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| C1  | **결과가 보인다:** 누른 결과(신청 확정 · 인증 · 가입 · 출석 · 저장)가 토스트만이 아니라 화면 상태로 바뀐다. 무엇이 바뀌었는지 한눈에 보인다.                                                                      | 누르기 전과 후 스크린샷 비교            |
| C2  | **성취의 순간 하나:** 확정 · 완주 · 첫 인증처럼 사람이 뭔가 해낸 화면에는 작은 시각적 순간이 하나 있다(큰 숫자 · 사진 · 카피바라 · 굵은 문장). 평범한 폼 결과처럼 보이지 않는다.                                  | 결과 화면들                             |
| C3  | **사람 냄새:** 빈 상태 · 처음 온 화면 · 확정 화면에 브랜드 자산(카피바라 일러스트 · 따뜻한 사진)이나 사람 말이 있다. 스톡 · 이모지 · 3D 오브젝트는 없다.                                                          | 빈 상태 · 처음 온 사람                  |
| C4  | **화면마다 같은 틀만 반복하지 않는다:** 모든 화면이 "제목 + 흰 카드 나열"이면 위계가 사라진다. 화면의 주인공(사진 · 날짜 · 큰 숫자 · 주 행동)이 하나 보인다. 시안(L01b) 수준과 비교.                              | 같은 묶음 화면을 나란히                 |
| C5  | **모션 규칙:** 색 · 불투명도 전환만, 120ms 이내. 바운스 · 패럴랙스 · 자동재생 · 레이아웃이 밀리는 움직임 없음. `prefers-reduced-motion`이면 전환을 끈다. 전환 중 글자가 사라지는 순간이 없다(글자색도 함께 전환). | `transition` 값 · 모션 줄이기 켜고 보기 |
| C6  | **과함 점검:** 한 화면에 움직이는 것은 하나 이하, 정보를 가리지 않는다. 매일 쓰는 화면(홈 · 내 일정 · 호스트)일수록 더 절제한다. 장식이 주 행동이나 숫자보다 먼저 눈에 띄면 과하다.                               | 첫 화면에서 눈이 먼저 가는 곳           |

## 여정 (끝까지 따라가기 — 화면 사이를 본다)

각 여정은 한 번에 끝까지 가며, 화면 **사이**에서 맥락이 이어지는지(같은 이름 · 같은 금액 · 돌아오는 자리)를 본다. 결과를 FINDINGS "여정" 절에.

| ID  | 여정                                                                                                                                                  | 사람              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| J1  | **DM 첫 진입:** 활동 주소 직진입 → "로그인하고 신청" → 메일 로그인 → 온보딩 → **같은 활동으로 돌아와** 신청 확인 → 결과 → 내 일정                     | 새 메일 (모바일)  |
| J2  | **유료 신청:** 발견 필터(유료) → 상세 → 신청 → 입금 안내(계좌 복사) → 운영진 입금 확인 → 확정 반영(상세 · 홈 · 일정 · 주문) → 환불 요청 금액 미리보기 | 처음온사람        |
| J3  | **챌린지·클럽:** 회원 홈 "오늘 인증" → 인증 올리기 → 진행 반영 → 클럽 상세 → 가입 → 홈 "내 사람들"                                                    | 멤버하나 (모바일) |
| J4  | **호스트 하루:** `/host` 처리할 일 → 지난 활동에서 가져와 새로 만들기 → 표지 → 공개 → (멤버 신청) → 공지 → 빠른 출석 → 장부 지출 → 정산 · 단골        | 바라호스트        |

여정 체크:

- 화면이 바뀔 때마다 **"방금 한 일의 결과"** 가 보이는가(토스트가 아니라 화면 상태로).
- 로그인 · 온보딩을 거친 뒤 **원래 하려던 곳**으로 돌아오는가.
- 같은 활동의 이름 · 날짜 · 금액 · 상태 배지가 모든 화면에서 같은가(U10 · D7).
- 막힌 지점에서 "다음 행동"이 하나라도 있는가.
