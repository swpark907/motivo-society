# 워크북 아이디어 회의 기록

## 2026-10-18 웹 클래스 프로젝트 연계와 실제 공유

사용자 확정: 같은 프로젝트를 끝까지 발전시키고 실제 배포·다른 사람에게 공유까지 목표로 한다. 4단원의 기본은 항목 선택과 상세 보기이며 저장은 필요한 경우에만 적용한다. 5단원은 공개 전 점검→실제 배포·외부 접속→공유·수정·재배포로 구체화한다. 이번 요청은 [1~5단원 커리큘럼, 기존 수업 유지·수정·추가와 작업 순서](workbook-web-class-project-curriculum.md)의 문서화이며 구현은 하지 않는다.

에이전트 제안과 미결: 한 페이지 소개·모음 사이트와 페이지 내 상세 펼침을 기본 예시로 권장한다. 배포 서비스는 기존 Vercel Drop과 최근 논의한 Netlify 후보를 비교한 뒤 결정한다. 세부 완료 판정, 대체 과제, 작업 순서는 검토안이다. 단계별 결과 기록은 새 입력을 반복하기보다 기존 내용을 이어받는 방향으로 제안한다.

## 2026-10-06 토글과 기존 문구 겹침 수정

사용자 스크린샷에서 하단 토글이 기존 문구를 가리는 문제를 확인했다. 절대 위치 대신 메뉴 본문·토글 전용 행을 분리한 그리드로 수정한다. 접힘 전후 버튼 위치는 유지하고, 낮은 화면에서도 기존 하단 문구를 숨기지 않으며 필요 시 본문 영역만 스크롤한다.

## 2026-10-06 bx-debug 고정 아이콘 슬롯 참조

사용자 지정 bx-debug의 RootLayout을 읽고 패널 폭과 독립적인 아이콘 슬롯 방식을 참조했다. 토글은 데스크톱에서 동일한 좌측·하단 좌표에 고정하고 18px 아이콘·40px 조작 영역으로 축소했다. 기본 테두리와 배경을 제거하고 hover·펼침 선택·키보드 포커스만 표시한다. 펼침 240px·접힘 56px로 패널도 축소했다. 형제 저장소는 수정하지 않았다.

## 2026-10-06 메뉴 아이콘과 클래스 시작 자동 접힘

사용자 요청으로 텍스트 토글을 공식 Lucide PanelLeft SVG로 교체했다. 데스크톱은 좌측 패널 하단, 모바일은 상단에 두며 접근 가능한 이름과 툴팁을 제공한다. 클래스 체험 시작 시 화면 크기와 무관하게 메뉴를 접고, 이후 사용자가 펼친 상태는 개별 레슨 진입에서 다시 접지 않는다. 새 패키지 의존성 없이 원본 아이콘을 인라인 사용하며 라이선스는 docs/licenses/lucide.txt에 보존했다.

## 2026-10-06 좌측 메뉴 폭·스크롤 보정

사용자가 레슨 진입 시 좌측 패널 스크롤이 생기는 문제를 전달했다. 펼친 폭을 260px, 접힌 폭을 112px로 조정하고 장식 조명에 할당하던 하단 100px 여백을 줄였다. 지도와 레슨에서 동일한 단일 내부 스크롤 정책을 사용한다. 낮은 화면에서는 하단 장식 문구를 생략하고, 메뉴 내용 자체가 화면보다 길 때만 내부 스크롤을 허용한다.

## 2026-10-06 도착 카드 시각 개선

사용자 피드백으로 캐릭터를 가리던 도착 팝업을 포인트 아래로 이동했다. 이중 테두리와 큰 주황 버튼 대신 어두운 단일 클릭 카드에 수업명·장소·작은 주황 화살표를 배치한다. 모바일에서는 지도 바로 아래에 두어 캐릭터와 포인트를 가리지 않는다.

## 2026-10-06 고정 학습 화면 디자인 검토

사용자 승인 후 인앱 브라우저의 1440×900·390×844 화면에서 확인했다. 모바일의 펼친 메뉴가 본문 높이를 차지해 수업 진입 시 자동 접힘으로 보정했고 직접 다시 펼칠 수 있다. 본문 줄 길이와 퀴즈 간격, 우측 목표 문구 줄바꿈을 조정했다. 작은 화면의 퀴즈는 본문 안에서 스크롤하고 헤더·진행바는 유지한다. 지도 라벨이 다른 포인트의 클릭을 가로채지 않도록 수정했다.

## 2026-10-06 고정 학습 화면과 우측 패널

사용자가 고정 헤더·넓은 본문·우측 진행 패널 구조를 승인했다. 레슨에서 상단 수업명과 장소를 유지하고 본문만 독립 스크롤이 가능하도록 구성했다. 설명 문단은 누적 대신 같은 영역에서 교체하며 이전으로 다시 볼 수 있다. 비교·퀴즈 자료는 함께 유지한다. 우측 패널은 목표·핵심 메모·이전/다음 조작을 제공하고 모바일에서는 하단 진행바로 축소한다. 작은 화면·글자 확대에서 내용을 자르거나 글자를 축소하지 않고 본문 스크롤을 허용한다.

## 2026-10-06 메뉴와 진행 조작 위치 개선

사용자 요청으로 워크북 좌측 메뉴 접기·펼치기, 레슨 우측의 고정 진행 버튼(모바일 하단), 지도 도착 위치의 시작 팝업을 적용했다. 모바일에서는 지도 중앙 정렬로 포인트 위쪽에 시작 버튼을 두고, 도착 시 초점을 옮겨 화면에 보이도록 한다. 접힘 상태는 현재 레이아웃 방문 동안 유지하며 별도 영구 저장은 하지 않는다.

## 2026-10-06 퀴즈·지도·문단 공개 사용성 개선

사용자는 정오답을 별도 하단 결과가 아닌 선택 버튼에 표시하고, 굵은 점선 화살표 애니메이션과 다음 목표 포인트 강조로 순서를 안내하자고 요청했다. 긴 수업 글은 페이지 안에서 2~3단계로 나눠 공개한다. 구현은 하단 이유 텍스트 유지, 지도 경로와 다음 목표 자동 갱신, 경로 정지 및 모션 줄이기 대응, 긴 설명 페이지의 3단계 누적 공개를 적용했다. 화면 전체 클릭 대신 명확한 다음 버튼을 사용해 퀴즈·탭 조작 시 의도치 않게 진행되지 않게 했다.

## 2026-10-06 퀴즈 정오답 피드백

사용자 요청으로 클래스 확인 문제의 선택 결과를 정답은 초록색·체크, 오답은 빨간색·X로 표시한다. 색상과 함께 정답·오답 문구 및 이유를 제공하고 재선택할 수 있다. 선택하지 않은 답에는 정답을 미리 노출하지 않는다. 1·2수업의 객관식 및 용도 중복 확인 문제에 적용했다.

## 2026-10-06 분리된 수업 진입을 카피바라 여정에 통합

사용자는 기존 카피바라 프로젝트를 선택형으로 분리한 구현이 의도와 다르다고 정정했다. 새 입문 내용을 기존 맵·캐릭터·이야기를 수정해 그 안에 녹이는 방향을 확정했다. 클래스 진입을 맵으로 복구하고 찻집의 AI 이해 → 장터의 AI 종류와 도구를 연결했다. 수업 종료 후 위치를 유지한 맵으로 돌아와 다음 장소를 선택한다. 뒤 세 지점은 준비 중으로 표시하며 장소 배치는 프로토타입 제안이다. 긴 배경 이야기는 선택 감상으로 남기되 맵 자체는 주 학습 흐름이다.

## 2026-10-06 원고 추가보다 프로토타입 반영 우선

사용자는 세 번째 수업 원고 작성 전에 합의한 방향을 프로토타입에 먼저 반영하도록 요청했다. 클래스 진입을 입문 목차로 바꾸고 1·2수업의 설명·예시 비교·확인 문제를 구현했다. 도구 준비부터 뒤 세 수업은 준비 중으로 표시한다. 기존 이야기·지도는 선택형 이전 시안으로 보존했다. 개인 컴퓨터 실습·모바일 복습을 안내하며 이번 방문의 확인 상태만 유지한다. 실제 도구 실습·회원 진도·기기 간 동기화는 구현하지 않았다. 디자인 체크는 승인 요청 상태다.

## 2026-10-06 개인 컴퓨터 실습·모바일 복습 확정

사용자는 두 번째 수업 구성과 기본 도구 하나로 시작하는 방향에 동의했고, 자기 컴퓨터로 실습하는 것을 기본으로 모바일은 복습 용도로 하자고 확정했다. 공용 규칙과 재계획안에 반영했다. 에이전트는 세 번째 수업을 준비물·기본 도구 소개·접속 또는 설치·입력창 확인·첫 대화 연결로 구성하는 안을 기록했다. 구체 도구·지원 OS·기기 간 동기화는 미확정이며 UI는 변경하지 않았다.

## 2026-10-06 AI 종류와 도구 수업 초안 작성

사용자가 합의한 순서에 따라 후속 상세 기획 진행을 요청했다. 에이전트는 `workbook-lesson-02-tools.md`에 만들 결과 비교, 모델과 도구의 구분, 필요한 기능 선택 활동, 다음 도구 준비로의 연결을 작성했다. 제품명 암기 대신 용도와 기능을 판단하며 한 도구의 용도가 겹칠 수 있음을 설명한다. 공식 자료를 참고한 실제 제품 예시는 선택형으로 분리했고 직접 사용 검증·실습 도구 선정은 아직 하지 않았다. 기본 도구 하나로 시작 경로를 안내하는 것은 제안이며 특정 제품·유료 플랜·UI 구현은 미확정이다.

## 2026-10-06 입문 학습 순서 수정 확정

사용자는 ‘AI 이해 → 종류와 도구 → 도구 준비 → 첫 대화와 수정 요청 → 에이전트와 바이브코딩’ 순서를 더 자연스럽다고 승인했다. 첫 수업에서 수정 요청까지 진행하던 초안은 대체한다. 첫 수업은 짧은 예시로 역할과 한계를 이해하고, 실제 요청·수정은 도구를 알고 준비한 뒤 진행한다. 카피바라는 함께 배우는 동료로 유지한다. 첫 수업 원고와 재계획안을 수정했으며 코드 변경은 하지 않았다. 구체 도구 선정·차시 수·맵 배치는 미확정이다.

## 2026-10-06 첫 수업 원고와 재계획 초안

사용자가 ‘AI 이해하기’의 실제 원고·활동을 만든 뒤 다시 계획하자는 진행을 승인했다. `workbook-lesson-01-ai.md`에 설명→카피바라 소개문 사례→확인되지 않은 정보 찾기→수정 요청 비교→정리·내 작업 연결을 작성했다. `workbook-beginner-replan.md`에는 AI 종류·대화·에이전트·바이브코딩·설치·첫 제작 순서를 검토안으로 정리했다. 아직 사용자 검토·발행 전이며 기존 UI는 바꾸지 않았다.

## 2026-10-06 공부가 중심인 경험 확정

사용자는 대화형 AI도 거의 써보지 않은 초보를 포함하는 출발 수준에 동의했다. 스토리는 자연스럽게 연결하되 수업 내용이 중심이어야 하고 사용자가 게임보다 공부한다고 느끼는 감각을 유지해야 한다고 명확히 했다. 맵·캐릭터 삭제 요구가 아니라 역할과 우선순위의 정정이다.

에이전트 제안: 지도는 시각적인 목차, 장소명은 보조 표기, 활동은 학습 질문→상황 예시→설명과 조작→확인→핵심 정리로 구성한다. 제목·배울 내용·배운 내용을 명확히 표시하고 이야기 이해를 평가하지 않는다. 카피바라는 같은 입장에서 질문하고 사례를 보여주는 동료이며 과도한 게임 보상이나 대사 통과를 진도로 삼지 않는다. 구체 차시·시간·활동 구성은 추가 기획 대상이며 코드 변경은 하지 않았다.

## 2026-10-06 AI 완전 입문 범위 정정 — 논의 재개

사용자는 ‘AI 설치·기초’를 설치 여부 확인 후 제작 연습으로 해석한 구현이 의도와 다르다고 정정했다. AI가 무엇인지, AI의 종류, 에이전트, 바이브코딩 등 완전 초보가 알아야 할 개념부터 클래스에 포함하자는 뜻이다. 추가 구현보다 논의가 먼저다. 현재 준비 체크와 예시 요청 화면은 새 요구를 충족한 완성 교육 콘텐츠가 아니다.

에이전트 제안(미확정): AI 이해→종류와 용어 관계→대화와 작업 수행의 차이→바이브코딩의 의미와 사람의 역할→도구 설치·첫 사용→작은 제작으로 이어지는 입문 과정을 먼저 설계한다. AI의 종류를 브랜드 목록으로만 나열하지 않고 목적·사용 방식·서비스와 모델의 차이를 구분한다. 기존 4+1에 입문 지역을 포함할지, 별도 시작 지역으로 둘지는 학습 내용을 정한 후 판단한다. 첫 인터뷰는 ‘대화형 AI도 처음’과 ‘대화는 해봤지만 제작은 처음’ 중 기본 출발 수준을 확인하는 것이다.

## 2026-10-05 직관적인 활동 중심 진입 적용

사용자의 수정 진행 요청에 따라 시작 지점을 AI 도구 준비로 바꿨다. 긴 캐릭터 이야기는 선택형으로 보존하고 설치 없이 요청·확인·수정을 경험하는 사전 제작 예시를 추가했다. 실제 AI 호출이 아님을 표시한다. 준비 확인→첫 요청 예시→홈페이지 기획하기로 바로 진행하며 지도 탐색도 선택형이다. 지도 안내는 클릭→이동→도착의 3단계로 축소했다. 8개 활동 순서는 펼쳐보기로 제공한다. 실제 도구별 설치 안내와 이후 활동은 미구현이며 화면에 표시한다. 다음 논의는 기본 안내에 사용할 AI 도구 선정이다.

## 2026-10-05 서론 축소와 AI 입문 보강

사용자 전달 피드백: 콘셉트는 좋지만 캐릭터 이야기·찻집의 의미·맵 조작 등을 먼저 이해해야 해서 바이브코딩 학습의 시작이 늦고 부담스럽다. 에이전트는 필수 도입을 짧게 하고 학습 행동을 전면에, 이야기를 선택형 또는 행동에 대한 짧은 반응으로 두는 방안을 제안했다. 아직 기존 구현을 변경하지 않았다.

사용자 추가 제안: AI 설치와 AI에 대한 지식을 배우며 도구와 친해지는 과정도 필요하다. 명칭은 ‘누구를 위한 홈페이지인가요?’보다 ‘홈페이지 기획하기’처럼 직관적인 활동 이름을 선호한다.

에이전트 수정안: ‘AI 도구 준비하기 → AI와 첫 화면 만들어보기 → 홈페이지 기획하기 → 화면 구성하기 → 콘텐츠 준비하기 → 제작 요청하기 → 홈페이지 만들기 → 확인하고 수정하기’. 앞의 체험은 준비된 작은 예제로 요청·확인·수정 한 번을 경험하고, 뒤의 제작은 자신의 기획을 적용하는 것으로 구분한다. 별도 긴 AI 이론 강의 대신 모델과 도구, 작업 폴더·파일, AI의 오류와 확인 책임을 필요한 순간에 소개한다. 설치가 끝난 사람은 준비 확인 후 넘어가고, 미설치자는 가이드로 준비한다. 유료 결제 강제나 비밀키 입력을 연습 조건으로 만들지 않는다. 실제 설치 안내 제작 시 도구별 공식 최신 절차를 확인한다. 특정 도구·설치 방법은 이번 논의에서 확정하지 않았다.

## 2026-10-05 인트로 구현 진행

사용자 승인으로 배낭 카피바라 보행 소개와 3개 대화 장면을 구현했다. 다음·이전·건너뛰기·다시보기로 진행을 직접 조절하며 새 도입에서 기존 월드 안내·찻집 활동으로 이어진다. 이미지와 생성 기록은 `docs/design-references/workbook-intro-assets.md`. 실제 브라우저 디자인 체크는 승인 요청 상태다.

## 2026-10-05 홈 B안 승인 및 적용

사용자가 콘텐츠와 학습이 함께 있는 홈에 이어하기를 결합하는 B안 진행을 승인했다. 복수 클래스·실험·칼럼을 배치하고 모니터 속 픽셀 마을의 실사 표지를 적용한다. 추가 클래스·칼럼은 가상 판매 상품으로 만들지 않고 기획 예시로 표시했다. 현재 이어하기는 실제 로컬 실험 기록만 사용하며 회원 구매 상태는 아직 구현하지 않는다.

## 2026-10-05 복수 클래스·콘텐츠를 위한 홈 재구성

사용자는 모니터 속 픽셀 세계를 보여주는 실사 썸네일 방향을 승인했다. 현재 거대한 단일 클래스 카드 중심 홈 대신 여러 클래스·콘텐츠가 있는 상황을 가정해 사용성 관점의 방안을 제안해 달라고 요청했다. `workbook-home-options.md`에 탐색형·편집형과 이어하기·내 학습 중심의 세 안을 비교했고, 에이전트는 두 번째 안을 추천했다. 레이아웃 확정이나 가상 클래스 출시 승인은 아니다.

## 2026-10-05 홈과 픽셀 클래스 사이의 시각적 연결

사용자 전달 피드백: 기존 워크북 홈의 영화·실사·고급스러운 톤에 픽셀 맵 썸네일이 바로 등장해 이질적이다. 실사 카피바라가 게임 속으로 들어간다는 콘셉트는 긍정적이므로 학습 콘텐츠나 게임 세계 자체를 바꿀 필요는 없다는 방향이다.

에이전트 제안: 홈 클래스 카드는 따뜻한 실사 카피바라 작업실의 영화 포스터 같은 이미지로 바꾸고, 모니터 속에만 픽셀 마을을 보여준다. 클래스 소개는 같은 톤을 유지하면서 실제 게임 화면을 별도 미리보기로 명확하게 제시한다. 체험 시작 후 모니터의 세계로 진입하는 짧은 전환과 픽셀 캐릭터 소개를 연결한다. 모션 줄이기에서는 정적인 장면 전환을 제공한다. 픽셀 맵은 클래스 안에서 본격적으로 펼친다. 카드에는 인터랙티브 클래스라는 성격을 표시해 실사 게임으로 오인시키지 않는다.

이것은 디자인 제안이며 새 이미지 생성·UI 교체·전환 애니메이션은 아직 구현하지 않았다. 우선 썸네일 한 장으로 외부 톤과 내부 세계의 연결을 검토하는 것을 추천한다.

## 2026-10-04 게임형 도입 연출 보완 논의

사용자는 제자리걸음 카피바라의 짧은 소개, 친구와 전화·대화하는 이미지, 대사 진행에 따라 그림이 바뀌는 장면 또는 말풍선이 차례로 켜지는 4컷 만화를 제안했다. 에이전트는 소개 뒤 3개 대화 장면을 클릭으로 진행하는 방식을 추천했다. 구체 연출·4컷 채택은 미확정이며 `workbook-world-1-storyboard.md`에 선택 근거와 접근성·제작 경계를 기록했다. 이번 논의로 실제 이미지·보행·컷씬 구현을 완료한 것은 아니다.

## 2026-10-04 워크북 구매 단위 정정 — 클래스별 구매

사용자 정정: 워크북 페이지에는 결제 가능한 여러 클래스가 있다. 사용자가 그중 ‘바이브코딩 웹개발 클래스’를 구매하면 현재 기획 중인 게임형 클래스를 플레이할 수 있다. 워크북 전체를 구매해야 홈이 열리는 구조라는 이전 해석은 폐기한다. 접근 권한의 단위는 개별 클래스다. 회원가입·로그인은 구매·이용 계정의 맥락이며 워크북 목록 열람 자체에 로그인 제한을 두기로 결정한 것은 아니다.

흐름: 워크북 클래스 목록→개별 클래스 소개·구매→해당 클래스 시작 또는 이어하기→첫 진입 이야기→월드 맵·활동. 결제 사업자·가격·이용 기간·환불·실제 인증 및 결제 구현은 아직 미결이다. 이번 정정은 상품·진입 구조 확정이며 즉시 실결제 기능을 구현하라는 요청은 아니다.

## 2026-10-04 주인공 설정 확정과 첫 구간 대본

사용자가 ‘작은 웹 경험을 만드는 카피바라’ 설정을 승인했다. 차 따르기·호흡 맞추기·돌 정원 등 일상에 작은 쉼을 주는 작업을 AI와 만드는 동료 캐릭터다. 흩어진 작업을 소개할 홈페이지가 필요하다는 상황에서 시작한다. 이름은 미정이다. 실제 서비스의 출시 상태와 이야기 설정을 구분한다.

`workbook-world-1-storyboard.md`에 선착장 메시지→서로 다른 홈페이지 예시→4+1 여행 안내→찻집 이동→방문자 선택→기획 메모·장터 연결까지 대사와 선택지를 작성했다. 설정은 확정이고 구체 대본·화면 연출은 검토할 제작안이다.

## 2026-10-04 도입에서 제작 한 사이클 보여주기

사용자는 활동 이유를 상황·행동·결과로 자연스럽게 전달하는 방향을 승인했다. 추가로 카피바라 이야기 초반에 기획→화면→백엔드 심화→배포의 한 사이클과 이후 효율·확장을 돕는 바이브코딩 생활을 녹이도록 요청했다. 상세 연출 제안은 `workbook-world-1.md`의 도입 이야기 절에 기록했다. 백엔드는 필요에 따른 선택이며 모든 홈페이지에 필수라고 안내하지 않는다. 도입의 구체 대사·장면은 제안 단계다.

## 2026-10-04 활동의 당위성을 부담 없이 전달하기

사용자 요구: 참여자가 ‘갑자기 이걸 왜 하지?’라고 느끼지 않도록 활동 이유를 직접·간접 어떤 형태로든 부담 없이 전달한다. 에이전트 제안: 앞 장면의 작은 필요→직접 행동→달라진 결과, 목적 한 줄, 선택형 추가 설명을 조합한다. 장소별 예시는 `workbook-world-1.md`에 기록했다. 매 활동을 강제 실패나 필수 설명 팝업으로 시작하지 않는다. 공방에서 HTML·CSS·JS 역할을 짧게 경험하는 안도 논의 중이며 구현 확정은 아니다.

기록 시작: 2026-10-02. 참여: 승우·Codex.

현재는 아이디어 수집 단계다. 이 문서에 실린 내용은 기능 확정이나 개발 지시가 아니다. 아이디어를 충분히 모은 뒤 별도 필터링 회의를 진행한다. 논의 중에는 새 아이디어와 보완·우려를 함께 기록하고, 사용자 의견과 에이전트 제안을 구분한다.

## 현재 확인된 방향과 작업 상태

- 사용자: 책상 정리 액티비티 개발은 잠시 대기한다.
- 사용자: `vibe-web-class-ssot` 내용을 양질의 자료로 개선해 워크북에 녹이는 방향을 논의한다. 형제 저장소 자체의 수정 승인은 아니다.
- 사용자: 새로운 홈 이미지 시안은 괜찮다고 평가했다. 이 평가를 전체 기능 구현 승인으로 해석하지 않는다.
- 사용자: 핵심 타깃은 20~30대다. 캐릭터와 게임 요소 때문에 아동 대상처럼 보이지 않도록 조율해야 한다.
- 사용자: 인터넷에서 공유되고 확산될 요소도 중요하다.
- 사용자: 아이디어 회의를 기록하면서 이어가고, 수집 이후 필터링을 진행한다.
- 미결: 독학 입문자까지 포함할지, 클래스 참여자를 먼저 대상으로 할지. 상세 기획안은 독학 입문자 포함을 가정한 초안이다.

## 이야기와 상호작용 예시

### 휴대폰에서 생긴 문제

사용자 발상: 카피바라가 주인공이고, 모바일 화면에 관한 불만이 줄거리에 등장한다.

에이전트 확장: 작업실 페이지를 받은 친구가 정류장에서 휴대폰으로 보다가 제목이 잘리고 문의 버튼을 찾지 못한다. 학습자는 문제를 찾고, 가로·세로 배치 결과를 예상하고, 화면 폭과 여백을 바꾸어 확인한다. 이후 자기 페이지에서 발견한 문제를 AI에게 수정 요청한다. 마무리에서는 친구가 버튼을 찾는 장면을 보여준다. 이 시나리오는 제안이며 제작 확정이 아니다.

### 본문 안의 작은 실험

에이전트 제안:

- ‘화면이 좁아지면’을 누르면 옆 예시의 폭과 카드 배치가 바뀐다.
- ‘간격’을 조절하면 본문 속 카드 사이의 거리가 바뀐다.
- ‘이 정보는 저장됐을까요?’에서 예상한 뒤 새로 열어 결과를 확인한다.
- 공통 요소 하나를 수정하면 연결된 여러 예시에 변화가 나타난다.
- 핵심 구절의 밑줄·연결선이 등장하며 관련 도형을 짚는다.

본문 전체가 계속 움직이거나 애니메이션이 끝날 때까지 읽기를 막는 방식은 피하자는 제안이다. 현재 전역 모션 규칙을 변경하거나 이 아이디어를 구현한 것은 아니다. 제작 전 워크북 콘텐츠의 모션 범위와 접근성 기준을 정해야 한다.

## 성인 타깃과 공유 경험에 관한 논의

사용자는 귀여운 카피바라와 많은 게임 요소가 아동 대상처럼 보일 가능성을 지적했다. 20~30대라는 타깃과 인터넷 확산 가능성을 함께 고려해야 한다는 요구다.

에이전트 제안은 다음과 같다.

- 자기 작업실·작은 브랜드·사이드 프로젝트를 다루고 실제 제작의 문제를 이야기로 사용한다.
- 카피바라는 과하게 칭찬하는 선생보다 함께 만들고 막히는 동료로 둔다.
- 원색과 과도한 폭죽보다 저채도 픽셀 미술과 정교한 작은 반응을 검토한다.
- 레벨 숫자보다 내 결과·선택·발견이 보상과 공유의 재료가 되게 한다.
- 공유자에게는 자기표현, 보는 사람에게는 공감이나 직접 해볼 거리를 제공한다.
- 우선 전후 비교 카드와 짧은 공개 실험의 반응을 검증하고, 작업실 개인화는 비용을 보고 판단한다.

‘귀여워서 들어오고, 내 이야기라 머물고, 내가 만든 것이 생겨서 공유한다’는 에이전트의 방향성 문구다. 확정 슬로건이 아니며 바이럴 효과를 검증했다는 뜻도 아니다.

## 알림에 관한 확인과 미결

웹도 알림이 가능하다는 점을 논의했다. iOS의 홈 화면 웹앱 등 환경별 조건이 있어 사용자 설정 과정이 필요하다. 카카오톡 채널 메시지와 알림톡은 구분해 검토하며, 학습 독려·새 이야기 안내가 모두 알림톡으로 허용된다고 전제하지 않는다.

2026-10-02 대화에서 참고한 공식 자료:

- [Apple 웹 푸시 안내](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)
- [카카오비즈니스](https://business.kakao.com/)

실제 발송 사업자·메시지 심사·요금·수신 동의·연락처 연결은 미확인이다. 알림 구현이나 외부 메시지 발송은 하지 않았다.

알림 후보: 사용자가 지정한 학습 시간, 진행 중 활동 이어가기, 새 이야기 공개, 요청한 피드백 도착. 캐릭터가 슬퍼한다는 식의 죄책감 유도보다 돌아와서 할 수 있는 일을 안내하자는 에이전트 제안이 있었다.

## 2026-10-04 기본 4월드 + 선택 심화 1월드 확정

디자인 검수에서 반복 목적 안내를 첫 설명에만 남기고 첫 수업의 중복 정리를 합쳤다. 홈페이지 기획은 반복 설명을 줄여 입력이 앞에 보이도록 하고 용어·제작 범위는 펼치기로 이동했다. 데스크톱·모바일에서 실제 학습을 거쳐 목적별 기획과 마지막 정리를 확인했다. 증빙은 `/tmp/workbook-purpose-learning-20261014/`에 있다.

## 2026-10-15 첫 화면·수정 기준과 결과 모아보기

사용자는 서비스 소개·포트폴리오·개인 사이트별 첫 화면 확인 기준과 수정 요청 예시, 마지막 결과물/변화 요약을 요청했다. 목적 정의 옆에 화면 확인 기준을 관리하고, 첫 화면은 누구를 돕는지/맡은 역할/좋아하는 주제와 이유를 확인하도록 연결했다. 수정 단계는 같은 목적의 문장·목록·버튼을 작은 화면에서도 읽을 수 있는지 확인하며, 수정 초안에 해당 기준이 포함된다. 연습의 고정 너비 조건을 실제 파일의 문제로 오인하지 않도록 기존 안내를 유지한다.

결과 모아보기는 확인 조건을 마친 뒤 나타난다. 기획 제목·소개·내용과 관찰/수정 전후 기록을 함께 보여주고 제작·수정 요청/근거는 펼쳐볼 수 있다. 기획 구성은 실제 파일의 캡처가 아님을 표시하고 실제 적용 결과는 기존 본인 확인 기록이 있을 때만 별도로 보여준다. 선택 모아보기는 내부 스크롤만 이동하며 새 브라우저 이력이나 필수 진행 클릭을 추가하지 않는다. 내용 목록은 먼저 세 항목을 보여주고 나머지를 펼쳐볼 수 있다.
