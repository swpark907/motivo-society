# 전체 과정의 지도별 진입으로 재정리 — 2026-10-25 최신

사용자 정정에 따라 전체 과정은 각 단원 지도의 진입 가능 여부를 보여주고 해당 지도로 이동하는 화면으로 정리했다. 각 지도 바로 아래의 버튼은 그 단원 지도만 연다. 현재 듣던 수업이나 선행 수업으로 보내는 버튼은 전체 과정에서 제거했다. 이전 단원을 마치지 않은 지도는 ‘잠김’·개방 조건과 흐린 이미지로 표시하며 해당 지도 버튼을 비활성화한다. 열린 단원은 진입 가능 및 학습 확인 수를 표시한다. 지도 진입 뒤 다음 수업 시작은 기존 지도 패널이 담당한다. 단원별 접힘 UI를 제거해 지도·버튼·진입 상태가 항상 함께 보이게 했다. 아래 앞선 수정 시도는 철회된 기록이다.

재부팅 후 PC·모바일에서 지도별 버튼의 비활성/활성, 해당 단원 지도 진입, 소개 왕복과 수업 화면 보존을 검증했다. 6개 브라우저 시나리오가 통과했으며 잠금 전후 화면 캡처도 확인했다.

# 전체 과정에서 선택한 단원과 진입 버튼 구분 — 2026-10-25

잠긴 2단원을 펼쳤을 때 ‘이 학습부터 이어가기’는 실제로 1단원의 남은 수업을 여는 버튼이었다. 선택한 단원으로 들어가는 듯한 문구를 제거했다. 잠긴 단원은 ‘N단원에 들어가기 전에 아래 수업을 먼저 마쳐요’와 실제 선행 수업 번호·이름을 명시한다. 열린 단원은 그 단원의 다음 미완료 수업을 직접 여는 버튼과 지도 보기 버튼을 분리한다. 학습 해금·완료 기준은 유지한다. PC·모바일에서 잠긴 단원 버튼의 선행 수업 진입과 열린 단원 버튼의 기획 수업 렌더링을 확인했다. 첫 자동 검증은 미리보기 전용 URL을 실제 수업 URL로 기대한 assertion 때문에 실패했고 이를 수정했다. 재실행은 브라우저 조작 응답 지연으로 시간 초과하여 최종 통과로 기록하지 않는다. 타입 검사는 통과했다.

# 다음 학습 안내와 지도 조작부 개선 — 2026-10-25

아래 첫 방문 검수의 후속 구현이다. 이전 검수에서 남긴 문제와 관찰은 당시 기록으로 보존한다.

- 지도 패널 맨 위에 다음 미완료 수업의 번호·이름과 ‘다음 수업 시작’을 항상 표시한다. 선택 카드가 있다는 이유로 다음 행동을 숨기던 CSS를 제거했다.
- 다섯 단원의 공통 선택 수업 카드는 완료 상태를 전달받아 ‘다시 보기’로 표시한다. 선택 수업의 진입은 보조 버튼으로 두어 다음 수업·단원 진입과 주 강조색으로 경쟁하지 않는다.
- 모바일은 다음 학습/다음 단원 안내 → 지도 → 선택한 수업과 기록·이용 안내 순서다. 데스크톱은 지도 왼쪽·패널 오른쪽을 유지한다.
- 모든 단원 지도에 고정된 지도 뷰포트를 두고 전체 과정·도움말을 그 위에 배치했다. 이미지만 가로 스크롤하며 조작부는 움직이지 않는다. 투명도·호버와 도움말 왼쪽 팝업은 유지했다.
- 소개의 유일한 시작/학습 복귀 버튼을 표지의 설명 바로 아래로 옮겼다. 첫 화면에서 찾을 수 있고 예시 둘러보기와 기존 학습 복귀 경로를 사용한다.

PC·모바일의 소개 → 1단원 예시 학습 전체 → 2-1 진입 연속 검증을 통과했다. 시작 버튼의 첫 화면 노출, 다음 안내의 지도보다 앞선 배치, 지도 가로 스크롤 전후 조작부 좌표, 완료 수업의 다시 보기, 소개 왕복 후 내부 화면 보존을 확인한다. 외부 앱·실제 파일·학습 판정·저장 정책은 변경하지 않았다.

# 첫 방문 연속 화면 검수 — 2026-10-25

새 브라우저 컨텍스트에서 클래스 소개 → 제작 예시 → 1-1~1-5의 모든 기본 화면 → 1단원 완료 → 2-1 진입을 PC(1280×800)·모바일(Pixel 7)에서 연속 진행했다. 완료 상태 주입·직접 수업 URL 이동 없이 실제 UI로 이동했다. 지도→전체 과정→닫기→소개→학습 복귀도 1·2단원에서 각각 확인했다. Playwright 두 시나리오는 통과했지만, 이는 동작 가능성 검증이며 아래 사용성 문제의 해소를 뜻하지 않는다.

1-3은 복습, 1-4·1-5는 사전 제작 예시 경로다. 외부 앱 설치·실제 파일 제작·배포를 수행하거나 완료로 선언한 검수가 아니다. 이번 요청은 검수이므로 제품 UI는 변경하지 않았다.

## 유지할 동작

- 제작 예시 선택은 미리보기만 바꾸고 ‘기초강의 시작하기’에서 같은 1-1로 들어간다. 학습 분기가 생긴다고 오해하지 않도록 안내한다.
- ‘단원 지도 보기’ → 현재 단원, ‘전체 과정 보기’ → 다섯 단원의 모달, ‘클래스 소개 보기’ → 소개로 목적지가 구분된다.
- 전체 과정 닫기는 원래 지도로 복귀한다. 소개에서 ‘학습으로 돌아가기’도 해당 단원 지도를 복원한다. 이후 수업 재진입 시 내부 화면 번호가 보존된다. 2-1 화면 2에서 왕복한 뒤에도 화면 2였다.
- 1단원 완료 안내의 ‘2-1 홈페이지 기획하기 시작’은 바로 해당 수업을 연다. 지도 먼저 보기는 보조 경로다.
- 2-1은 같은 `my-first-web/index.html`을 이어 쓴다는 연결과 ‘아직 첫 파일이 없어요’의 별도 안내를 제공한다. 예시만 본 사람을 실제 파일 제작 완료로 승격하지 않는다.

- 화면 캡처: 실행 결과의 `01-introduction`, `02-examples`, `03-overview`, 각 `map-before-*`, `04-unit-recap`, `05-unit-handoff`, `06-planning`, `07-unit-two-overview`.

# 내용 묶음·단원 전환·소개 복귀 후속 — 2026-10-24

관련된 설명/입력/실행과 뒤의 결과 확인을 내용 단위로 다시 묶었다. 1-3의 설치·환경 선택부터 요청 작성·관찰 기록·폭 비교·메모 표시·주소 실행을 재구성하고 이중으로 접힌 심화를 정리했다.

수업→현재 단원 지도, 지도→전체 과정 모달, 지도→클래스 소개의 목적지와 이름을 구분했다. 소개에서 복귀할 때 이번 방문의 위치를 되살린다. 단원을 마치면 다음 수업 번호·이름과 직접 시작 버튼을 먼저 제공하고 지도 탐색/복습 기록은 보조로 둔다. 기존 선행 학습과 예시/실제 결과 판정은 유지한다. 기준과 검토 경로는 [강의 UI 기준](../design-references/workbook-lesson-ui.md)의 최신 절에 기록했다.

# 선택 심화·별도 적용 기록의 시각 체계 통일 — 2026-10-24 후속

# 3~5단원 적용 기록의 학습 정리 연결 — 2026-10-23 후속

사용자 승인으로 기존 선택 적용 기록을 마지막 학습 정리와 지도 단원 요약에 연결했다. 아래 전체 검수의 첫 번째 문제에 대한 후속이다. 기본 학습의 진행·해금·완료 조건은 변경하지 않았다.

- 기존 선택 실습의 결과·문제·근거 입력을 그대로 사용한다. 기존 기록 버튼에서 `확인한 범위 충족`과 `남은 문제가 있는 결과`를 구분한다. 새 확인 체크·적용/생략 사유·필수 외부 실습을 기본 수업에 추가하지 않는다.
- 새 명시적 기록에는 본인이 확인한 원문과 그때의 프로젝트·기획·관련 변경 버전·앞선 적용 기록을 함께 보관한다. 예시 조작·예전 confirmed 값·첨부 자료는 이 확인을 만들지 않는다. 이전 기록은 작성 내용을 다시 입력하지 않고 현재 버튼에서 명시적으로 확인할 수 있다.
- 3·4단원의 충족 기록은 정리의 실제 목표 결과로 표시하고 해당 남은 확인을 해소한다. 문제가 있는 기록은 확인한 일부 결과를 보여주면서 문제 내용을 남은 일에 표시한다. 파일 변경 여부·기능 적용/생략 판단을 추가로 요구하지 않는다.
- 5단원의 범용 적용 기록은 실제 결과에 표시하지만, 공개 전 점검이나 주소 문자열을 공개·공유·수정 후 같은 주소 재배포 전체로 승격하지 않는다. 정리의 남은 일에는 기록된 범위와 별도로 필요한 공개 확인을 안내한다. 최종 공개 완료 기준을 완화하거나 실제 배포 기능을 추가한 작업은 아니다.
- 작성 내용·기획·관련 작업 기준·앞선 실제 적용 기록이 바뀌면 결과는 재확인으로 이동한다. 이전 확인 원문은 수정 중에도 그대로 보여주고 새 확인을 명시적으로 기록할 때 갱신한다. 기본 예시 학습 기록은 취소하거나 다시 잠그지 않는다.
- `classProjectSummary`가 기존 공통 판정과 새 적용 확인의 읽기 모델을 합성한다. 범용 기록을 세부 체크포인트·기능 생략 결정·실제 배포 이벤트로 바꾸지 않는다. 기존 공통 상태와 방문 메모리 저장 방식은 유지한다.

1. **구현 완료:** 자기 프로젝트에서 부탁한 파일만 바뀌었는지, 화면과 버튼이 원하는 대로 나오는지 확인한 결과를 첫 제작 이후에도 연결했다. 예시 복습은 계속 허용하고 본인 적용 기록과 구분한다. 요청 초안·기록 UI의 완료이며 외부 파일 실습 완료가 아니다.
2. **안내 구현 완료:** 화면 개선과 필요한 동작의 실제 적용·재확인 안내를 연결했다. 소개 페이지에 불필요한 DB·로그인을 의무화하지 않는다. 구조·기능 범위·파일 역할 등의 상세 누락은 기존 SSOT와 대조하여 활동 배치를 정한다.
3. **안내 구현 완료:** 기존 Vercel Drop 공식 절차와 학습자의 주소·다른 기기 확인·문제 수정 본인 기록을 연결했다. 에이전트의 실제 업로드·계정 생성·유료 서비스 사용·외부 저장 구현을 자동으로 시작하지 않는다.
4. 확정된 독립 월드 구조를 학습 지점과 연결한다. 옛 8장소를 그대로 복원하거나 새 미술부터 만들지 않는다.

선택 심화의 가장 작은 제안은 ‘같은 페이지를 고칠 때 지킬 규칙을 적고 다음 요청에 재사용하기’다. 파일 범위·유지할 내용·두 폭/버튼 확인이라는 세 조건을 편집하고 일회성 요청과 비교한다. 도구가 자동으로 규칙을 저장한다고 약속하지 않는다. 스킬·MCP·자동화는 차이와 사례를 설명하는 후속 선택 활동으로 남긴다. 이 제안은 아직 새 단원 구현이나 상세 순서 확정이 아니다.

## 검증 범위

후속 적용 기록 연결의 최신 검증은 [단원 기록](workbook-project-application.md)을 따른다. 최종 워크북10 PASS57.6초, 디자인 보정 후 영향2 PASS34.6초, check7파일14 PASS. PC/모바일 공통 UI 검수와 자원 정리를 마쳤다. 외부 결과는 본인 입력이며 자동 검증이 아니다. 아래는 최초 정적 감사 당시의 이력이다.

직전 실제 검증은 워크북 선택 E2E 10 PASS(57.1초), 공개·운영 문구 보정 후 PC/모바일 영향 흐름 2 PASS(32.6초), Node22.14 `pnpm check` 7파일·14테스트 PASS다. PC/모바일 정상 경로 디자인 검수와 자체 코드 리뷰를 마쳤다. 초기 기능 실패는 없었다. 수정 후에도 ‘연습용 결함’으로 남던 제목을 ‘수정한 예시’로 고쳤고 API 키의 짧은 정의·사례를 본문에 추가했다.

이번 완료 기준 대조는 문서·라우트·컴포넌트의 정적 검토다. 새 브라우저·E2E·성능 검사를 실행하지 않았다. 전체 사이트 E2E, 실제 외부 설치·파일 제작·공개·DB/API 검증은 미실행이다. 자체 서버·IAB·테스트 Chrome 종료 및 3211 리스너 닫힘은 직전 마감에서 확인했다. 전체 클래스 완성 판단·커밋·푸시·병합·배포는 남겨 둔다.

## 후속 정정 — 기존 강의 보강과 정책 결정 구분

기존 내용·쉬운 문구·플레이풀 상호작용은 승인된 개선 범위이며 ‘상세 강의 범위 합의’로 일괄 중단하지 않는다. 사용자 정책 결정은 단원 보상 대응·포인트 용도/가치·계정 기록/로그인 전 처리 세 가지다. [현재 내용 대조와 검증 준비물](workbook-content-audit-and-pilot.md)에서 이미 해결된 공백을 제외했고 실제 Windows/Mac 실습은 여전히 미검증으로 남겼다. 이번은 읽기/문서 감사이며 동일 기능 검사를 반복하지 않았다.
