# 동작과 데이터 · 한 줄 메모로 표시와 저장 구분하기

2026-10-09 후속: 사용자 승인으로 [고산 마을의 독립 지도3지점](workbook-world-3-implemented-map.md)을 연결 중이다. 정적/CPU 준비 완료이며 기능·PC모바일 실제 검수는 조율 차례 대기다. 아래 새 지도 없이 연결한 내용은 최초 최소 단원의 이력이다.

4+1 구조의 ‘동작과 데이터’ 첫 단위다. 선행 조건은 AI 입문·첫 제작·화면과 사용 경험의 완료다. 같은 홈페이지 제목·소개·내용과 기존 CSS 미리보기를 이어 받는다. 지도 원화를 추가하지 않고 첫 맵 완료 기록의 다음 단원 버튼으로 연결한다.

## 학습 결과와 흐름

1. 입력창에 한 줄을 적으면 바로 소개 페이지에 나올지 예측하고 ‘화면에 표시하기’를 누른다. 입력창의 값과 버튼 후 표시되는 문장의 차이를 읽는다.
2. 저장하지 않고 새로고침하면 문장이 남을지 예측하고 새로고침을 흉내 낸다. 문장을 브라우저 저장에 넣는 흉내 후 다시 새로고침해 전후를 비교한다.
3. 다른 기기에서도 같은 문장이 보일지 예측하고 다른 기기 예시를 연다. 같은 브라우저에만 저장되는 것과 여러 사람이 함께 읽는 데이터를 구분한다. 친구가 다른 컴퓨터에서 쓴 답장을 함께 읽는 경우 서버가 필요함을 고르고 이유를 적는다.

## 완료와 기록

예측은 정답으로 입장을 제한하지 않는다. 버튼 후 결과와 이유를 읽게 한다. 화면 표시, 저장 없는/있는 새로고침, 다른 기기 결과를 모두 확인하고 서버가 필요한 사례를 고른 뒤 비교 이유를 적으면 완료다. 이전·취소·지도/이야기 왕복·완료 재방문에 이번 방문 기록을 유지한다. 같은 버튼 반복 클릭은 비교 원문을 지우지 않는다. 앞 홈페이지 기획이 바뀌면 후속 기록도 초기화한다. 선행 화면 단원을 다시 수정하면 동작 단원은 잠시 잠기고 선행 완료 후 기존 기록을 이어 본다.

## 시뮬레이션 경계

이 단원 안의 브라우저 저장·새로고침·다른 기기는 모두 React 메모리로 만든 학습 예시다. 실제 localStorage·파일·회원 DB·외부 API를 쓰지 않는다. 워크북 페이지를 실제 새로고침하면 이 방문의 작성과 진행 기록은 초기화된다. 플랫폼의 회원별 서버 진행 저장은 미래 연동 계획이며 이 수업의 저장 개념 설명으로 구현하지 않는다. 로그인·DB 만들기는 필수 과제가 아니다. 실제 서버 연결과 권한·서비스 설정은 후속 범위다.

## 2026-10-15 · 입문자의 조작 순서와 저장 경계

입력은 ‘예시에 표시할 한 줄’로 표시하고 내 기획을 담은 예시의 메모라고 설명한다. 각 단계의 실습 위치/실제 파일 적용 차이를 제공한다. 실제 브라우저 새로고침을 누르면 학습 기록을 잃을 수 있어 저장 비교는 수업의 ‘새로고침 흉내 내기’ 버튼을 사용한다고 단계 바로 앞에 명시했다. 진행 안내는 예측→입력→표시, 저장 전 새로고침 흉내→저장 흉내→저장 후 새로고침 흉내, 다른 기기→서버 판단→이유 기록의 남은 행동을 보여준다. 실제 저장/기기 연결 없이 기존 메모리 시뮬레이션과 완료 조건을 유지한다. 실제 적용 요청은 필요한 입력/표시 동작만 별도 파일에서 확인하며 저장·로그인 연결 완료를 추정하지 않는다.

## 자기 초안의 상세 보기·저장 판단 보강 원고 — 2026-10-20

승인된 프로젝트 연계 방향을 반영한 4단원 후속 원고다. 위 메모 시뮬레이션·필수 저장 비교·현재 완료 판정은 구현 이력으로 보존한다. 아래는 자기 프로젝트 중심의 목표 원고이며 코드·화면·판정·저장 구조에 아직 적용하지 않는다. 공통 예시의 학습 확인과 자기 파일의 실제 결과를 구분한다.

### 도입 — 방문자에게 필요한 동작을 골라요

앞 단원에서 같은 초안을 PC와 모바일 폭으로 살펴봤어요. 이번에는 **관심 있는 항목을 골라 자세히 읽을 필요가 있는지**, 그 선택을 다시 방문할 때도 남길 필요가 있는지 판단해요.

기능이 많아야 좋은 페이지가 되는 것은 아니에요. **필요한 동작은 적용하고, 필요 없는 동작은 이유를 남겨 생략**해요. 지금까지 만든 같은 폴더와 실제 내용을 이어가요. 로그인·댓글·결제·여러 사람의 데이터를 함께 저장하는 서버는 이번 기본 과제에서 만들지 않아요.

### 활동 1 — 자세히 볼 내용이 필요한가요?

**공통 사례로 원리 확인**

카피바라 쉼 모음에서 활동을 고르면 그 활동의 방법과 준비물이 보여요. 다른 활동을 선택하면 해당 설명이 나오고, 펼친 설명을 접으면 목록을 다시 볼 수 있어요. 선택에 따라 달라지는 정보를 **상태**, 그 상태에 맞춰 보이는 내용을 **표시**라고 생각해봐요. 글자 입력도 입력의 한 종류지만, 항목을 누르는 선택도 화면을 바꾸는 입력이 될 수 있어요.

이것은 원리를 익히는 공통 사례예요. 예시를 눌렀다고 내 파일에 동작이 생긴 것은 아니에요.

**자기 초안에서 필요 판단**

페이지의 목적과 실제 내용을 다시 읽어요. 처음부터 꼭 보여야 할 요약은 남겨두고, 관심 있는 사람이 더 읽을 설명이 있는지 살펴봐요.

| 내 페이지             | 처음부터 보여줄 내용                      | 선택해서 더 볼 수 있는 내용              |
| --------------------- | ----------------------------------------- | ---------------------------------------- |
| 서비스 소개           | 도울 사람·실제 제공 내용의 요약·다음 행동 | 제공 범위·준비 자료·제외 내용            |
| 포트폴리오            | 작업명·요약·내 역할                       | 문제·해결 과정·결과·배운 점              |
| 개인 추천 모음        | 항목명·짧은 추천 이유                     | 사용 상황·직접 겪은 장단점·관련 정보     |
| 짧은 소개나 단일 작업 | 짧은 본문 전체                            | 추가로 나눌 설명이 없으면 상세 보기 생략 |

핵심 내용을 접힌 설명 안에 모두 숨기지 않아요. 여러 설명을 비교하며 읽어야 한다면 함께 열리게 해도 좋아요. 별도 팝업보다 페이지 안에서 펼치는 방식으로 충분한지 먼저 생각해요. 검색·필터·새 페이지를 기능 수를 늘리기 위해 추가하지 않아요.

#### 상세 보기가 필요하면 — 같은 파일에 적용

> 현재 my-first-web의 페이지와 연결된 파일을 먼저 읽어줘. [항목 목록]에서 항목별 [추가 설명]을 페이지 안에서 펼쳐 볼 수 있게 해줘. 항목명·요약·주요 행동은 처음부터 보이게 유지해줘. 각 항목을 열면 해당 설명이 나오고 다시 접을 수 있게 해줘. 마우스·터치·키보드로 조작할 수 있고 열림 상태를 알 수 있게 해줘. 기본 HTML 기능으로 충분하면 그 방식을 사용해줘. 기존 내용과 링크 목적지는 유지하고, 아직 저장·로그인·외부 서비스는 추가하지 마. 다른 파일 변경이 필요하면 이유와 범위를 먼저 알려줘.

대괄호는 실제 항목과 설명으로 바꾼다. 같은 프로젝트의 기존 구조를 이어가고 다른 파일 내용을 무조건 HTML 하나로 합치지 않는다. 이미 상세 보기가 잘 동작하면 다시 만들지 않고 아래 확인으로 넘어간다.

**확인할 행동**

1. 같은 실제 파일을 브라우저에서 새로고침하고 항목을 열어요. 제목과 설명이 같은 항목인지 읽어요.
2. 접기 또는 다른 항목 선택을 해봐요. 설명을 닫아도 요약과 주요 행동을 찾을 수 있는지 확인해요.
3. 넓은 화면과 모바일 폭에서 내용이 잘리지 않는지 확인하고 기존 주요 링크·버튼을 다시 눌러봐요.
4. 키보드의 Tab으로 조작에 접근하고 기본 펼침의 Enter·Space 등 해당 조작으로 열고 닫을 수 있는지 확인해요.

두 번째 항목이 실제로 있을 때만 항목 간 내용 대응을 비교한다. 항목 수를 늘리기 위해 가짜 내용을 만들지 않는다. 키보드가 작동하지 않거나 설명이 잘못 연결되면 해당 관찰을 전달해 같은 파일에서 고치고 다시 확인한다.

#### 상세 보기가 불필요하면 — 생략 이유

> 작업이 하나이고 설명도 짧아서 처음부터 모두 읽을 수 있어요. 내용을 숨기면 한 번 더 눌러야 하므로 상세 보기를 추가하지 않아요.

이유는 **방문자의 필요와 현재 내용으로 충분한 근거**를 포함해요. 위 문장을 확인 없이 복사할 필요는 없어요. 자기 화면에서 핵심 내용과 주요 행동을 찾을 수 있는지 확인했다면 기능을 추가하지 않아도 괜찮아요. 공통 사례의 원리는 익히되 자기 파일에서 불필요한 수정 요청을 만들지 않아요.

### 활동 2 — 새로고침 뒤에도 남길까요?

**화면 변화와 저장의 차이**

지금 설명을 펼칠 수 있다는 것과 다시 열었을 때 같은 선택이 남는 것은 다른 일이에요. 펼친 상태를 새로고침 때 초기화해도 읽는 데 문제가 없다면 저장하지 않아도 돼요.

다음 순서로 물어봐요.

1. 방문자가 나중에 돌아와 **같은 선택을 다시 찾을 이유**가 있나요?
2. 그 선택이 **이 브라우저에만 남아도 충분**한가요?
3. 저장하려는 것이 비밀번호·연락처 같은 민감한 내용이 아닌 **단순한 개인 선택**인가요?

| 선택                         | 맞는 상황                                                | 확인할 기대 결과                                           |
| ---------------------------- | -------------------------------------------------------- | ---------------------------------------------------------- |
| 저장하지 않기                | 읽는 동안만 설명을 펼치면 충분함                         | 새로고침 뒤 접혀도 본문·상세 설명을 다시 볼 수 있음        |
| 관심 항목만 저장             | 추천 목록에서 나중에 볼 항목을 다시 찾고 싶음            | 관심 표시·해제 각각이 같은 브라우저에서 새로고침 뒤 반영됨 |
| 서버 기능을 별도 범위로 남김 | 문의 전달·신청 접수·여러 사람의 답장·기기 간 동기화 필요 | 이번 브라우저 저장으로 전달·공유됐다고 표시하지 않음       |

상세 보기와 관심 표시는 서로 다른 행동이에요. 설명을 열었다고 자동으로 관심 항목에 넣을 필요는 없어요. **저장 생략은 상세 보기 생략과 따로 판단**해요.

#### 저장이 필요하면 — 관심 선택만 적용

> 같은 프로젝트에서 [관심 표시가 필요한 항목]을 나중에 다시 찾도록 관심 추가·해제를 만들어줘. 저장할 것은 항목을 구분할 값과 관심 선택뿐이고, 이 사이트의 같은 브라우저에서 새로고침 뒤 복원되면 돼. 설명을 펼치는 상태와 관심 선택은 구분해줘. 관심 해제도 저장에 반영하고, 저장을 사용할 수 없어도 본문과 상세 보기는 이용할 수 있게 해줘. 로그인·서버·기기 간 동기화·개인정보 입력은 추가하지 마. 기존 내용과 주요 행동을 유지하고 변경 파일과 확인 방법을 알려줘.

필요하다고 판단한 사람만 사용하는 요청 예시다. 이름만 있는 기능이나 저장 성공 문구 대신 실제 결과를 확인한다.

1. 항목 하나를 관심 항목으로 표시하고 **자기 사이트가 열린 브라우저 탭**을 새로고침해 유지되는지 확인해요.
2. 관심 표시를 해제하고 다시 새로고침해 해제 상태도 남는지 확인해요.
3. 설명 펼침·본문·기존 링크를 다시 확인해요. 가능하면 저장을 사용할 수 없는 환경에서도 본문과 상세 보기를 이용할 수 있는지 확인해요. 확인하지 못한 조건은 남겨둬요.

실습 파일을 연 탭과 워크북 수업 탭을 구분한다. 현재 워크북을 새로고침하면 방문 진도가 초기화되므로 수업의 시뮬레이션은 기존 ‘새로고침 흉내’ 조작을 유지한다. 이 원고의 실제 새로고침은 별도로 연 자기 사이트에서 수행한다.

#### 저장이 불필요하면 — 생략 이유

> 서비스 내용을 읽는 동안 설명을 열면 충분해요. 다음 방문에 다시 찾을 개인 선택이 없어서 저장하지 않아요.

저장할 이유가 없다면 관심 표시도 새로 만들지 않아요. 새로고침 뒤 초기 상태로 돌아가도 필요한 내용과 행동을 이용할 수 있는지 확인해요. 상세 보기·저장을 모두 생략했다면 두 판단을 짧게 함께 설명할 수 있고 같은 내용을 반복 입력할 필요는 없어요.

### 활동 3 — 다른 기기에서는 무엇을 기대할까요?

내 페이지의 글·이미지·상세 보기 코드는 배포할 파일에 들어 있어요. 방문자가 고른 관심 항목은 그 사람이 사용하는 브라우저에 남을 수 있어요. **페이지를 공개하는 것과 방문자의 개인 선택을 함께 공유하는 것은 다른 일**이에요.

- 저장 없음: 다른 기기에서도 공개된 내용을 읽고 상세 보기를 조작할 수 있어야 해요. 내 기기에서 열어둔 설명까지 옮겨갈 필요는 없어요.
- 관심 선택 저장: 다른 기기에서 내 관심 표시가 그대로 보이지 않아도 예상한 결과예요. 그 기기에서 새로 고른 선택은 해당 브라우저를 기준으로 확인해요.
- 여러 사람이 함께 볼 정보: 문의·답장·공유 기록이라면 브라우저 저장만으로 상대에게 전달되지 않아요. 서버와 접근 권한이 필요한 요구임을 구분하고 이번 기본 과제 밖에 남겨요.

브라우저 저장은 영구 보관이나 회원 진도 저장이 아니에요. 데이터를 지우거나 브라우저·기기·도메인이 달라지면 같은 선택이 이어지지 않을 수 있어요. 로컬 파일에서의 저장 동작은 브라우저 환경에 따라 다를 수 있으므로, 지금 확인한 범위만 기록하고 **5단원의 실제 공개 주소에서 저장·해제를 다시 확인**해요. 공개가 로컬 선택을 자동 이전해주지는 않아요.

지금 실제 다른 기기를 준비하거나 서버를 만들 필요는 없어요. 이 활동에서는 기대 결과를 설명하고, 실제 공개·다른 기기 접속은 다음 단원으로 넘겨요.

**시도 기록과 목표 결과 확인은 구분**한다. 문제를 적거나 에이전트가 완료했다고 말한 것만으로 성공 판정하지 않는다. 외부 결과는 본인 확인이며 캡처·자동 검사·인증을 요구하지 않는다. 생략 분기는 원리 학습과 근거 있는 필요 판단으로 인정하며 적용하지 않은 기능의 성공 기록을 만들지 않는다.

상세 정보를 어떻게 읽게 할지, 방문자의 선택을 남겨야 할지 판단했어요. 기능을 넣었다면 동작과 범위를 확인했고, 넣지 않았다면 **왜 지금은 필요 없는지** 설명할 수 있어요.
