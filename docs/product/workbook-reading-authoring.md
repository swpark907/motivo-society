# 워크북 에디토리얼 문서 v1

2026-10-16. 내부 기술명은 **에디토리얼 문서 스키마**, 관리자 화면의 제품명은 **아티클 편집기**로 제안한다. DSL이라고 불러도 되지만 작성자는 ‘글과 배치를 담는 문서’로 이해하면 된다.

## 현재 정본과 역할

- 정본: `content/drafts/workbook/*.json`의 여섯 테스트 글. 기존 MDX를 이 형식으로 이관했다.
- 런타임 스키마: `src/lib/content/workbook-editorial-schema.ts`.
- AI에게 전달할 JSON Schema: `content/schemas/workbook-editorial-v1.schema.json`.
- 렌더러: `src/components/EditorialArticle/`의 공통 렌더러·SCSS. 글별 slug로 디자인을 분기하지 않는다.
- 스키마를 고쳤으면 `pnpm content:editorial-schema`로 기계용 명세를 갱신한다. 테스트가 두 명세의 일치를 확인한다.

글에는 임의 JSX·HTML·CSS·JavaScript를 넣지 않는다. JSON을 검증한 뒤 등록된 컴포넌트로 렌더링하며 코드를 컴파일하지 않는다. `version: 1`이 해석 기준이다. 새 형식이 필요해지면 명시적으로 버전과 마이그레이션을 설계한다.

## 문서는 표지와 본문 블록의 조합

`layout`은 note·feature·guide 중 글의 성격이다. **긴 가이드만** 소제목이 둘 이상일 때 접이식 TOC가 나온다. 표지 배치는 독립적인 `cover.layout`으로 정한다. 긴 가이드도 분할 표지를 쓸 수 있다.

| 선택 영역 | 제공하는 배치                                                                                       |
| --------- | --------------------------------------------------------------------------------------------------- |
| 표지      | title-first(제목→사진), image-first(사진→제목), split(제목·사진 좌우), compact(작은 사진·제목 좌우) |
| 표지 제목 | 왼쪽·가운데 정렬, 짧은 제목 1~3줄, 별도 도입 문구                                                   |
| 본문 폭   | reading(40rem), wide(45rem), full(본문 편집 면의 전체 폭)                                           |
| 텍스트    | 기본·큰 도입문·작은 보조문·잡지 2단·드롭캡, 왼쪽·가운데 정렬                                        |
| 사진      | 16:9·정사각·4:5, 초점 왼쪽·가운데·오른쪽, 장면·확대 크롭                                            |
| 사진+글   | 이미지 좌·우, 1:1·이미지 넓게·글 넓게, 위·가운데 맞춤                                               |
| 인용      | 선으로 구분·큰 문장·큰 따옴표·여백 인용, 왼쪽·가운데 정렬                                           |
| 비교      | 2~3개 항목의 나란히·세로·명암 대비·항목 대조                                                        |
| 요점·순서 | 한 줄씩·2열 그리드·큰 번호 단계·타임라인·체크리스트                                                 |

`full`은 화면 전체가 아니라 종이 본문의 안쪽 편집 영역이다. 모바일에서 다열은 읽는 순서대로 단일 열로 바뀐다. 사진+글은 항상 사진→글 순서로 접으며 PC의 이미지 좌·우 설정은 내용의 읽기 순서를 바꾸지 않는다. 임의 픽셀·폰트·색 대신 의미 있는 선택지만 제공한다.

## 지원하는 블록 9개

- `text`: `text`, `tone`, `width`, `align`. 일반 문단과 큰 도입문.
- `callout`: `text`, 선택 `label`, `layout`, `width`, `align`. 작성자의 핵심 메모.
- `qa`: 1~8개의 `items: [{question, answer}]`, `layout`, `width`. 질문과 답변.
- `heading`: `text`. TOC로 연결할 소제목. `id`가 URL 앵커다.
- `image`: `image`, `width`. 사진과 캡션.
- `quote`: `text`, 선택 `label`, `layout`, `width`, `align`.
- `compare`: 2~3개의 `items: [{label, text}]`, `layout`, `caption`, `width`.
- `list`: 2~8개의 `items: [{title, body}]`, `layout`, `width`.
- `split`: `image`, `content`, `imageSide`, `proportion`, `verticalAlign`, `width`.

모든 블록은 글 안에서 유일한 `id`를 갖는다. `split.content`에는 text·heading·quote·list·callout·qa만 넣고 배치 안에 다시 배치를 중첩하지 않는다. heading id는 글 내부 링크이므로 발행 후 바꾸지 않는다. 공유 UI가 쓰는 id와 중복되면 검증에서 거부한다.

`text`·`quote.text`·목록 body·비교 text 안에는 **굵게**, `인라인 코드`, `[링크](https://...)` 표기만 해석한다. 전체 Markdown이나 MDX가 아니다. 새 문단은 빈 줄로 구분한다. HTML·표현식·지원하지 않는 Markdown은 코드로 실행하지 않고 일반 문자열로 보여준다. 링크는 HTTPS 표기만 연결한다.

사진 src는 현재 준비된 `/images/workbook/notes/`의 로컬 자산을 지정한다. 캡션은 필수다. 확대·대체 크롭도 생성 사진이 실험 증거처럼 읽히지 않게 설명한다.

## 간단한 조합 예시

다음은 문서의 `content`에 넣을 블록 예시다. 생략한 선택값에는 스키마 기본값이 적용된다.

```json
{
  "type": "split",
  "id": "question-spread",
  "imageSide": "left",
  "proportion": "image-wide",
  "image": {
    "src": "/images/workbook/notes/show-the-screen-v1.png",
    "alt": "화면의 한 곳을 짚는 손",
    "caption": "AI 생성 연출 사진 · 실제 수정 결과가 아니에요.",
    "ratio": "square",
    "focus": "right"
  },
  "content": [
    {
      "type": "quote",
      "id": "question-example",
      "layout": "rule",
      "label": "직접 써볼 요청 · 설명용 예문",
      "width": "reading",
      "align": "left",
      "text": "제목과 버튼 사이에서 답답하게 보이는 부분을 함께 살펴봐줘."
    }
  ]
}
```

전체 파일의 title·summary·slug·thumbnail·thumbnailAlt·visualCaption·tags·sources·nextTry·related는 기존 샘플을 참고한다. `displayTitle`와 `deck`은 선택이다. title·summary는 목록·OG용 전체 문구로 유지한다. related는 최대 두 편이며 실제 다른 글의 slug와 연결 이유를 지정한다.

## 여섯 샘플의 편집 의도

| 파일                           | 구성                                                                                    |
| ------------------------------ | --------------------------------------------------------------------------------------- |
| 01-describe-the-result.json    | 제목 먼저 → 큰 도입문 → 명암 대비 요청 비교 → 본문 크기의 수정 요청 예문                |
| 02-show-the-screen.json        | 좌우 분할 표지 → 사진 왼쪽·인용 오른쪽의 펼침면 → 질문·답변 좌우                        |
| 03-leave-a-handoff.json        | 작은 사진과 제목 → 네 가지 인계 항목 2열 → 넓은 장면 사진 → 일반 본문 설명              |
| 04-report-the-error.json       | 사진 먼저 → 기대·실제·재현의 세로 타임라인 → 본문 크기의 수정 요청 예문                 |
| 05-check-the-source.json       | 가운데 제목 → 글 왼쪽·세로 사진 오른쪽 → 체크리스트 → 왼쪽 요청 예문 → 옆선 핵심 메모   |
| 06-test-the-awkward-cases.json | 규칙 그리드 → 입력 대조 → 사진과 요청 예문 → 실행 타임라인 → 업무 적용과 최종 점검 통합 |

내용과 공식 근거는 기존 초안을 유지했다. 새 레이아웃·연출 사진을 실사용 검증의 근거로 쓰지 않는다. 여섯 글은 정식 발행 전 테스트 프리뷰이며 noindex·검증 전 표시를 유지한다.

## AI에게 줄 작업 지시

아래 지시는 JSON Schema와 이 문서·[구간 카탈로그](editorial-block-catalog.md)를 함께 전달한다. 샘플은 문법 참고용이며, 해당 글의 순서를 그대로 복제하는 템플릿이 아니다.

> 에디토리얼 문서 JSON 한 파일을 작성해줘. 먼저 독자가 얻을 것과 다음 행동 하나를 정하고, 설명 → 예시 → 판단 → 적용의 흐름을 내용에 맞게 설계해줘. 이 순서를 고정 공식으로 쓰지는 마.
>
> 제공된 블록·배치만 사용하고 임의 HTML·CSS·코드·새 필드는 만들지 마. layout은 글 성격, cover.layout은 표지 배치야. 일반 설명은 reading 폭과 왼쪽 정렬을 기본으로 하고, 비교·사진 등 넓게 보여줄 이유가 있을 때만 넓혀줘. 여러 레이아웃을 쓰되 종류 수를 채우기 위해 내용을 쪼개지 마. 같은 역할에는 같은 표현을 써도 돼.
>
> 요청 예문은 quote의 rule 배치, reading 폭, 왼쪽 정렬로 쓰고 ‘직접 써볼 요청 · 설명용 예문’처럼 성격을 밝혀줘. 핵심 주장은 본문 속 짧은 굵은 강조나 callout으로 표현해줘. 큰 인용(statement/pull)은 읽기를 멈출 가치가 있는 문장에 제한적으로 쓰고, 작성자 문장을 타인의 실제 발언처럼 꾸미지 마. 예문과 실제 실행 결과를 구분해줘.
>
> 출처는 글 끝에 번호 없는 text 블록(tone: small, width: reading, align: left)으로 두고, ‘**참고한 자료**’ 다음 빈 줄에 링크와 참고한 범위·편집 예시의 성격을 적어줘. 참고용 heading은 만들지 마. 본문에서 근거가 바로 필요한 주장에는 링크를 가까이 남겨줘.
>
> 짧은 한 문단에 columns를 쓰지 마. 강조 구간이 연속되면 중간 설명을 일반 본문으로 받아줘. 같은 사진의 반복은 확대해서 다른 정보를 보여주는 등 이유가 있을 때만 사용해줘. 마지막 요약·체크리스트·다음 행동이 같은 말을 반복하면 하나로 합치고, 반복을 줄이면서 고유한 판단 기준은 남겨줘. 사진은 장면 설명·캡션·AI 생성 여부를 유지해줘.
>
> id는 글 안에서 중복 없이 정하고 기존 slug·heading id는 바꾸지 마. 실제 제공된 자산과 확인한 링크만 사용하고 관련 글 연결 이유와 다음 행동 하나를 적어줘. 사용 경험·실험 결과·수치·검증 날짜를 지어내지 마. 자료가 부족하면 확인이 필요한 점을 보고해줘.
>
> 작성 후 아래 검토 항목으로 스스로 검토해 수정하고, JSON과 별도로 선택한 편집 의도·줄인 중복·아직 확인할 내용을 짧게 보고해줘. 보고 문구를 JSON의 새 필드로 넣지 마.

### AI 제출 전 검토

- 각 배치가 비교·순서·질문·장면 등 내용의 관계를 설명하는가? 모양만 바뀌는 구간은 단순화했는가?
- 요청 예문, 실제 결과, 작성자의 핵심 판단을 라벨과 표현으로 구별할 수 있는가?
- 큰 인용·비교·박스가 연속돼 모든 구간이 강조되지는 않는가?
- 다단 본문에 충분한 문단이 있는가? 모바일에서 단일 열로 읽어도 문맥이 이어지는가?
- 사진을 반복했다면 각각 새로 보여주는 정보가 있는가? 캡션이 증거와 연출을 구별하는가?
- 결론·체크리스트·다음 행동에 중복이 없는가? 합치는 과정에서 필요한 기준을 빼지는 않았는가?
- 출처는 작은 보조 영역에 남고, 링크와 주장·적용 범위가 대응하는가? 검증하지 않은 경험을 주장하지 않는가?
- 스키마에 맞는 JSON인가? id·실제 자산·관련 slug가 유효한가? PC·모바일 미리보기 검토가 필요함을 구분했는가?

## 관리자 페이지 연결 방향

현재 문서·스키마·공통 렌더러와 개발용 `/demo/admin/articles` 편집 실험실을 구현했다. 운영 관리자·인증·DB·발행·Markdown 가져오기는 후속 작업이다.

AI 문서 생성 → 검증 → 서버에 초안 저장 → 동일 렌더러로 PC·모바일 미리보기 → 검토·발행으로 연결한다. 시각 편집 버튼은 같은 JSON의 블록 순서·유형·내용·허용된 배치값을 수정한다. Markdown 가져오기를 추가하면 지원 범위만 이 구조로 변환하고 손실·지원하지 않는 문법을 미리 알려준다. Markdown과 JSON을 각각 수정 가능한 두 정본으로 두지 않는다.

관리자 초기 범위는 문구 수정·이미지 교체·블록 추가/이동/복제/삭제·배치 선택·PC/모바일 미리보기·초안 저장/발행이다. 자유 좌표 캔버스와 사이트 제작 도구로 확장하지 않는다. 정식 발행에는 기존 사람의 검증·검토 정책을 유지한다.

개발용 편집기의 구체 범위와 운영 관리자 구조 제안은 [관리자·콘텐츠 아키텍처 검토](../architecture/admin-content-architecture.md)를 참고한다.

### 미리보기 중심 편집

관리자 실험실은 구간 클릭 후 정렬·스타일 버튼을 선택하는 방식이다. 사진과 글 배치는 사진 쪽을 클릭해 전체 구간을 선택하고, 내부 문단을 클릭하면 해당 문단만 선택한다. 문구 수정은 선택한 곳에서 따로 열며 복합 콘텐츠와 메타데이터는 상단 원문 편집을 사용한다. 원문을 열면 캔버스 변경을 잠시 막아 서로의 변경을 덮어쓰지 않는다.

구간 종류 9종과 문자 중심 표현24종의 용도·JSON 예시는 [에디토리얼 구간 카탈로그](editorial-block-catalog.md)를 따른다. 종류 전환은 내용을 보존하되 문맥을 재검토하며, 사진 구간을 손실시키는 변환은 제공하지 않는다.

### 선택지 미리보기와 구간 추가

종류·스타일·정렬·폭·사진 배치 선택 버튼에는 작은 SVG 구도 미리보기를 함께 표시한다. 도식은 문서에 저장하지 않는 편집 보조 UI이며 실제 글은 공통 렌더러로 확인한다. 편집기 상단은 제목·샘플·도구 위주로 압축하고, 공개 메뉴는 해당 개발 편집기에서만 숨긴다.

본문의 첫 구간 앞, 모든 최상위 구간 사이, 마지막 구간 뒤의 `+`로 9종 요소를 추가한다. 넣는 위치는 앞 구간의 고유 ID로 기억하고, 위치가 사라졌거나 최대80개에 도달하면 추가를 막는다. 새 요소는 예시 문구로 시작하며, 사진 요소는 현재 글의 표지 자산을 재사용한다. 추가한 직후에는 ‘추가 되돌리기’를 제공한다. 사진과 글 내부의 중첩 요소 추가는 이번 범위가 아니다.

선택 요소 바깥의 빈 여백이나 부모 편집기 영역을 클릭하면 선택·추가 팝업이 닫힌다. 다른 요소를 누르면 선택을 바꾼다. 미적용 문구는 방문 중 구간별로 임시 보관하여 다시 선택하면 복원하며, 명시적으로 취소하거나 유효하게 적용하면 보관본을 지운다. 브라우저 임시 저장을 통해 새로고침 후에도 복원한다.

선택·요소 추가 팝업의 헤더는 내부 스크롤 상단에 고정한다. 제목과 닫기 버튼은 항상 보이며, 헤더 아래의 옵션만 스크롤된다.

편집기 상단은 관리자 복귀·글 선택·PC/모바일 전환·테스트 배지·원문·내보내기·더보기의 한 줄로 구성한다. 별도 제목과 안내 행은 표시하지 않는다. 모바일에서는 글 선택과 화면 전환을 유지하고 원문·내보내기·초기화·안내는 더보기에 둔다. 헤더 아래 남은 높이를 편집 캔버스에 사용한다.

편집기 높이는 100dvh 셸의 flex 남은 영역으로 정한다. 화면 상단 좌표를 빼는 추정 계산이나 모바일 미리보기의 고정 높이 상한을 두지 않고, 실제 캔버스 크기를 ResizeObserver로 읽어 배율을 적용한다. 원문 패널은 자체 스크롤하며 캔버스를 화면 밖으로 밀어내지 않는다.

종류를 고르면 기존 팝업 목록을 변경 확인 화면으로 교체한다. 선택한 종류로 변환한 실제 문장을 공통 렌더러로 보여준다. 적용 버튼은 미리보기에 사용한 동일한 변환 문서를 반영한다. 상단의 ‘종류 목록’은 변경 없이 목록으로 복귀하고, 하단의 적용·취소 버튼은 스크롤 본문과 분리해 항상 보인다. 적용 후에는 종류 목록을 접고 해당 구간의 스타일 편집으로 돌아간다.

내용이 한 문단뿐이어도 별도 준비 화면으로 나누지 않고 변경 확인 화면에서 바로 수정한다. ‘나눌 내용’에 빈 줄로 구분한 두 개 이상의 내용을 입력하면 실시간 미리보기가 나타나고, 유효해질 때만 변경 버튼을 활성화한다. 나누는 중의 문구도 최종 종류 변경 적용 전에는 본문에 반영하지 않는다. 사진을 포함한 구간은 ‘사진 모양 바꾸기’로 현재 비율·위치 옵션을 바로 열고, 텍스트에 사진을 넣고 싶으면 ‘아래에 사진 추가’로 원문 뒤에 요소를 추가한다. 사진 옆의 내부 글을 비교로 바꾸려는 경우에는 사진 구간 아래에 비교를 추가한다.

비교·문답·목록 구간을 선택하면 ‘제목·내용 수정’으로 항목 제목과 본문, 질문과 답변, 비교 설명을 직접 편집한다. 필요한 구간의 입력란만 연다. 변경 확인 화면에서도 같은 입력란을 펼칠 수 있고 수정이 즉시 미리보기에 반영된다. 필수 값이 비거나 공백뿐이면 적용을 막는다. 기존 구간의 내용 편집을 바깥 클릭으로 닫으면 방문 중 임시 보관하고, 다시 선택했을 때 복원한다.

내용을 수정할 때만 팝업을 넓힌다. PC에서는 입력 40%·미리보기 60%로 나누고 각 영역을 독립적으로 스크롤한다. 작은 화면과 모바일 캔버스에서는 ‘내용 수정 / 미리보기’ 탭으로 전환하며 입력 상태를 유지한다. 종류 변경에서 내용을 나누거나 제목을 수정할 때도 같은 작업 영역을 쓴다. 헤더와 하단 적용·취소 버튼은 스크롤 영역 밖에 둔다.

구간 미리보기는 개발 전용 `/demo/editorial-block-preview`에서 공통 렌더러를 실제 1200px iframe 너비로 실행한 뒤 가용 공간에 맞춰 축소한다. 좁은 입력 패널 때문에 PC 레이아웃이 모바일 배치로 바뀌지 않는다. 동일 출처의 부모 프레임 메시지만 받고 문서 스키마를 검증하며, 적용 전에는 원본 문서를 바꾸지 않는다. 해당 경로는 운영 환경에서 열리지 않고 검색 색인을 허용하지 않는다.

구간 미리보기는 전체 맞춤이 기본이며 확대·축소, 100%, 전체 맞춤 버튼을 제공한다. 확대는 문서 레이아웃 너비를 바꾸지 않고 표시 배율만 변경하며, 미리보기 내부에서 가로·세로로 스크롤한다. 배율 변경은 문서에 저장하지 않는다.

확대 미리보기는 마우스 왼쪽 버튼으로 잡아 끌어 가로·세로 이동한다. 포인터 캡처로 영역 밖에서 놓아도 드래그가 끝난다. 모바일은 브라우저의 기본 터치 스크롤을 사용하며, 미리보기 iframe이 제스처를 가로채지 않도록 한다. 키보드 스크롤도 유지한다.

ミ리보기 영역 안에서 Ctrl+휠과 두 손가락 핀치로 10~200% 배율을 조절한다. 해당 영역의 제스처만 처리하고 일반 휠·한 손가락 스크롤은 유지한다. 포인터·핀치 중심을 기준으로 스크롤 위치를 보정한다.

## 통합 내용 수정과 문서 기록 — 2026-10-16

모든 내용 수정은 ‘내용 수정’으로 열고 같은 PC 좌우·작은 화면 탭 작업 영역을 사용한다. 문단·소제목·인용·메모·표지 제목은 문구 입력, 비교·목록·문답은 항목 입력, 사진·사진과 글은 사진 설명과 캡션 입력을 제공한다. 사진 옆의 각 글은 해당 내부 구간을 선택해 수정한다. 모든 적용 버튼은 하단에 고정한다.

상단에는 샘플 원본 / 편집 중(미적용 내용) / 문서에 반영됨·파일 보관 필요 / 내보냄·서버 저장 아님을 구분한다. 바깥 클릭으로 보관된 미적용 초안이 있으면 구간 재선택 후 적용·취소를 안내하고 내보내기와 문서 실행 취소를 막는다. 실제 서버 저장·브라우저 영속 저장을 의미하지 않는다.

실행 취소·다시 실행은 부모 편집기의 글별 문서 기록으로 통합한다. 내용·배치·종류·추가·복제·이동·유효한 JSON 적용·샘플 초기화를 같은 기록으로 관리한다. 새 변경은 redo 기록을 비우고 최근100개를 유지한다. Ctrl/Cmd+Z와 Ctrl/Cmd+Shift+Z를 제공하며 입력창 안에서는 브라우저의 텍스트 실행 취소가 우선한다. 미적용 입력이나 원문 편집 중에는 문서 기록 이동을 막아 초안을 버리지 않는다.

## 항목 구성과 읽기 화면 — 2026-10-16

비교·문답·목록의 내용 수정 화면에서 항목을 추가·삭제하고 위아래로 이동한다. 문서 스키마를 유지해 비교2~3개, 문답1~8개, 목록2~8개로 제한하고 경계의 버튼을 비활성화한다. 추가한 입력란은 비워 두며 필수 내용을 채워야 적용할 수 있다. 이동·삭제 후에도 항목의 제목과 본문은 한 쌍으로 유지하고 해당 위치의 입력란에 초점을 옮긴다. 작업은 미적용 초안에 반영되며 ‘내용 적용’ 시 문서 이력에 한 번 쌓인다.

상태 줄의 ‘읽기 화면’은 같은 글에서 추가 버튼·선택선·팝업을 숨긴다. PC·모바일 너비 전환은 유지하고 ‘편집으로 돌아가기’로 복귀한다. 읽기는 마지막으로 적용한 문서를 보여주며 미적용 초안을 자동 적용하거나 버리지 않는다. 편집으로 돌아가 구간을 재선택하면 초안을 복원한다. 서버 저장·발행·공유 기능은 추가하지 않는다.

## 구간 목록과 수정 위치 — 2026-10-16

상태 줄의 ‘구간 목록’으로 필요할 때만 탐색 패널을 연다. 표지·본문 구간의 현재 순번, 종류, 짧은 내용 미리보기를 표시하며 사진과 글의 내부 구간은 하위 번호로 구별한다. 검색은 마지막으로 적용한 문서의 전체 문구·항목 내용·종류·순번을 대상으로 한다. 보이는 미리보기 문구만으로 검색 범위를 제한하지 않는다.

목록에서 구간을 누르면 해당 구간의 시작으로 이동하고 편집 모드에서는 선택·수정 도구를 연다. 읽기 모드에서는 이동만 하며 편집 표시를 만들지 않는다. 이동 중 미적용 초안을 유지하고 같은 구간으로 돌아오면 복원한다. 목록은 선택·바깥 클릭·미리보기 조작·닫기·Esc로 닫으며 Esc는 목록 버튼으로 초점을 돌려준다. 글 전환 시에는 목록을 닫고 현재 문서로 다시 구성한다.

수정 도구의 고정 헤더에는 ‘4번째 구간 · 비교’처럼 현재 위치를 표시한다. 순서는 문서 배치에서 계산하고 실제 탐색은 변경되지 않는 구간 ID로 연결한다. 표지는 본문 순번에서 제외한다.

## 적용할 수 없는 이유 안내 — 2026-10-16

내용 수정과 종류 변경의 비활성 적용 버튼은 ‘답변2를 입력해주세요’, ‘항목1 제목을 입력해주세요’, ‘사진 설명을 입력해주세요’처럼 문서 검증 경로를 사용자에게 보이는 입력 이름으로 변환해 이유를 설명한다. 고정 하단 영역에 먼저 확인할 두 곳과 추가 누락 개수를 표시하고, 각 구조화 입력란 아래에는 해당 필드의 안내를 표시한다. 미리보기 탭에서도 하단 이유는 유지한다.

공백만 있는 필수 값도 누락으로 취급하고, 내용을 채우면 안내·비활성 상태를 함께 갱신한다. 선택 입력을 비워 두는 것은 오류로 취급하지 않는다. 단순 문구·표지 제목의 빈 줄·사진 설명·비교 설명도 구별한다. 내용 나누기 단계는 질문·답변 또는 두 내용 사이의 빈 줄이 필요하다는 행동 안내를 제공한다. 적용 버튼과 오류 입력은 aria-describedby로 안내를 연결하고 누락 입력은 aria-invalid로 표시한다.

비활성 적용 사유 중 입력 대상이 있는 안내는 점선 밑줄 버튼으로 제공한다. 누르면 해당 작업 영역의 ‘내용 수정’ 탭을 열고 입력란을 보이도록 스크롤한 뒤 포커스한다. PC에서는 같은 입력 영역 안에서 이동한다. 제목·항목 본문·문답·사진 설명·비교 설명·내용 나누기 모두 문서 검증 경로와 입력 키를 연결하며, 문구를 비교해서 대상을 추측하지 않는다. 입력란 아래의 개별 안내도 해당 입력으로 포커스를 돌려준다. 이동은 초안·배율·문서 적용 상태를 바꾸지 않는다.

## 새 글·불러오기·기본정보 — 2026-10-16

상단 도구에서 ‘새 글’, ‘JSON 불러오기’, ‘글 기본정보’를 열 수 있다. 작은 화면에서는 더보기 안에 둔다. 기본정보 입력은 별도 창에만 표시하고 헤더·적용 버튼을 고정한다. 제목·소개글·태그·글 형식을 먼저 보여주고 표지용 제목/소개글, 사진 설명, 출처 URL, 다음 실험, 관련 글은 필요할 때 펼친다. 표지 제목을 별도로 설정하지 않으면 목록·공유용 제목과 같은 값을 사용한다. 기존 주소는 읽기 전용이다. 기본정보 적용은 한 번의 실행 취소로 복원한다.

새 글은 고유한 주소와 기본 문단으로 시작하며 기존 제공 사진을 임시 표지로 사용한다. 불러오기는 16MB 이하 JSON을 데이터로 파싱하고 스키마·제공 사진 목록·관련 글 연결을 검증한다. 같은 주소가 있으면 기존 문서를 변경하지 않고 새 주소를 요구한다. 불러온 글과 새 글 모두 기존 구간 편집·미리보기·내보내기를 사용한다. 독립 미리보기는 서버가 제공한 사진 목록을 별도로 검증하며 부모 편집기가 전체 문서 간 연결을 검증한다. 브라우저에 자동 임시 저장하며 JSON 파일로도 보관할 수 있다.

구간 편집창을 여는 행위 자체는 미적용 상태가 아니다. 문구·구조화 항목이 적용된 문서와 다를 때만 초안으로 표시하며, 수정 후 원래 값으로 돌아오면 표시를 해제한다. JSON 원문도 원래 문자열로 되돌리면 미적용 표시를 해제한다.

## 구간 복제·삭제·순서 — 2026-10-16

본문 구간 선택 도구 상단에서 ‘위로 이동’, ‘아래로 이동’, ‘구간 복제’, ‘구간 삭제’를 제공한다. 작은 화면은 두 열로 배치한다. 복제는 같은 부모 안의 바로 다음 위치에 놓고 복제본을 선택한다. 사진과 글을 통째로 복제하면 내부 글에도 새 ID를 부여해 독립 편집·구간 탐색을 유지한다. 삭제하면 다음 구간 또는 이전 구간을 선택한다. 이동은 같은 부모의 이웃과 순서를 교환하고 선택 ID를 유지한다.

모든 구간 정리는 문서 적용 하나로 기록되며 글별 실행 취소·다시 실행으로 복원한다. 미적용 초안이 있는 문서는 구간 정리 버튼을 잠그고 먼저 적용하거나 취소하도록 안내한다. 표지는 대상에서 제외하며 본문은 1~80개, 사진 내부 글은 1~6개를 유지한다. 비활성 버튼에 경계·개수 제한 이유를 연결한다. 읽기 화면이나 공개 렌더러·JSON에는 관리 도구를 넣지 않는다.

## 본문 도구막대 — 2026-10-17

구간 이동·복제·삭제는 팝업에서 본문 도구막대로 옮긴다. 선택 테두리 상단에 위로·아래로·복제·더보기를 표시하고 삭제는 더보기 안에 둔다. 위쪽 공간이 부족하거나 긴 구간을 스크롤 중이면 선택 구간의 보이는 상단 안쪽에 붙인다. 창 크기·본문 크기·스크롤 변화에 맞춰 위치를 갱신하고 작은 화면에서도 버튼이 잘리지 않도록 한다. 더보기는 바깥 클릭·초점 이동·Esc로 닫는다. 읽기 화면·표지·내용 수정 및 종류 변경 작업 중에는 구간 도구를 숨긴다. 내용·종류·스타일 팝업과 문서 기록·초안 보호는 유지한다.

## 사진 고르기와 미리보기 — 2026-10-17

표지 또는 사진이 있는 구간에서 ‘편집 → 사진 바꾸기’로 제공 사진 목록을 연다. 본문 사진은 내용 수정에서도 같은 목록을 사용한다. 서버에서 제공된 표지·본문 사진을 주소로 중복 제거해 표시하고, 검증도 같은 사진 목록을 기준으로 한다. 외부 사진 주소 입력·파일 업로드·서버 저장은 제공하지 않는다.

적용 전에는 본문 캔버스·내보내기에 반영하지 않는다. 닫은 뒤 같은 구간에서 편집을 다시 열면 사진 초안을 복원한다. 취소는 초안을 버리고 적용은 문서 기록 하나로 남겨 실행 취소·다시 실행을 지원한다. 사진 변경은 기존 비율·초점·크롭·배치·내부 글·구간 ID를 유지한다.

## 내 컴퓨터 사진 추가 — 2026-10-17

사진 선택 화면에서 파일을 고르면 브라우저가 JPEG·PNG·WebP 파일을 읽어 편집용 JPEG로 재인코딩한다. 원본은 10MB 이하, 결과는 긴 변 1600px 이하·900000자 이하로 제한한다. 사진 메타데이터를 옮기지 않고 투명한 부분은 흰색으로 합성한다. 손상된 파일·지원하지 않는 형식·초과 용량은 이유를 안내하고 기존 선택을 유지한다. 준비 중인 창을 닫으면 해당 작업의 늦은 결과가 다른 구간을 덮어쓰지 않는다.

추가한 사진은 이 브라우저의 공용 사진 목록에 나타나 표지·본문에서 다시 선택할 수 있다. 선택 직후 작업 미리보기를 확인하고 적용·취소·실행 취소·다시 실행은 기존 경계를 따른다. 사용한 사진의 JPEG 데이터를 src에 넣으므로 JSON 파일 하나로 문서와 사진을 함께 보관하고 다시 불러온다. 사용하지 않은 목록 사진은 내보내지 않으며 사용하지 않은 사진 목록도 브라우저에 임시 저장된다. 사진을 포함한 JSON의 가져오기와 문서 적용은 16MB까지 허용한다.

v1 스키마는 제공 경로와 검증된 작은 JPEG 데이터 URL을 허용하도록 확장했다. MIME·인코딩·JPEG 프레임 크기를 런타임에서 검사하고 생성된 JSON 스키마에도 패턴·길이 제한을 반영한다. SVG·외부 주소·blob 주소는 문서에 넣지 않는다. 실제 운영의 서버 저장·미디어 자산 관리·원본 보관 방식은 별도 설계한다. 직접 추가한 표지에는 ‘직접 추가한 이미지’로 표시하고 기존 샘플의 AI 생성 안내와 구별한다.

## 브라우저 자동 임시 저장 (2026-10-17)

IndexedDB에 글별 적용 문서·JSON 원문·미적용 구간 수정·작성 중 기본정보·업로드 사진 목록과 마지막 편집 위치를 자동 저장한다. 같은 브라우저의 같은 사이트 주소로 다시 들어오면 복원한다. 업로드 사진은 JPEG 데이터로 저장하며 서버 업로드·회원 동기화·발행은 하지 않는다. 실행 취소·다시 실행 기록은 현재 방문 중에만 유지한다.

저장 상태를 편집기에 표시한다. 저장 공간 부족과 저장본 검증 실패 시 마지막 정상 저장본을 유지하고 JSON 보관을 안내한다. 여러 탭이 다른 내용을 저장하려 하면 이전 버전을 가진 탭의 자동 저장을 멈춰 덮어쓰기를 막는다. 브라우저 사이트 데이터를 삭제하면 임시 저장본도 삭제되므로 장기 보관은 JSON 내보내기를 사용한다.

## 임시 저장 목록과 초안 삭제 (2026-10-17)

상단 편집 도구의 ‘임시 저장 목록’에서 브라우저에 저장된 글을 검색하고 이어 편집한다. 제목·글 주소·최근 작업 시점을 표시한다. 최초 제공 샘플도 편집 가능한 브라우저 초안으로 목록에 포함한다. 예전 저장본은 시점 정보 없이 복원할 수 있다.

삭제 버튼은 먼저 글 제목과 삭제 범위를 확인한다. 확인하면 해당 글·미적용 수정 내용을 지우고 다른 글의 추천 연결도 정리한다. 연결된 글에 미적용 JSON이 있으면 먼저 적용·취소하도록 안내하여 원문을 잃지 않게 한다. 삭제는 실행 취소되지 않으며, 삭제된 글의 참조가 되살아나지 않도록 문서 실행 취소 기록도 비운다. 공용 업로드 사진 목록은 유지한다. 모든 초안을 지운 상태도 저장하며 재방문 때 샘플을 자동 복구하지 않는다. 빈 편집기에서는 새 글 또는 JSON 불러오기로 시작한다. 삭제 변경도 기존 자동 저장 실패·충돌 보호 정책을 따른다.

## 본문 여백 정책 — 2026-10-17

본문 구간·소제목·접이식 목차·글 끝의 다음 행동은 같은 왼쪽 기준선을 공유한다. reading·wide·full은 기존 너비를 유지하며 오른쪽으로 확장한다. 구간을 너비별로 개별 가운데 정렬하지 않는다. margin 인용도 자동으로 오른쪽에 밀지 않고 같은 기준선에서 시작한다. 박스·인용선·목록 번호의 내부 여백은 역할을 나타내므로 유지한다. 명시한 align=center는 구간 안 문구 정렬이며 구간 자체를 옮기지 않는다. 사진과 글 내부의 열 구성·사진 위치, 표지 배치는 유지한다.

여섯 글·관리자 전체 미리보기·변경 확인의 단일 구간 미리보기는 공통 렌더러의 같은 정책을 쓴다. 편집기의 요소 추가선도 본문과 같은 왼쪽 기준선에 맞춘다. 화면이 좁으면 기존 읽기 표면의 안쪽 여백을 유지한 채 가용 너비에 맞춘다.

## 사진 비율·크롭·캡션 — 2026-10-17

표지·본문·편집기의 전체/단일 구간 미리보기는 `src/styles/_editorial-media.scss`의 사진 프레임 규칙을 공유한다. 원본 파일과 기존 문서의 비율·초점·사진 위치 선택은 유지한다. 이미지 비율을 임의 높이나 본문 길이에 맞춰 늘이지 않는다.

- 비율: 가로 16:9, 정사각 1:1, 세로 4:5. 본문은 기존 image.ratio 값을 사용한다. 표지는 title-first·image-first가 16:9, compact가 1:1, split이 4:5다. 같은 표지 배치는 PC·모바일에서 같은 비율을 유지한다.
- 크롭: scene은 선택한 비율을 채우는 기본 크롭이며 원본의 모든 가장자리가 보인다는 뜻은 아니다. detail은 같은 프레임 안에서 1.25배 추가 확대한다.
- 초점: left·center·right는 가로 20%·50%·80%, 세로 가운데를 기준으로 한다. object-position과 확대 기준점이 같은 초점을 사용한다. 기존의 오른쪽 고정 확대 기준점을 제거한다.
- 캡션: 사진 바로 아래 12px 간격, 사진과 같은 폭의 왼쪽 정렬. 글자 위계는 기존 12/13px 공통 캡션 토큰을 유지한다. 표지의 이미지 설명과 제작 표기도 같은 왼쪽 기준선에서 순서대로 읽는다. 사진 위에 캡션을 덮지 않는다.
- 사진과 글: PC의 좌우 위치·열 비중·위/가운데 맞춤은 유지하고 캡션을 사진 열 안에 묶는다. 모바일은 사진 → 캡션 → 관련 본문 순서로 읽는다. 캡션이 다른 열이나 전체 구간 아래로 떨어지지 않는다.

편집기의 비율 버튼에 수치를 표시하고 크롭은 ‘비율에 맞춤 / 초점 확대 · 1.25배’로 안내한다. 스키마 키나 저장된 값은 바꾸지 않는다. 원본이 잘리면 초점을 조정하거나 다른 비율을 선택해 미리보기에서 확인한다. 자동 인물 인식·자유 크롭·새 파일 생성은 추가하지 않는다.

### 글 전체의 편집 흐름

요청 예문은 `quote.layout: rule`과 설명용 예문 라벨, 왼쪽 정렬·읽기 너비·본문 크기로 표현한다. 핵심 주장에 사용하는 큰 인용(statement/pull)과 구분한다. 출처는 번호 있는 ‘참고’ 소제목 대신 마지막 `text.tone: small` 구간에 ‘참고한 자료’와 링크·적용 범위를 남긴다. 짧은 문단을 다단으로 쪼개거나 같은 사진·마무리 점검을 반복해 길이를 늘리지 않는다. 여섯 번째 가이드는 업무 적용 단계 안에 최종 점검을 합치고 끝 사진을 생략한다.
