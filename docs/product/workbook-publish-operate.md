# 공개와 운영 · 친구에게 보여주기 전후

확정된 4+1 구조의 ‘공개와 운영’ 최소 단위다. AI 입문·첫 제작·화면과 사용 경험·동작과 데이터 다음에, 같은 홈페이지 기획과 미리보기를 이어 받는다. 기존 첫 맵의 기록에서 연결하며 새 지도나 호스팅 서비스를 만들지 않는다.

## 세 화면과 완료 기준

1. 제목·소개·목록을 두 폭에서 읽고 내용 보기 버튼을 눌러 공개 전 화면을 점검한다. 공개하면 안 되는 계정 비밀번호와 공개 여부를 확인한 소개 자료를 구분한다. 두 폭 확인·버튼 확인·공개 자료 판단이 필요하다.
2. 내 컴퓨터의 localhost 주소와 공개 서버의 HTTPS 주소 예시를 골라 친구 기기의 접속을 흉내 낸다. 두 결과를 비교하고 주소만 적는 것과 실제 배포가 다름을 자기 문장으로 적는다. `.invalid`는 접속할 수 없는 설명용 주소이며 링크·복사·업로드 기능을 제공하지 않는다. 호스팅·배포를 짧게 정의한다.
3. 학습용으로 동작을 막아둔 추가 작업 버튼을 눌러 문제를 재현한다. 화면 크기·행동·기대·실제 결과를 적고 그 기록으로 수정 요청 초안을 만든다. 요청은 편집할 수 있으며 적용 버튼은 예시 버튼 하나만 고친다. 다시 눌러 목록이 나타나는지 확인하고 달라진 점을 적으면 완료다. 실제 파일이나 운영 사이트를 바꾸는 활동으로 기록하지 않는다.

## 기록과 경계

이전·취소·이야기/지도 왕복·완료 재방문에서 이번 방문 기록을 유지한다. 같은 버튼 반복은 재확인 기록을 지우지 않는다. 문제 기록이나 수정 요청을 바꾸면 재확인을 다시 하고, 앞 홈페이지 기획이 바뀌면 공개·운영 기록도 초기화한다. 선행 단원 수정 중에는 잠기고 선행 완료 후 기존 기록을 이어 본다.

실제 배포·외부 계정·유료 서비스·회원 인증·파일 업로드·DB/API/플랫폼 진행 저장은 구현하지 않는다. 후속 [실습·공개 안내](workbook-practice-guides.md)에 기존 Vercel Drop의 파일 준비·공개·갱신·오류 확인을 연결했다. 계정·이용 조건은 학습자가 공식 안내에서 확인하며 가격·소요 시간을 보장하지 않는다. 실제 공개 주소 검증은 미실행이다. 단원 완료는 예시에서 공개 전 확인과 운영 흐름을 연습했다는 뜻이며 실제 공개 성공을 주장하지 않는다. 선택 심화 ‘AI와 일하는 방식’ 및 각 월드의 나머지 지점은 별도 작업으로 남는다.

## 2026-10-15 · 입문자의 공개/운영 예시와 실제 점검 분리

각 단계에서 워크북 예시 조작과 내 파일/실제 주소에서 해야 할 일을 구분한다. 요청과 관찰 입력은 ‘예시 버튼의 수정 요청’·‘예시 버튼을 다시 눌러 확인한 변화’로 표시한다. 진행 안내는 두 화면 읽기 체크/내용 버튼/공개 가능 자료, 두 주소의 접속 흉내/주소 판단 이유, 예시 결함 재현/네 문제 항목/요청/수정 적용/같은 버튼 재확인/변화 기록 중 남은 행동을 안내한다. 예시 완료 후 클래스 정리를 먼저 보여주는 순서는 유지한다. 실제 적용은 선택이며, 미공개라면 공개 전 파일 점검까지, 이미 공개했다면 실제 주소의 다른 기기 확인을 구분한다. 배포 서비스·자동 업로드·신규 외부 호출·실제 접속 검증은 추가하지 않았다.

## 같은 프로젝트의 실제 공개·공유·재배포 보강 원고 — 2026-10-20

승인된 프로젝트 연계 방향과 Vercel 기본 후보를 반영한 5단원 후속 원고다. 위 주소·고장 난 버튼 시뮬레이션과 현재 완료 조건은 구현 이력으로 보존한다. 아래는 목표 원고이며 화면·판정·코드·외부 계정·실제 배포는 변경하거나 실행하지 않는다. 공식 문서 확인과 학습자 계정·Windows/Mac 실제 검증은 구분한다.

### 도입 — 같은 페이지를 다른 사람도 열 수 있게 해요

지금까지 같은 폴더에서 내용을 만들고 화면과 필요한 동작을 확인했어요. 이번에는 **공개할 자료를 점검하고, 실제 주소로 접속하고, 한 사람에게 공유한 뒤 수정해 다시 반영**해요.

‘호스팅’은 사이트 파일을 다른 사람도 접속할 수 있는 환경에서 제공하는 것이고, ‘배포’는 준비한 파일을 그 환경에 반영하는 일이에요. 내 컴퓨터에서 파일을 저장하는 것과 공개 사이트를 갱신하는 것은 달라요.

기본 후보는 Vercel Drop이에요. 실제 계정·이용 목적·환경 조건이 맞는지 확인한 뒤 진행해요. **Hobby는 비상업적 개인 용도**이며 실제 상품·서비스 판매 홍보는 상업 사용에 포함돼요. 해당 목적은 적합한 플랜이나 다른 호스팅을 별도로 확인해야 해요. 연습이라는 표기만 붙여 실제 상업 목적이 사라지는 것은 아니에요. 유료 가입·도메인 구매를 공통 과제로 요구하지 않아요. [공식 이용 기준](https://vercel.com/docs/limits/fair-use-guidelines)

### 활동 1 — 공개할 내용과 파일을 점검해요

**앞 단원의 결과를 이어받아요.** 주요 내용·링크·상세 보기·저장 판단을 다시 적기보다 기존 기록과 현재 파일을 대조해요. 생략한 기능을 공개를 위해 새로 추가할 필요는 없어요.

| 점검             | 직접 확인할 행동                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 사실과 공개 범위 | 제목·소개·작업·실적이 실제 내용과 맞는지, 연습 소재는 표시했는지 확인. 다른 사람의 사진·이름·자료도 공개할 수 있는지 확인  |
| 파일             | 같은 프로젝트의 index.html과 연결된 CSS·JavaScript·이미지를 확인. 업로드할 폴더의 첫 화면 위치와 필요한 자산 점검          |
| 불필요한 자료    | 비밀번호·API 키·개인 문서·비공개 기록·수업과 관계없는 파일을 업로드 범위에서 제외. 실제 값은 질문이나 기록에도 붙이지 않음 |
| 읽기와 행동      | PC·모바일 폭에서 제목·내용·이미지와 주요 링크·버튼 확인. 상세 보기가 있다면 내용 대응·열기/닫기 확인                       |
| 저장             | 저장을 쓴다면 무엇이 이 브라우저에만 남는지 확인. 저장 생략 이유가 여전히 맞는지도 확인                                    |

배포할 것은 처음부터 이어온 같은 프로젝트의 공개 파일이에요. 정적 폴더의 최상위에 `index.html`과 필요한 자산을 준비하는 경로로 안내해요. 컴퓨터의 전체 문서 폴더나 프로젝트의 비밀 설정을 함께 올리지 않아요. 원본 프로젝트를 지우거나 새 예제로 바꿀 필요는 없어요.

필요한 파일을 별도 공개용 폴더로 모았다면 원본과의 관계를 기억해요. 이후 수정은 기존 원본에 반영하고 공개용 파일도 갱신해요. 동작에 필요하지 않은 패키지 설치·프레임워크 전환·Git 연결을 추가하지 않아요.

문제가 보이면 먼저 로컬 파일에서 해당 부분을 고쳐요. 해결하지 못한 내용이나 공개할 수 없는 자료가 있다면 **공개 준비 중**으로 남기고 배포를 미뤄요.

### 활동 2 — 배포하고 실제 접속을 확인해요

#### 계정과 프로젝트를 확인해요

본인 계정에 로그인하고 이용 목적·플랜·사용 가능 범위를 확인해요. 기존에 이 사이트를 배포한 프로젝트가 있다면 아래 첫 생성 단계를 반복하지 말고 그 프로젝트를 찾아 갱신 경로를 사용해요.

**첫 배포 경로**

1. [Vercel Drop](https://vercel.com/drop)을 열고 준비한 정적 폴더를 업로드해요.
2. 배포할 팀과 프로젝트 이름을 확인하고 Deploy를 선택해요.
3. 업로드·배포가 완료됐는지 상태를 읽어요. 실패했다면 표시된 단계와 오류를 먼저 확인해요.

공식 문서상 Drop 첫 화면은 새 프로젝트를 만들며, 기존 Git 미연결 프로젝트에는 폴더를 올려 production을 갱신할 수 있다. 이 원고의 경로는 [Vercel Drop 공식 안내](https://vercel.com/docs/drop)를 기준으로 한다. 계정별 UI와 OS별 폴더 선택·업로드 조작은 실제 실습 후 확정하며 소요 시간·무료 완료를 보장하지 않는다.

#### 공유할 주소를 골라요

`file://`는 내 컴퓨터의 파일을 여는 주소이고 `localhost`는 그 기기에서 실행한 서버를 가리켜요. 친구에게 그대로 보내도 내 컴퓨터 화면을 볼 수 있는 주소가 아니에요. Vercel 관리 화면 주소도 사이트 본문 주소와 달라요.

공유할 것은 **해당 프로젝트의 production 대표 도메인 주소**예요. 배포마다 생성되는 개별 URL과 구분하고, 재배포 뒤에도 다시 확인할 주소로 기록해요. 모든 HTTPS 주소가 공개 접근 가능한 것은 아니에요.

Vercel Standard Protection은 production domain을 제외한 배포 URL을 보호하고, All Deployments는 production domain도 보호한다. 팀·프로젝트 설정을 확인해야 하며, 사이트를 공개하기 위해 모든 미리보기 보호까지 일괄 해제하라고 안내하지 않는다. [공식 보호 범위](https://vercel.com/docs/deployment-protection)

#### 소유자가 아닌 환경에서 열어요

1. Vercel에 **로그인하지 않은 브라우저 환경**에서 대표 주소를 직접 열어요. 로그인이나 접근 승인을 요구하는지 확인해요.
2. 컴퓨터와 **다른 기기**에서도 같은 주소를 열어 제목·이미지·주요 내용과 행동을 확인해요. 사용할 기기가 없다면 이 확인은 남은 작업으로 기록해요.
3. 상세 보기가 있으면 열고 닫아봐요. 저장을 적용했다면 공개 주소에서 관심 추가→새로고침→유지, 해제→새로고침→해제를 확인해요. 다른 기기에 이전 관심 표시가 없는 것은 예상한 범위일 수 있어요.

공개 주소가 생긴 것, 외부에서 본문이 열린 것, 주요 행동이 맞게 동작한 것은 각각 확인해야 해요. 워크북의 주소 입력이나 예시 접속으로 실제 배포·공개 성공을 대신하지 않아요. 외부 결과는 본인 확인이에요.

### 공유 — 주소와 부탁할 행동 하나를 보내요

외부 접속을 확인했다면 한 사람에게 대표 주소와 확인할 행동을 함께 전달해요. 큰 평가나 추천을 부탁할 필요는 없어요.

> 작은 사이트를 만들어봤어. [실제 대표 주소]에서 [관심 작업을 열고 내가 맡은 역할 찾기]를 해볼 수 있어? 어디서 헷갈렸는지 알려주면 다음 수정에 참고할게.

서비스 소개라면 제공 내용 찾기, 개인 사이트라면 관심 항목과 추천 이유 읽기처럼 자기 페이지에 맞게 바꿔요. 대괄호는 실제 내용으로 바꾼 뒤 본인이 사용하는 수단으로 직접 전달해요. 원고 작성이나 워크북 조작이 메시지를 대신 보내는 것은 아니에요.

**실제로 전달했다면 답장이 없어도 공유 조건을 충족**해요. 상대 이름·메시지 캡처·회신 제출은 요구하지 않아요. 공유할 수 없는 사정이 있다면 공개와 재배포는 계속할 수 있지만 공유는 대기로 남겨요. 혼자 주소를 열어본 것을 타인 공유로 기록하지 않아요.

### 활동 3 — 한 가지를 수정하고 같은 주소에서 확인해요

답장이 있다면 그 의견을 참고하고, 없다면 공개 주소를 스스로 다시 살펴봐요. 피드백을 전부 받아들이기보다 페이지의 목적과 실제 불편을 기준으로 **중요한 변경 한 가지**를 고르세요.

오류가 없으면 추천 이유를 더 분명하게 쓰거나 제공 범위를 보완하는 등 의미 있는 콘텐츠 개선으로 재배포를 연습해요. 고장 난 버튼을 일부러 만들거나 의미 없는 글자 변경을 요구하지 않아요.

**수정 요청 예시**

> 같은 my-first-web 프로젝트에서 [실제로 관찰한 문제 또는 개선할 설명]을 수정해줘. [원하는 결과]가 되면 좋겠어. 기존 제목·주요 내용·링크·상세 보기·저장 판단 중 [유지할 부분]은 유지해줘. 변경 파일과 로컬에서 확인할 방법을 알려주고 배포는 하지 마.

요청을 실제 내용으로 바꾸고 **같은 원본 파일**에 적용해요. 로컬 화면에서 변경과 기존 주요 행동을 확인한 뒤 배포할 폴더에도 최신 파일이 반영됐는지 확인해요.

**기존 프로젝트 갱신**

Vercel 대시보드에서 앞서 만든 Git 미연결 프로젝트를 열고 수정한 폴더를 올려 production을 갱신해요. Drop 첫 화면으로 돌아가 같은 사이트의 새 프로젝트를 만들거나 기존 프로젝트를 삭제할 필요는 없어요. 이 경로는 [기존 프로젝트 갱신 안내](https://vercel.com/docs/drop)의 동작을 따른다.

배포 상태를 확인한 뒤 **처음 공유한 같은 대표 주소**에서 바뀐 내용과 기존 링크·동작을 확인해요. 비로그인 환경에서도 최신 내용이 보이는지 재확인해요. 로컬 파일 저장만 했거나 다른 배포 URL에서만 바뀌었다면 대표 주소의 재배포 확인은 아직 남아 있어요.

### 막힌 지점과 완료 범위를 구분해요

아래 상태 이름은 설명용 제안이다. 공유 대체 과제와 최종 UI 문구는 미결이며 현재 완료 판정에 추가하지 않는다.

이전 화면 문제는 파일 저장→업로드한 폴더→배포 성공 여부→보고 있는 주소→브라우저 재확인 순서로 좁힌다. 계속 실패하면 화면 조건·행동·기대·실제 결과를 정리해 다음 수정에 활용한다. 새 프로젝트 생성이나 유료 업그레이드를 모든 오류의 해결책으로 안내하지 않는다.

### 최종 정리 — 무엇을 만들고 확인했나요?

처음 목적과 초안에서 이어진 **화면 개선 또는 유지 판단→상세 보기·저장 적용 또는 생략→공개 주소→공유→마지막 개선과 재배포**를 한 흐름으로 읽어요. 앞 기록을 불러오고 변경된 부분만 갱신해요.

최종 기록은 대표 주소·접속 확인 범위·공유 여부·마지막 변경과 재배포 결과·남은 문제 정도로 제한해요. 캡처는 선택이고 상대 정보는 필요 없어요. URL 입력이나 파일 첨부만으로 외부 성공을 인증하지 않아요.

학습 확인, 실제 프로젝트의 부분 진행, 실제 프로젝트 완료를 구분해요. 최종 프로젝트 완료는 같은 사이트의 내용·화면·필요한 동작과 저장 판단, 비로그인/다른 기기 접속, 실제 타인 공유, 의미 있는 수정 후 같은 대표 주소의 재배포 확인을 포함해요. 정당한 기능 생략은 완료를 막지 않지만 확인하지 않은 공개·공유는 남은 작업으로 남겨요. 회원 저장·기기 간 진도 동기화·공개 주소의 영구 유지나 서비스 한도 없는 이용은 약속하지 않아요.

### 원고 검증 범위

2026-10-20 KST에 Vercel Drop·Deployment Protection·Fair Use 공식 문서를 확인했다. 실제 계정 생성·플랜 변경·폴더 업로드·배포·비로그인/다른 기기 접속·타인 공유는 수행하지 않았다. 학습자 Windows/Mac에서 실제 경로와 화면 이름을 검증한 뒤 공개 수업 안내를 확정해야 한다. 기존 예시 중심 완료·선행 조건·현재 기록 구조를 이 원고 작성만으로 바꾸지 않는다.
