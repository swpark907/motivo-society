# 모쏘 커뮤니티 플랫폼 대략 기획 (초안)

2026-11-02. 백엔드 큰 그림([platform-backend-overview.md](../architecture/platform-backend-overview.md))과 벤치마킹 조사([platform-benchmark-research.md](../architecture/platform-benchmark-research.md))를 바탕으로 한 **대략 기획**이다. 이 기획을 맞춘 뒤 DB 구조 설계로 이어간다. 화면·카피·세부 정책은 이 문서의 범위가 아니다. 용어는 모두 가칭이다.

## 1. 한 줄 정의

**클럽에서 만나고, 모임과 챌린지로 함께하고, 클래스로 배우고, 만든 것으로 발견되는 테크 컬쳐클럽 플랫폼.**

- 컨셉 (대표와 합의, 2026-11-02): 소모임 + 동행클럽 + 디스코드.
- 전략: B2C, 웹으로 시작하고 모바일 앱으로 확장한다.
- 이 플랫폼은 "강의를 내려주는 곳"이 아니라 "장(場)"이다. 클래스도 같은 장 안의 한 가지 참여 방식이다.

## 2. 세 서비스에서 가져오는 것

| 출처                 | 가져오는 것                                                                 | 가져오지 않는 것                                         |
| -------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| 소모임               | 누구나 찾고 들어가는 클럽, 클럽 안 모임, 관심사 기반 추천                   | 회비를 앱 밖에 두는 방식(장기적으로 플랫폼 결제)         |
| 동행클럽             | 시즌제 다회차 모임, 공식 호스트 큐레이션, 대기 신청·최소 인원               | 전원 사전 인터뷰(열림 원칙과 충돌, 필요한 상품에만 검토) |
| 디스코드             | 클럽 안의 상시 공간 구조, 역할, 스레드, 초대 링크, **온라인 모임과 챌린지** | 상주형 실시간 음성·채팅을 웹에서 재현하기                |
| 인프런(최종 타깃 축) | 클래스, 진도, 수강자 전용 스터디·챌린지                                     | 강사 → 수강생의 일방향 구도                              |

### 디스코드 흡수의 의도 (2026-11-02)

디스코드를 흡수하려는 이유는 **온라인 챌린지와 온라인 모임까지 확장**하기 위해서다. 오프라인 만남에 더해, 온라인에서도 모이고 함께 해내는 경험을 클럽 안에 담는다.

- **구조는 흡수하고, 매체는 따라 하지 않는다.** 클럽 안의 주제별 공간, 역할(클럽 레이어), 모임별 스레드, 초대 링크, 가입 온보딩, 결과물 공유는 웹에서도 잘 통한다. 링크로 바로 열리고 검색된다는 점은 오히려 웹이 유리하다.
- **정해진 시간의 온라인 모임은 웹으로 충분하다.** 약속한 시간에 링크로 들어오면 되기 때문이다. 웹에서 약한 것은 "늘 켜 두고 들렀다 가는" 상주형 경험이다.
- **챌린지는 비동기라 웹과 잘 맞는다.** 기간 안에 미션을 하고 인증을 올리는 방식이다.
- **(2026-11-13 갱신) 클럽 실시간 채팅은 직접 만든다** — 아래 줄의 채팅 부분을 대체한다. 근거와 구조는 `platform-private-clubs.md`. 음성·화상은 여전히 외부 링크.
- **실시간 음성·화상은 웹 단계에서 직접 만들지 않는다.** 온라인 모임에는 외부 화상 링크(구글 밋·줌·디스코드 등)를 붙이고, 신청·출석·스레드·후기는 플랫폼 안에 둔다. 상주형 실시간(라운지 채팅, "지금 모각코 중")은 푸시 알림이 생기는 앱 단계에서 검토한다.
- **밖으로는 "디스코드 같은"이라고 말하지 않는다.** 메인 타깃(소모임 층)에게 디스코드는 낯선 도구일 수 있다. "모임 사이에도 이어지는 클럽"처럼 하는 일로 표현한다. 이 시장 판단은 통계로 확인한 것이 아니라 체감이며, 형제 서비스의 "스페이스"(체크인·라운지·도움 요청) 사용량으로 검증할 수 있다.

## 3. 핵심 개념

| 개념   | 무엇                                                           | 비고                                         |
| ------ | -------------------------------------------------------------- | -------------------------------------------- |
| 계정   | 한 사람. 참석자이자 호스트일 수 있다                           | 계정 종류를 나누지 않는다                    |
| 클럽   | 소속 단위. 멤버, 레이어(역할), 공간을 가진다                   | 한 사람이 여러 클럽에 들어갈 수 있다         |
| 공간   | 클럽 안의 주제별 방. 게시판형 글과 댓글                        | 웹 단계는 비동기만                           |
| 모임   | 한 번의 만남. **오프라인 / 온라인**                            | 클럽 안 또는 클럽 밖(호스트 개인 주최)       |
| 시즌   | 회차 묶음. 한 번 등록하고 각 회차는 모임                       | 오프라인 강의(형제 서비스)도 여기에 들어온다 |
| 챌린지 | 기간 + 미션 + 인증. 정해진 기간 동안 각자 해내고 인증을 올린다 | 온라인 비동기. 클래스와 묶을 수 있다         |
| 스레드 | 모임·시즌·챌린지마다 붙는 대화                                 | 모이기 전 질문, 끝난 뒤 후기·사진            |
| 클래스 | 혼자 진행하는 온라인 학습(워크북)                              | 진도는 서버에 저장한다                       |
| 이용권 | 누가 무엇에 참여·수강할 자격이 있나                            | 결제·초대·수료 어디서 생겼든 여기서 판정     |
| 주문   | 유료 참여의 신청과 결제                                        | 지금은 계좌이체 + 운영진 확인, 나중에 PG     |

## 4. 사람들의 여정

1. **발견.** 인스타 DM 링크로 모임·클럽·챌린지·아티클 페이지에 바로 들어온다. 로그인 없이 내용이 보인다.
2. **가입.** 가입 직후 관심사를 고르고, 관심사에 맞는 클럽·모임·챌린지를 추천받는다. 나이·전화번호는 유료 신청이나 호스트 자격처럼 필요한 순간에 받는다.
3. **참여.**
   - 무료 모임·챌린지는 신청하면 바로 확정된다.
   - 유료는 신청하면 입금 대기 상태가 되고, 운영진이 입금을 확인하면 확정되며 이용권이 생긴다.
   - 클럽 가입은 클럽 설정에 따라 즉시 또는 승인이다.
4. **모임 전후.**
   - 모임 스레드에서 준비물을 묻고, 리마인드를 받는다.
   - 온라인 모임이면 시작 시간에 화상 링크가 열린다.
   - 출석을 체크하고, 끝나면 후기와 사진을 남긴다.
5. **챌린지.**
   - 기간 동안 미션을 하고 인증을 올리면, 서로 응원하고 진행 현황이 보인다.
   - 클래스 수강자만 참여하는 챌린지도 있다(인프런 챌린지·워밍업 클럽형).
6. **클럽의 일상.** 모임이 없는 날에도 공간에 질문, 정보, 만든 결과물이 쌓인다. 좋은 결과물은 큐레이션되어 아티클·라이브러리로 올라간다(발견의 양방향).
7. **배우기.** 클래스를 구매해 이용권을 받고, 진도가 서버에 남는다. 클래스는 관련 시즌·챌린지·클럽으로 이어진다.
8. **호스트.**
   - 호스트 자격을 신청하고, 승인되면 모임·시즌·챌린지를 연다.
   - 명단, 입금 확인, 공지, 출석, 인증 현황을 관리한다.
   - 클럽 관리자는 레이어를 만들어 운영진에게 권한을 나눈다.
9. **운영(소유자).** 호스트 자격 승인, 입금 확인·환불, 신고 처리와 제재, 콘텐츠 발행을 맡는다.

## 5. 원칙

- **기본은 열림.** 클럽·모임·챌린지 페이지는 누구나 볼 수 있다. 멤버 전용 공간·모임은 클럽이 정한 예외다.
- **하나의 흐름을 재사용한다.** 오프라인·온라인 모임, 시즌, 챌린지는 신청 → 확정 → 참여 → 후기라는 같은 흐름 위에 있다. 다른 점(장소, 출석과 인증, 일정 구조)만 종류별 규칙으로 둔다.
- **돈은 이용권으로 연결한다.** 결제 수단이 계좌이체에서 PG로 바뀌어도 화면과 권한 판정은 바뀌지 않는다.
- **학습과 성취가 먼저다.** 레벨·포인트·뱃지는 나중의 별도 기능이고, 참여를 독려하는 장치가 학습과 만남을 가리지 않게 한다.

## 6. 단계 (대략)

| 단계 | 웹              | 담는 것                                                           |
| ---- | --------------- | ----------------------------------------------------------------- |
| 1    | 계정·권한       | 로그인, 프로필, 관심사, 소유자 역할                               |
| 2    | 클래스 + 이용권 | 워크북 진도 서버 저장, 수강 이용권                                |
| 3    | 클럽과 모임     | 클럽, 레이어, 공간, 오프라인·온라인 모임(무료), 스레드, 초대 링크 |
| 4    | 유료 참여       | 주문(계좌이체 확인), 시즌, 형제 서비스의 클래스 신청 이관         |
| 5    | 챌린지          | 기간·미션·인증, 클래스 연계                                       |
| 6    | 호스트 확장     | 호스트 자격 신청과 심사, 클럽 밖 개인 주최                        |
| 이후 | 앱·결제         | 모바일 앱과 푸시, 가벼운 실시간, PG와 호스트 정산, 조직(B2B)      |

순서는 제안이며, 첫 공개 목표(어느 단계까지)는 미결이다.

## 7. 미결

- 첫 공개 목표의 범위
- 클럽 가입 방식의 기본값(즉시 / 승인)
- 시즌과 챌린지를 클럽 밖에서도 열 수 있게 할지
- 로그인 방식(이메일, 카카오 등 소셜 로그인)
- 모임·클럽 대화를 플랫폼 안에 둘지, 외부(카톡 오픈채팅·디스코드)로 보낼지의 기본값
- 챌린지 인증 방식(글·사진·링크)과 완주 판정, 참여비 환급 여부
- 후기·평점 구조
- 환불 규정(대표 승인)
