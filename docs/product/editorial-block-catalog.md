# 에디토리얼 구간 카탈로그

2026-10-16. 에디토리얼 문서 v1의 추가 선택지다. 기존 문서는 그대로 읽으며 새 종류를 생성하는 AI와 편집기는 갱신된 `content/schemas/workbook-editorial-v1.schema.json`을 사용한다. 임의 HTML·CSS를 넣는 방식으로 확장하지 않는다.

## 종류와 표현을 따로 고른다

`type`은 내용의 역할, `layout` 또는 `tone`은 그 내용을 보여주는 방식이다. 본문은 9종이며, 아래 여섯 문자 중심 종류에서 총24개 표현을 제공한다. 표지·사진·사진과 글의 배치 조합은 별도다.

| 종류                | 표현값                                                                                    | 적합한 내용                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 문단 `text`         | `body` 기본 / `lead` 큰 도입 / `small` 보조 / `columns` 잡지 2단 / `dropcap` 첫 글자 강조 | 이어 읽는 설명. 2단은 긴 설명, 드롭캡은 글의 첫 도입에 제한적으로 사용                                           |
| 인용 `quote`        | `rule` 위아래 선 / `statement` 큰 문장 / `pull` 큰 따옴표 / `margin` 좁은 여백 인용       | 실제 인용이나 명시된 요청 예문. 평범한 설명을 인용으로 만들 때는 출처·화자를 꾸미지 않기                         |
| 목록 `list`         | `rows` 행 / `grid` 2열 / `steps` 큰 번호 / `timeline` 세로 흐름 / `checklist` 확인 목록   | 독립 요점·절차·순서·확인 기준. 타임라인은 순서가 의미 있을 때 사용. 체크 표시는 읽기용이며 완료 저장 기능은 아님 |
| 비교 `compare`      | `columns` 나란히 / `stack` 세로 / `contrast` 명암 대비 / `table` 라벨과 설명 대조         | 2~3항목의 차이. 명암 대비가 좋고 나쁨이나 실험 결과를 자동으로 의미하지 않으므로 라벨과 캡션으로 설명            |
| 핵심 메모 `callout` | `note` 테두리 / `band` 가로 띠 / `aside` 옆선 메모                                        | 작성자의 요약·주의·곁가지. 인용처럼 타인의 발언으로 오해하게 만들지 않기                                         |
| 질문과 답변 `qa`    | `interview` 문답 / `columns` 질문·답변 좌우 / `ruled` 구분선                              | 자주 묻는 질문·자문자답. 실제 인터뷰가 아니라면 인터뷰 상대나 발언 사실을 만들지 않기                            |
| 소제목 `heading`    | 번호와 제목                                                                               | 구간의 실제 구조. guide의 TOC에 포함되므로 장식용 대문장에는 사용하지 않기                                       |
| 사진 `image`        | 가로·정사각·세로 / 초점·크롭                                                              | 하나의 장면. alt·캡션·AI 생성 여부 유지                                                                          |
| 사진과 글 `split`   | 좌우 위치 / 같은 폭·사진 넓게·글 넓게 / 위·가운데 맞춤                                    | 장면과 관련 설명. 내부에는 text·heading·quote·list·callout·qa 허용. 비교와 사진 구간 중첩 불가                   |

모바일에서는 잡지 2단·문답 좌우·비교 열을 세로로 읽는다. 순서는 문서에 쓴 순서를 유지하며 PC에서만 배치를 달리한다.

## 추가 구간 예시

```json
{
  "type": "callout",
  "id": "verification-note",
  "label": "확인의 기준",
  "text": "출처 링크가 있어도 **원문과 주장을 직접 대조**해요.",
  "layout": "aside",
  "width": "reading",
  "align": "left"
}
```

```json
{
  "type": "qa",
  "id": "screen-question",
  "items": [
    {
      "question": "화면 캡처로 버튼의 동작도 확인할 수 있나요?",
      "answer": "정지 화면만으로 실제 버튼의 동작을 확인했다고 볼 수는 없어요."
    }
  ],
  "layout": "columns",
  "width": "wide"
}
```

callout의 label은 선택, text는 필수다. qa는 question·answer를 가진 항목1~8개를 받는다. 이 구간도 다른 본문처럼 굵게·인라인 코드·HTTPS 링크만 해석한다.

## AI가 조합할 때

먼저 내용을 문단·요약·인용·비교·문답 같은 역할로 나눈 뒤 표현을 고른다. 다양성을 위해 내용을 임의로 잘게 쪼개거나 인용·인터뷰·숫자를 만들지 않는다. 글마다 모든 표현을 쓰지 말고, 도입과 중심 구간에 강조를 배분한다. 같은 기능에는 같은 표현을 반복해도 된다.

여섯 샘플에는 요청 비교·사진과 예문·문답·인계 항목·실행 타임라인·핵심 메모를 내용에 맞게 나눠 적용했다. 요청 예문은 `quote.layout: rule`의 본문 크기와 설명용 라벨로, 핵심 판단은 본문 강조나 callout으로 구분한다. 출처는 번호 없는 `text.tone: small` 영역에 둔다. 짧은 한 문단의 다단 배치와 이유 없는 사진·마무리 반복은 피한다. AI에 전달할 지시와 제출 전 검토는 [작성 가이드](workbook-reading-authoring.md#ai에게-줄-작업-지시)를 따른다. 사진과 기존 설명을 활용한 테스트이며 실제 실험·검증이 완료됐다는 뜻은 아니다.

## 편집기에서 종류를 바꿀 때

구간 선택 → 종류 바꾸기 → 대상 종류 선택 → 변환 안내 확인 → 종류 변경 적용 순서다. 문단·소제목·인용·목록·비교·메모·문답 사이에서 바꾼다. 변경 직후에는 되돌리기를 제공하며, 다른 편집이 생긴 뒤에는 그 편집을 덮어쓰지 않도록 이전 변환의 되돌리기를 숨긴다.

변환은 문장을 유지하지만 구조를 완벽히 추론하지 않는다. 기존 제목·라벨·캡션을 본문에 합칠 수 있고, 목록·비교에는 ‘항목1’ 같은 임시 라벨을 붙인다. 문답은 첫 문단을 질문, 나머지를 답변으로 잡는다. 적용 전에 안내하고 적용 후 사람이 내용을 확인해야 한다. 비교/목록/문답의 재료가 한 문단뿐이면 같은 변경 확인 화면에서 빈 줄로 내용을 나눈다. 두 개 이상의 내용과 필수 항목이 채워져야 적용할 수 있다. 임시 제목과 질문·답변은 ‘제목·내용 수정’에서 바로 고칠 수 있으며 부족한 내용을 지어내지 않는다.

사진이나 사진과 글은 텍스트 종류로 바꾸면 이미지·내부 구간을 잃을 수 있어 직접 변환하지 않는다. 기존 사진 배치 도구를 사용한다. 실제 저장과 발행을 붙이기 전의 탭 메모리 실험 범위는 그대로다.
