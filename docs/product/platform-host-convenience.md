# 호스트 편의 기능 — 제안 (2026-11-06)

승우가 직접 모임을 운영하면서 겪은 불편에서 시작한다. 결론은 **호스트가 편해야 모임이 계속 열린다**는 것이다. 이 문서는 제안이며, 범위와 순서는 승우가 정한다. 돈이 걸린 부분은 대표 확인이 필요하다.

## 출발점: 기존 소모임 서비스에서 불편했던 것

1. 여태 연 모임을 다시 볼 수 없다.
2. 모임을 만들 때 바로 직전 모임의 문구만 불러올 수 있다.
3. 모임 이미지가 저장되지 않아서 매번 직접 찾아 넣어야 한다.
4. 참가비를 호스트가 각자 계좌로 받고, 모임 돈을 관리할 방법이 없다.

## 제안

### 1. 지난 활동 기록 — "내가 연 활동"

- 호스트 도구(`/host`)에 **내가 연 활동 전체 목록**을 둔다. 끝난 것과 취소된 것까지 포함하고, 종류·클럽·기간·검색으로 거른다.
- 활동마다 그때의 기록이 남는다: 참가자 명단과 출석, 받은 돈과 환불, 후기와 사진, 대화.
- 참가자도 "나"의 내 일정에서 **지난 활동**을 본다. 내가 간 모임, 함께한 사람, 남긴 후기.
- DB는 이미 준비되어 있다. 활동과 참가 기록은 지우지 않고 보관하기 때문에(명세 0절) 새 테이블 없이 화면만 만들면 된다.

### 2. 어떤 활동에서든 불러와 만들기

- 새 활동을 만들 때 **"지난 활동에서 가져오기"**를 고르면, 내가 연 모든 활동이 나온다. 직전 활동 하나가 아니라 전부다.
- 가져올 항목을 고른다: 소개 문구, 표지 이미지, 장소, 정원, 가격, 신청 질문, 현장 비용 안내. 일정은 비워 둔 채로 시작한다.
- 자주 쓰는 구성은 **"양식으로 저장"**에 이름을 붙여 남긴다. 예: "월례 모각코", "카페 수다".
- **장소 즐겨찾기**: 한 번 쓴 장소(이름, 주소, 지도 링크, 찾아오는 길)를 저장해 두고 골라 쓴다.
- **자주 쓰는 공지 문구**: 준비물 안내, 입금 안내, 리마인드 같은 문구를 저장해 두고 참가자 대화에 바로 넣는다.
- 지금 기획에 있는 "다음 주 같은 시간으로 복제"(명세 5절)는 그대로 두고, 그 위에 이 기능을 더한다.

### 3. 이미지 보관함

- 호스트가 올린 이미지는 **내 보관함**에 남는다. 활동을 만들 때 보관함에서 고르거나 새로 올린다.
- 클럽에는 **클럽 보관함**이 따로 있어서 클럽 운영진이 같은 이미지를 함께 쓴다.
- 지난 활동의 후기 사진 중 참가자가 허락한 것을 다음 표지 후보로 쓸 수 있다. 다른 사람이 찍은 사진이므로 이 기능은 동의 방식을 정한 뒤에 만든다.
- 표지가 없으면 종류 색과 제목으로 만든 기본 표지를 보여 준다.

### 4. 돈 — 받기는 모쏘가, 장부는 호스트에게

- **받기.** 참가비는 호스트의 개인 계좌가 아니라 모쏘가 받고, 모쏘가 호스트에게 정산한다. 이 방향은 2026-11-02에 확정했고 DB 설계에도 반영되어 있다. 호스트는 누가 입금했는지 따로 맞춰 볼 필요가 없다. 입금이 확인되면 참가 상태가 저절로 확정으로 바뀐다.
- **활동별 장부(새 제안).**
  - 들어온 돈: 결제 완료와 환불을 주문에서 자동으로 채운다.
  - 나간 돈: 대관료, 다과, 재료처럼 호스트가 직접 적는다. 영수증 사진을 붙일 수 있다.
  - 남은 돈과 정산 예정 금액을 한 화면에서 본다.
  - 참가자에게 사용 내역을 공개하는 선택지를 둔다. "함께 쌓인다"는 원칙에 맞는다.
- **정산 화면.** 월별로 정산 예정, 지급 완료, 환불 차감을 보여 준다. DB의 `settlements`가 이미 있으므로 화면을 붙이면 된다.
- **클럽 회비(나중, 결정 필요).** 정기 회비를 누가 냈는지 보여 주는 현황판. 회비를 모쏘가 대신 받을지, 기록만 남길지는 법률·세무 확인과 대표 결정이 필요하다. 기록만 남기는 방식은 돈을 직접 다루지 않으므로 먼저 만들 수 있다.

### 5. 같이 넣으면 좋은 호스트 편의

- **참가자 한 번에 연락**: 확정자 전체, 대기자 전체, 입금 대기자 전체에게 공지를 보낸다. 리마인드는 이미 자동이다.
- **명단 내보내기**: CSV로 내보내고, 현장에서 쓸 출석표를 인쇄한다.
- **빠른 출석 체크**: 휴대폰 한 손으로 이름을 눌러 체크한다. 모임 화면의 QR로 참가자가 직접 체크하는 방식도 있다.
- **지난 참가자 다시 부르기**: 새 활동을 열 때 "지난번 참가자에게 알리기". 받은 사람이 알림을 끌 수 있어야 한다.
- **단골 보기**: 내 활동에 자주 온 사람과 출석률. 노쇼 기록과 연결되지만 제재에는 쓰지 않는다(명세 13절 제안 기본값).
- **공동 호스트**: 진행자를 여러 명 둘 수 있다(이미 기획됨). 진행자에게 장부를 볼 권한을 줄지는 따로 고른다.

## DB에 더할 것 (초안)

| 테이블                    | 내용                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `media_assets`            | 소유자(사람 또는 클럽), 저장 경로, 대체 텍스트, 올린 사람·시각. 활동 표지가 이 행을 가리킨다                           |
| `activity_templates`      | 소유자, 이름, 가져올 항목(jsonb, 허용 필드만)                                                                          |
| `saved_places`            | 소유자, 장소 이름, 주소, 지도 링크, 찾아오는 길                                                                        |
| `saved_snippets`          | 소유자, 제목, 본문(공지 문구)                                                                                          |
| `activity_ledger_entries` | 활동, 종류(지출 / 기타 수입), 금액, 메모, 영수증 이미지, 적은 사람. 결제·환불은 주문에서 계산하고 여기 복사하지 않는다 |

- 쓰기는 지금처럼 `security definer` 함수로만 한다. 장부를 고치고 지운 것은 감사 기록에 남긴다.
- "지난 활동에서 가져오기"는 기존 활동을 읽어 새 초안을 만드는 함수 하나로 충분하다.

## 정할 것

1. **순서.** 제안: ① 지난 활동 기록과 가져와 만들기 → ② 이미지 보관함 → ③ 활동별 장부와 정산 화면 → ④ 연락·명단·출석 → ⑤ 클럽 회비.
2. **장부 공개 기본값.** 제안: 기본은 호스트만 보고, 공개는 호스트가 고른다.
3. **클럽 회비를 모쏘가 받을지, 기록만 남길지.** 대표와 법률·세무 확인이 필요하다.
4. **후기 사진을 표지로 쓸 때의 동의 방식.**
