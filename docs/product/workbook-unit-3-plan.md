# 워크북 3단원 — 반응형 화면 만들기

2026-11-25 · 승우와 정한 3단원 다시 만들기. 1·2단원과 같은 방식으로 수업마다 화면 흐름을 제안 → 선택 → 한 화면씩 구현한다. 수업 만들기 규칙은 `docs/product/workbook-lesson-authoring.md`를 따른다(특히 2절 "단원 전체의 표현", 3절 "줄이지 말고 풀어 쓴다").

## 목표

2단원에서 기획하고 고친 같은 `my-first-web/index.html`을, 휴대폰 · 태블릿 · 컴퓨터처럼 크기가 다른 화면에서 열어 보고, 깨지는 곳을 찾아 고쳐 달라고 하고, 고친 뒤 다시 확인한다. 새 페이지를 만들거나 기획을 다시 쓰지 않는다. 문제가 없으면 근거를 남기고 그대로 둬도 된다(2026-10-20 승인 기준).

2-6에서 이미 "한 곳만 고쳐 달라기"와 "전후 비교"를 했으므로, 3단원은 **화면 크기 때문에 생기는 것**에 집중해 반복을 피한다.

## 3단원 다섯 수업 (2026-11-25 승우 결정)

제목은 학습자가 아는 말로 그 수업에서 하는 일을 말한다("너비" 같은 만드는 사람의 말을 쓰지 않는다 — 같은 날 지적).

| 수업                                          | 하는 일                                                                                                                                                          |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3-1 반응형 화면이란 무엇인가                  | 같은 내 페이지를 크기가 다른 기기에 나란히 띄워 보고, 하나의 페이지가 화면 크기에 맞춰 다시 놓이는 것을 반응형이라고 부른다는 것을 안다                          |
| 3-2 휴대폰 크기로 내 페이지 열어 보기         | 컴퓨터에서 브라우저 창을 좁히거나 개발자 도구로 휴대폰 · 태블릿 · 컴퓨터 세 가지 크기에서 내 페이지를 연다                                                       |
| 3-3 휴대폰에서 자주 깨지는 곳 찾기            | 연습 화면에서 자주 생기는 문제를 찾아본 뒤, 같은 기준으로 내 페이지를 점검한다                                                                                   |
| 3-4 고칠 곳 하나를 AI에게 부탁하기            | 찾은 문제를 "어느 화면에서, 어디가, 무엇이 불편한지" 한 문장으로 적고, 2-5의 네 칸 메모에 확인할 화면 크기를 더해 부탁한다. 문제가 없으면 근거를 남기고 유지한다 |
| 3-5 고친 뒤 휴대폰과 컴퓨터에서 다시 확인하기 | 고친 곳이 나아졌는지, 다른 크기의 화면이 망가지지 않았는지 두 화면을 나란히 놓고 확인한다                                                                        |

- 주소: 영구 주소 규칙에 따라 기존 세 주소를 다시 쓴다(제안: 3-3 `screen-observation`, 3-4 `screen-improvement`, 3-5 `screen-check`). 3-1 · 3-2는 새 주소를 받는다(이름은 구현 때 정한다).
- 수업 번호는 2단원처럼 `workbook-course.ts`에서 이름으로 찾는다.

## 담을 내용 (2026-11-25 승우 승인)

### 3-1 — 화면 크기가 다양한 기기

- 같은 내 페이지를 다섯 종류의 화면에 나란히 띄운다.
  - 휴대폰: 세로로 좁아서 내용이 한 줄로 쌓인다.
  - 접히는 폰: 접으면 휴대폰, 펼치면 태블릿만큼 넓어진다. 보는 도중에 화면 크기가 바뀌는 기기도 있다는 예.
  - 태블릿: 세로로 들었을 때와 가로로 돌렸을 때 모양이 다르다.
  - 노트북과 큰 모니터: 넓어서 2-3에서 고른 "두 칸" 배치가 그대로 보인다.
- 기기마다 페이지를 따로 만들 수 없으니, 하나의 페이지가 화면 크기에 맞춰 다시 놓이게 만든다 → 반응형.
- 본문에는 "접히는 폰"처럼 기기 종류로 쓰고, 제품 이름은 확인한 날짜와 함께 작은 글씨로만 붙인다. 화면 크기 숫자(픽셀)는 외우게 하지 않는다.
- **2-1과 잇기:** 2-1에서 "주로 휴대폰으로 본다"를 고른 사람에게는 그 선택을 다시 보여 주고, 내 페이지를 볼 사람이 주로 휴대폰으로 본다면 휴대폰 화면부터 확인하고 맞춘다는 것으로 잇는다.

### 3-2 — 세 가지 크기로 열어 보기

- 모든 기기를 다 확인할 수 없으니 대표 크기 세 가지(휴대폰 · 태블릿 · 컴퓨터)로 확인하는 습관.
- **앱 안에서 열리는 페이지:** 인스타그램이나 카카오톡에서 링크를 누르면 그 앱 안의 브라우저로 열려 위아래에 앱 메뉴가 붙고 화면이 더 좁아진다. 2-1에서 고른 "인스타그램 링크로 들어온다"와 잇는다. 모쏘도 인스타그램 DM이 주된 입구라 실제 상황과 맞닿아 있다.
- **진짜 휴대폰으로는 언제 보나:** 지금은 컴퓨터에서 휴대폰 크기를 흉내 내는 것이고, 내 휴대폰으로 직접 여는 것은 5단원에서 페이지를 인터넷에 올린 뒤에 한다고 미리 말해 둔다.
- 브라우저별 조작(창 좁히기 · 개발자 도구의 기기 보기)과 개발자 도구 기기 목록에 들어 있는 기기는 구현 전에 공식 문서로 확인하고 확인한 날짜를 적는다. Windows · Mac은 실제로 다를 때만 나눈다.

### 3-3 — 자주 깨지는 곳 점검 목록

- 옆으로 밀리는 화면(가로로 밀어야 보이는 내용)
- 너무 작은 글자, 너무 긴 줄
- 붙어 보이는 내용(간격)
- 누르기 힘든 버튼 — 손가락에는 "마우스 올리기"가 없어서, 마우스를 올려야만 보이는 내용은 휴대폰에서 아예 보이지 않는다
- 잘리는 그림
- 휴대폰 설정에서 글자를 크게 해 둔 사람에게 버튼 글자가 넘치거나 제목이 잘리는지

연습 화면의 문제는 연습용이다. 내 페이지에 같은 문제가 있다고 가정하지 않고, 정해진 수의 문제를 찾게 하지 않는다.

### 넣지 않는 것

- 다크 모드, 페이지 로딩 속도, 휴대폰 위아래 가림 영역(노치 · 홈 막대): 처음 배우는 단원에 너무 많다. 4·5단원이나 심화로 미룬다.

## 3-1 반응형 화면이란 무엇인가 (구현됨 · 2026-11-25)

| 화면 | 제목                           | 실제 모습                                                                                                                                                                                                                            |
| ---- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ①    | 휴대폰으로 열어 보면           | 컴퓨터 폭으로 그린 내 페이지를 휴대폰 틀에 그대로 줄여 넣음 → "손가락으로 크게 키워 보기"를 누르면 휴대폰 화면이 실제로 옆으로 밀림. 카피바라 장면(갸웃) · 학습자 파일이 아니라 "그대로 줄인다면"이라는 가정 (`WorkbookPhoneShrink`) |
| ②    | 화면 크기는 기기마다 달라요    | 휴대폰 · 접히는 폰(펼치기/접기) · 태블릿(가로/세로로 돌리기) · 노트북 · 큰 모니터 진열대. 기기마다 자기 폭으로 그린 같은 페이지. 접히는 폰 아래 "예: 갤럭시 Z 폴드8 · 2026년 11월 확인" (`WorkbookDeviceShelf`)                      |
| ③    | 크기에 맞춰 다시 놓이는 페이지 | 브라우저 창 손잡이를 끌거나(← → · PageUp/PageDown · Home/End) 넓혔다 좁혔다 하면 페이지가 다시 놓이고 "지금 ~"으로 바뀐 모양을 알려 줌. 한 번 움직이면 "반응형"이라는 말을 알려 줌 (`WorkbookResizeWindow`)                          |
| ④    | 화면이 좁아지면 무엇이 바뀔까  | 같은 페이지(메뉴 · 사진을 더한 예시)를 컴퓨터 · 휴대폰으로 나란히. 칸 수 · 글자 크기 · 그림 크기 · 메뉴 버튼을 누르면 두 화면에서 그 부분 표시 (`WorkbookShrinkChanges`)                                                             |
| ⑤    | 내 페이지는 어디서 볼까        | 2-1 방문자 카드(`WorkbookVisitorCard`) → 그 사람이 주로 쓰는 기기 속 내 페이지. 휴대폰 · 컴퓨터 · 고르지 않음에 따라 다른 조언 (`WorkbookWhereSeen`)                                                                                 |
| ⑥    | 오늘 알게 된 것                | 줄자 정리: 펼쳐지는 줄자 위 번호 1~4와 매달린 쪽지 네 장 (`WorkbookResponsiveRecap`)                                                                                                                                                 |

- 3단원 개념 수업은 `WorkbookExperienceLessonFrame`을 쓰고, 마지막 화면에서 3단원 기록의 `done`에 주소를 남긴다. 3단원 진도는 `workbook-experience.ts`의 `experienceStepsDone`/`experienceStepsAvailable` 한 곳에서 계산한다. 개념 수업은 실습 수업을 막지 않는다(수업 주소로 바로 들어와도 열려야 하므로).
- 내 페이지 미리보기(`WorkbookMyPage`)는 브라우저 폭이 아니라 자기 상자의 폭에 맞춰 칸이 바뀐다(container query). 좁으면 한 줄, 400px 이상 두 칸, 480px 이상 세 칸, 560px 이상이면 "두 칸" 배치에서 제목과 내용이 나뉜다.
- 3-2(휴대폰 크기로 내 페이지 열어 보기)는 아직 없다. 지금 코드의 3단원은 3-1 + 예전 세 수업(3-2~3-4)이며, 3-2를 넣으면 기획대로 다섯 수업이 된다.

## 표현 (수업별로 제안 → 선택)

2단원에서 정한 표현 규칙을 그대로 쓴다: 학습자의 내 페이지(`WorkbookMyPage`)를 실제처럼 그려 이어 쓰고, 카피바라 장면은 단원에 두세 곳, 정리 화면은 수업마다 다른 물건. 아래는 처음 아이디어이며 수업마다 다시 제안해 고른다.

- 3-1: 내 페이지 창의 손잡이를 끌어 늘였다 줄였다 하기(직접 조작) · 기기 다섯 개에 나란히 띄우기. 도입에 카피바라가 휴대폰으로 열었다가 옆으로 밀려 당황하는 장면.
- 3-2: 브라우저 약도 위 번호 핀.
- 3-3: 연습 휴대폰 화면에서 문제 찾기 → 같은 점검 목록으로 내 페이지 보기.
- 3-4: 2-5의 네 칸 메모를 이어 쓰고 "확인할 화면 크기" 칸을 더한다.
- 3-5: 같은 페이지를 휴대폰 · 컴퓨터 두 창에 나란히. 마무리 카피바라 장면 → 4단원.
- 정리 화면 물건 후보: 줄자 · 점검표 · 작업 지시서 · 검사 합격증.
