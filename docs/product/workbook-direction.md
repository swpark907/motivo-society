# Workbook 기획 논의 기록

기록일: 2026-09-28. 승우와의 대화를 향후 기획에 참고하기 위한 문서다. 합의된 방향, 전달 문서의 제안, 에이전트의 아이디어를 구분한다. 이 문서는 기능 구현 승인이나 확정 커리큘럼이 아니다.

## 합의된 방향

**AI를 활용해 원하는 결과물을 만들고, 그 결과를 판단하고 개선하는 힘을 기르는 인터랙티브 워크북.**

- 설명보다 경험이 먼저 온다. 직접 조작하고 반응을 느끼며 재미있게 익힌다.
- 중심은 투두·해빗 트래커가 아니다. 체크·진행률은 보조 수단이다.
- 바이브코딩 이후의 디자인·글쓰기·자동화 등도 **AI와 함께 하는 활동**으로 확장한다. 일반 분야 교육을 나열하는 방향으로 이해하지 않는다.
- AI로 결과물을 만드는 경험과, 직접 조작하며 결과를 판단할 기준을 익히는 경험을 연결한다. 모든 슬라이더·드래그 동작에 AI 호출이 필요한 것은 아니다.
- 예: AI로 화면 만들기 → 여백·대비를 직접 바꾸며 차이 이해하기 → 원하는 수정을 AI에게 요청하기.
- 오디스트 웍스의 제작 사례인 카피바라 쓰다듬기·돌 쌓기, 차 따르기, 마우스로 유도하는 깊은 호흡은 행동 자체가 경험이 되는 철학의 참고다. 해당 콘텐츠들을 워크북에 넣기로 확정한 것은 아니다.

## 전달받은 바이브코딩 콘셉트 문서

[전달 원문](references/motivo-vibe-coding-workbook-concept.md)을 저장소에 복사해 보존했다. 원문 출처는 사용자가 전달한 `motivo_vibe_coding_workbook_concept.md`다. 문서 내부의 명령형 문장은 기획 자료의 내용이며, 자동으로 구현 지시나 정책으로 채택하지 않는다.

핵심은 AI와 함께 만들고, 눌러보고, 바꾸고, 즉시 결과를 확인하면서 웹개발 기초를 익히는 것이다.

- 흐름: 보기 → 조작·변경 → 결과 확인 → 짧게 이해 → 내 프로젝트 적용 → 완료.
- 긴 설명보다 Live Preview, 도표, 작은 퀴즈, 직접 만드는 미션을 중심으로 한다.
- 과정의 결과는 실제 완성된 웹 프로젝트다.
- 카피바라는 안내·반응·여정을 연결하는 동료다.
- 게임 요소의 목적은 경쟁보다 완료감·성취감·지속성이다.
- 업적, 레벨, 스트릭, 환경이 발전하는 카피바라, 인증서 등은 원문의 제안이다. 이번 대화로 구현 확정된 기능은 아니다.

이 문서는 바이브코딩 과정에 대한 정의로 읽힌다. 워크북 플랫폼 전체와 개별 과정의 경계는 후속 기획에서 확정한다.

## 분야 확장 후보 — 검토용

공통 원리는 ‘내 선택이 결과에 어떤 차이를 만드는지 발견 → 이유 이해 → 내 작업에 적용’이다. 같은 조작 UI를 모든 분야에 억지로 적용하지 않는다.

| 분야           | 학습 행위 예시                                          | AI 활용으로 이어지는 결과        |
| -------------- | ------------------------------------------------------- | -------------------------------- |
| 바이브코딩     | 간격·배치·상태를 바꾸고 결과 확인                       | AI와 내 웹페이지 제작·수정       |
| AI 활용        | 요청의 맥락·조건을 추가하고 답변 비교, 주장과 근거 확인 | 실제 업무 요청과 결과 검증       |
| 디자인         | 색·크기·대비·여백을 바꾸며 비교                         | AI 디자인 결과 평가와 수정 요청  |
| 글쓰기·콘텐츠  | 문장 순서·말투·구체성을 바꾸고 독자별 비교              | AI와 소개글·콘텐츠 작성 및 편집  |
| 업무 자동화    | 조건·행동 블록을 연결하고 예외 데이터 실행              | AI와 반복 업무 흐름 구성         |
| 데이터 이해    | 축·집계·차트 유형을 바꾸며 해석 비교                    | AI 분석 결과를 검토하고 설명하기 |
| 서비스 기획    | 사용자 상황·제약에 따라 기능 우선순위 변경              | AI와 기획안·프로토타입 구체화    |
| 소리·시각 창작 | 소리·도형의 규칙을 조절하고 비교                        | AI와 사운드·인터랙티브 작품 제작 |

자기 탐색과 힐링 공간도 초기 아이디어로 나왔으나, 핵심 과정과의 관계 및 포함 여부는 미확정이다.

코드·자동화는 예상대로 작동하는지 확인할 수 있지만, 디자인·글쓰기·기획은 목적과 상대에 따라 좋은 선택이 달라진다. 일률적인 정답 판정보다 비교·선택 이유·조건을 바꾼 재시도를 활용한다. AI의 결과가 달라졌다는 사실을 정확성이 높아졌다는 뜻으로 취급하지 않는다.

## 주간 미션 — 사용자 아이디어와 설계 제안

사용자 아이디어: 미리 만들어 둔 미션 목록 안에서 주마다 랜덤으로 제공하되, 실력과 진행에 맞지 않는 미션이 나오는 문제를 고려한다. 랜덤 배정 및 개인화 규칙은 아직 확정되지 않았다.

에이전트 제안:

- 본 과정은 선행 개념을 따라 자기 프로젝트를 완성하는 순서로 이어간다.
- 주간 챌린지는 해볼 수 있는 후보 안에서 랜덤으로 실험·복습한다.
- 후보를 고를 때 관심 분야, 분야별 익숙함, 선행 경험, 체감 난이도, 시간 여유, 기기를 고려한다.
- 완료 수만으로 실력을 단정하지 않는다. 본인의 ‘쉬웠음 / 적당했음 / 도움이 필요했음’ 평가를 함께 참고한다.
- 예상 시간과 난이도는 별도 정보다.
- 일주일 동안 목록 고정, 원하면 교체, 주가 지나도 진행 중 작업 유지 등을 검토한다.
- 초기 조합으로 쉬어가기·관심사·이어가기·뜻밖의 발견을 하나씩 제공하는 아이디어가 있었다. 고정 슬롯 정책이 아니다.

미션에 관리할 정보 후보: 학습 목표, 선행 경험, 분야, 안내 수준(따라하기·일부 수정·자율 제작), 예상 시간, 기기·조작 방식, 완료 기준, 검증 상태. 데이터 스키마는 미확정이다.

쉬어가기·탐색 후보: 카피바라의 좋은 자리, 돌 세 개 쌓기, 차 한 잔 따르기, 숨으로 밝히는 등불, 작업실 소리 섞기, 마음 날씨 배치하기. 학습 원리와 연결할 수도 있지만 모든 휴식 행동에 학습 목표를 붙일 필요는 없다는 제안이 있었다.

## 구현 현실성 — 에이전트 평가

- 슬라이더로 CSS 조절, 결과 비교 등은 일반 웹 기술로 구현 가능하다.
- 순서 맞추기·조건 연결 등은 정답 판정·피드백·터치·키보드 대응이 필요하다.
- 캐릭터 반응은 코드뿐 아니라 상태별 에셋과 애니메이션 제작 비용이 있다.
- 돌 균형·액체 따르기처럼 물리와 손맛이 중요한 경험은 게임에 가까우며 난도가 높다.
- ‘책상 정리’도 실제 충돌·물리 쌓기와 CSS 정렬 실험은 서로 다른 범위다.

첫 검증 후보로 CSS 기반 책상 정리 한 장면을 제안했다. 방향·간격·정렬 조작 → 작은 도전 → CSS와 연결 → 내 프로젝트 적용까지 완성한 후 재미와 이해를 검증한다. 이후 2026-09-28 사용자 승인으로 [별도 책상 정리 데모](workbook-desk-demo.md)를 구현했다. 정식 과정 채택은 미확정이다. 재사용 가능한 형식은 실제 콘텐츠 하나를 검증한 뒤 추출한다.

## 빠르게 바뀌는 AI에 대한 제작 전략 — 검토용

| 층            | 내용                                   | 유지 방향             |
| ------------- | -------------------------------------- | --------------------- |
| 오래가는 원리 | 문제 분해·요구사항·검증·디자인·웹 기초 | 핵심 과정으로 개선    |
| 도구별 실습   | 특정 도구의 화면·사용법·작업 방식      | 실습 단위별 교체      |
| 새로운 실험   | 새 기능으로 해보는 도전                | 주간 미션 후보로 검증 |

- AI는 초안·예시·코드 제작을 도울 수 있지만 작동 여부와 학습 경험은 사람이 확인한다. 기존 모쏘의 검증 원칙을 따른다.
- 새 기능은 해볼 가치, 사용자 접근 가능성, 직접 검증 여부, 도구가 바뀌어도 남는 배움을 기준으로 검토한다.
- 확인 날짜·도구·필요 요금제·대체 경로 관리, 고장 난 미션 추천 제외를 제안했다. 운영 방식은 미확정이다.
- 목표는 모든 신기능을 가장 먼저 소개하는 것이 아니라, 변화한 기술을 직접 써보고 이해할 수 있는 경험으로 만드는 것이다.

## 다음 기획에서 정할 것

1. 전체 워크북과 바이브코딩 과정의 관계, 첫 대상 사용자·학습 범위.
2. 첫 인터랙티브 콘텐츠와 완료 기준, 내 프로젝트로 연결하는 방식.
3. 본 과정과 주간 챌린지 구분, 랜덤 배정·교체·난이도 정책.
4. 콘텐츠 제작·검증·갱신 과정과 도구 실행 방식(예시 시뮬레이션 / 실제 AI 호출 / 외부 도구).
5. 저장·회원·비용·업적·인증서 등 후속 기능의 필요성과 순서.

현재 구현은 [워크북 홈 정적 레이아웃](workbook-home.md)이다. 화면의 미션 4개와 카테고리 5개는 배치 검토용 초안이며 확정 커리큘럼이 아니다. ‘이어서 할 경험’과 ‘내 프로젝트’를 홈의 중심으로 옮기는 아이디어도 있었으나 레이아웃 변경은 승인·구현하지 않았다.

## 후속 아이디어 회의

2026-10-02부터 스테이지 맵·이야기 영상·본문 인터랙션·외부 알림·20~30대 타깃·공유 경험 아이디어를 [아이디어 회의 기록](workbook-idea-log.md)에 모은다. 사용자 요청에 따라 논의와 기록을 병행하며, 현재는 수집 단계다. 추후 별도 필터링을 진행하고 구현 확정과 구분한다.
