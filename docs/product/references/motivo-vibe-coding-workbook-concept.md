# Motivo Vibe Coding Workbook — Concept

## 제품 정의

**바이브코딩으로 시작하는 웹개발 기초**는 코딩 이론을 처음부터 길게 공부하는 교육 콘텐츠가 아니다.

AI와 함께 직접 만들고, 눌러보고, 바꿔보고, 결과를 즉시 확인하면서 웹개발의 기본 원리를 자연스럽게 익히는 **인터랙티브 온라인 워크북**이다.

핵심 학습 흐름은 다음과 같다.

**See → Try → Change → Preview → Understand → Complete**

즉, **설명보다 경험이 먼저 오는 구조**다.

긴 텍스트와 이론 설명은 최소화하고, 하나의 개념도 가능한 한 **짧은 설명 + 도표/인포그래픽 + 인터랙션 + 직접 실행**으로 이해하게 만든다.

예를 들어 CSS를 설명한다면 10분 동안 CSS의 정의를 읽는 게 아니라,

> Border Radius를 0 → 8 → 24로 움직여보기  
> ↓  
> 오른쪽 Live Preview에서 버튼이 실시간으로 변함  
> ↓  
> `border-radius`가 무엇을 바꾸는 속성인지 이해

이런 방식으로 학습한다.

---

## 핵심 경험 원칙

### 1. Less Reading, More Doing

한 화면에 긴 설명을 넣지 않는다.

이론은 사용자가 지금 하고 있는 작업을 이해하는 데 필요한 만큼만 제공한다.

**원칙**

- 긴 텍스트 설명 최소화
- 핵심 개념은 짧고 직관적으로
- 읽는 시간보다 조작하고 만드는 시간이 더 길게
- 이론을 먼저 설명하기보다 결과를 먼저 경험하게 설계

---

### 2. Live Preview First

가능한 개념은 모두 실시간 결과와 연결한다.

예:

- `font-size` 슬라이더 조절 → 글자 크기 변화
- `gap` 조절 → 카드 사이 간격 변화
- Flex 방향 선택 → 레이아웃 변화
- 색상 변경 → UI 즉시 변경
- 프롬프트 수정 → 생성 결과 비교

사용자가 **“아, 이걸 바꾸면 저게 변하는구나”**를 바로 느끼게 한다.

---

### 3. Interactive Learning

읽기만 하는 콘텐츠보다 선택하고 조작하는 콘텐츠를 중심으로 한다.

활용 가능한 인터랙션 예시:

- 드래그
- 클릭
- 슬라이더
- 코드 일부 수정
- 빈칸 채우기
- 순서 맞추기
- UI 요소 배치하기
- Before / After 비교
- Live Preview
- 선택형 시뮬레이션
- 직접 화면에서 정답 영역 클릭하기

---

## Visual Learning

글로 설명하기 어려운 개발 개념은 적극적으로 **도표와 인포그래픽**으로 바꾼다.

예를 들어 웹의 구조를 다음과 같은 흐름도로 보여줄 수 있다.

**Browser → Frontend → API → Backend → Database**

컴포넌트 개념은 실제 웹페이지를 다음처럼 색상별 블록으로 분해해서 보여준다.

- Navbar
- Hero
- Card
- Button
- Footer

목표는 명확하다.

> **개발 개념을 텍스트가 아니라 눈으로 이해하게 만드는 것.**

---

## Quiz & Micro Challenge

각 학습 단위 중간에는 아주 짧은 퀴즈를 넣는다.

시험 느낌보다는 **다음 단계로 넘어가기 위한 작은 게임**에 가깝게 설계한다.

예:

### 화면에서 직접 찾기

> 이 화면에서 Header는 어디일까요?

사용자가 실제 화면에서 Header 영역을 클릭한다.

### 선택형 퀴즈

> 이 카드를 가로로 배치하려면 무엇을 바꿔야 할까요?

- `flex-direction: row`
- `font-size: 24px`
- `border-radius: 20px`

정답을 맞히면 짧은 피드백과 함께 바로 다음 단계로 넘어간다.

---

## Follow-along Missions

모든 Chapter에는 반드시 **직접 만드는 과제**가 존재한다.

개념을 배웠으면 바로 자기 프로젝트에 적용한다.

예:

### MISSION 07

## 나만의 Hero Section 만들기

오늘 할 일:

1. Headline 작성
2. CTA 결정
3. AI에게 Hero 제작 요청
4. 결과 Preview
5. 디자인 수정
6. Mission Complete

따라서 사용자는 워크북을 끝낼 때 단순히 지식을 얻는 것이 아니라 **완성된 웹 프로젝트를 갖게 된다.**

---

## Game-like Progression

게임성은 너무 어린 느낌보다는 **성인을 위한 Playful Learning** 정도로 설계한다.

예:

### Chapter 01 · Web Explorer

`████████░░ 80%`

미션을 완료할 때마다 Achievement가 열린다.

- First Page
- First Prompt
- First Component
- First Interaction
- First Deploy

연속 학습 기능도 활용할 수 있다.

**7 Day Streak 🔥**

Chapter 완료 시:

> **LEVEL UP**  
> You've unlocked Interactive Web.

게임화의 목적은 경쟁이 아니라 **완료감, 성취감, 지속성**을 높이는 것이다.

---

## Capybara as Learning Companion

카피바라는 단순 장식용 이미지가 아니라 **워크북 경험을 연결하는 학습 캐릭터**로 사용한다.

### Guide

새 Chapter 시작:

> 오늘은 웹사이트를 조각조각 분해해볼까요?

### Reaction

퀴즈 정답:

> Nice.

오답:

> 거의 맞았어요. 이 부분을 한번 움직여보세요.

### Mission Visual

카피바라가 직접 웹페이지를 만들거나 노트북을 들여다보는 이미지를 활용한다.

### Achievement

Chapter가 끝날수록 카피바라의 환경도 발전한다.

처음:

**카피바라 + 빈 책상**

↓

HTML / CSS:

**모니터에 첫 페이지 등장**

↓

Interactive Web:

**여러 UI와 코드가 등장**

↓

Deploy:

**완성된 사이트를 바라보는 카피바라**

워크북 전체에 작은 **여정과 세계관**을 만든다.

## Completion Certificate

전체 과정을 완료하면 단순한 “수강 완료”가 아니라 **실제로 프로젝트를 완성했다는 의미의 인증서**를 제공한다.

예:

### MOTIVO SOCIETY

**VIBE CODING · WEB DEVELOPMENT**

Certificate of Completion

This certifies that  
**DAYOUNG PARK**

has completed  
**Vibe Coding — Web Development Fundamentals**

30 Missions Completed  
1 Web Project Built  
Project Deployed

2026

인증서에는 다음 정보를 포함할 수 있다.

- 이름
- 완료 날짜
- 프로젝트 URL
- Credential ID
- Share 버튼

SNS 공유용 인증 이미지도 함께 생성할 수 있다.

## 핵심 포지셔닝

이 워크북의 중심은 “예쁜 학습 대시보드”가 아니다.

실제 제품에서 화면의 주인공은 다음 요소들이 되어야 한다.

1. **Interactive Exercise**
2. **Live Preview**
3. **Mission**
4. **Visual Explanation**
5. **My Project**
6. **Achievement**

즉, 사용자가 콘텐츠를 소비하는 서비스가 아니라

> **사용자의 프로젝트를 실제로 완성시키는 인터랙티브 학습 도구**

로 정의한다.
