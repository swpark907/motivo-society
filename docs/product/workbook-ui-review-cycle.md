# 워크북 버튼과 여백 개선 및 검수 계획

2026-10-26. 목표는 입문자가 화면을 읽으며 지금 할 행동과 그 결과를 쉽게 알아보게 하는 것이다. 구현 세션은 아래 첫 묶음부터 반영하고, QA 검수와 피드백을 거쳐 다음 묶음으로 진행한다. 이번 준비 작업에서는 제품 코드를 수정하지 않았다.

## 공통 설계 기준

주 동작은 지금 결과를 만드는 실행이다. 선택은 결과를 살펴볼 대상을 고르는 조작이다. 보조 동작은 전체 보기·재시작·되돌리기다. 수업 이동은 이 세 가지와 별도 역할이다. 버튼 순서나 첫 번째 자식 여부로 역할을 추론하지 말고 명시적으로 스타일을 부여한다. 주 동작이 없어진 최종 상태에 재시작을 자동으로 주 동작으로 승격하지 않는다.

오렌지 채움은 화면 전체에서 경쟁하지 않게 쓴다. 본문 실행과 수업 이동을 둘 다 강하게 채우지 않는다. 화면별로 강조 버튼을 오락가락 바꾸기보다 전체 수업에서 반복 가능한 규칙을 먼저 확정한다. 선택 상태·정오답·포커스는 각각 다른 의미로 읽혀야 한다.

간격의 초기 시안은 제목과 설명 8px, 같은 조작군 내부 8px, 해당 결과와 조작 12~16px, 다른 학습 구간 24px다. 이는 워크북 내부 제안값이며 표준 요구사항이 아니다. 줄바꿈과 읽기 흐름을 보고 조정한다. 고정 높이로 본문을 자르거나 글씨를 줄여 끼워 넣지 않는다. 현재 최소 터치 높이 44px를 유지하되 모든 버튼을 같은 면적의 박스로 그리지 않는다.

외부 참고: [GOV.UK 버튼](https://design-system.service.gov.uk/components/button/)은 복수 주 동작의 경쟁과 과도한 보조 동작을 줄이고 실제 행동을 설명하는 문구를 권한다. 이 원칙을 참고하되 정부 서비스의 시각 디자인을 복제하지 않는다. [W3C 타깃 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)은 예외·간격 조건을 포함한 최소 기준이다. 워크북의 44px는 제품 기준이며 WCAG AA가 무조건 44px를 요구한다고 설명하지 않는다.

## 구현과 검수 순서

1. 첫 구현은 B01~B06과 B10을 1-1·1-4·2-2에 한정한다. 변경 전 세 화면의 기본·중간·최종 펼침을 캡처한다. 공통 강의 CSS를 바꾸면 다른 단원에도 영향이 있으므로 아래 회귀 화면을 함께 확인한다.
2. 구현 담당자는 바꾼 역할·상태별 동작·영향 파일·PC와 모바일 전후 캡처·테스트 결과·남은 문제를 이 문서의 제출 양식으로 보고한다.
3. QA는 화면과 실제 조작으로 통과 기준을 판정한다. ‘클릭됨’과 ‘보기 자연스러움’을 별도로 판정한다. 미통과 항목만 구체적으로 돌려보내며 반복 검수한다.
4. 첫 묶음이 통과하면 B07~B09 후보를 실화면으로 확인하고 같은 규칙을 적용할 다음 구현 묶음을 정한다. 전 수업 일괄 재디자인부터 시작하지 않는다.

검수 환경은 PC 1280×720, 모바일 390×844와 320×740이다. 키보드 Tab·Enter·Space로 선택과 실행을 확인하고, 조작이 사라지면 포커스가 합리적인 위치에 남는지 본다. 모바일 화면은 설명·복습 용도이며 외부 제작 실습 완료로 취급하지 않는다.

회귀 화면은 1-4 요청 직접 편집, 2-2 직접 편집된 요청과 일치하지 않는 연결, 3-3 전후·폭 전환, 4-2 저장 전·저장 후·다시 열기, 5단원 기존 이동이다. 기존 완료·해금·비활성 조건·실제 결과 기록·예시와 실제 구분은 유지한다. 펼침을 필수 체크로 만들거나 선택 연습을 완료 조건에 넣지 않는다.

변경 범위에 맞게 `pnpm check`와 관련 E2E를 실행한다. 공통 CSS나 이동을 수정하면 전체 수업 이동 회귀를 포함한다. 자동 테스트 통과만으로 시각 검수를 통과 처리하지 않는다. 코드 수정 이후에는 저장소의 최신 AGENTS.md와 해당 Next.js 내장 문서를 먼저 읽는다.

## 첫 구현 제출 — 2026-10-26

대상은 B01~B06·B10의 1-1·1-4·2-2다. 앞으로 진행하는 본문 실행만 오렌지 채움으로 표시하고, 선택은 체크·테두리·밑줄로, 전체 보기·되돌리기는 밑줄 보조 버튼으로 구분했다. 수업 이동 위치는 유지하며 다음은 외곽선, 이전은 약한 글자 버튼으로 낮췄다. 최소 터치 높이는 44px를 유지한다. 같은 조작군 8px, 결과·조작 16px, 원문 항목 사이 24px로 구분했다.

1-1 최종 펼침에서는 전체 설명 보기가 사라지고 선택한 메모로 포커스가 이어진다. 문장만 다시 보기는 연결하기 실행으로 돌아간다. 1-4 최종 펼침에서는 전체 예시 보기가 사라지고 결과 설명으로 포커스를 옮긴다. 재시작·조건 제거는 보조 역할을 유지하며 다음 실행으로 포커스를 잇는다. 2-2 전체 보기에서는 단일 선택을 해제하고 네 항목을 보는 상태를 안내한다. 펼침은 기존처럼 선택 사항이다.

독립 QA의 첫 피드백은 **2-2 전체 연결이 오른쪽 열만 쓰고 왼쪽에는 단일 출처 카드가 남는 문제**였다. 전체 보기에서 출처 열을 숨기고 원문 연결 영역이 본문 전체 폭을 사용하도록 보정했다. 한 항목 보기의 PC 두 열과 모바일 원문 중심 구성은 유지한다. 전체→한 부분→전체를 다시 조작했고, 390·320px에서 직접 편집 칸까지 스크롤해 입력과 미일치 안내를 확인했다. 독립 QA가 수정 후 전체 폭·보기 왕복·모바일 편집 접근·원문 보존을 확인해 첫 묶음을 최종 통과 처리했다. 검수 범위와 한계는 [독립 QA 기록](workbook-ui-qa-rounds.md)에 남겼다.
