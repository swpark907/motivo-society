# 내 홈페이지 기획과 첫 화면 — 2026-10-08

사용자 요청에 따라 AI 입문 5수업을 마친 뒤 같은 제작 공방에서 이어가는 작은 단원이다. 새 지도·옛 8장소 지도 복원·전체 4+1 월드 변경은 하지 않는다. 입문에서 만든 `my-first-web/index.html`을 자기 주제로 바꾸며 목적·대상·실제 콘텐츠를 요청과 화면 점검에 연결한다.

## 학습 목표와 활동

1. **홈페이지 기획하기:** 제목, 읽을 사람, 방문자가 할 일, 사실에 기반한 소개·내용을 적는다. 카피바라 예시는 선택형 연습이며 자신의 실제 실적으로 취급하지 않는다. ‘대상’은 읽을 사람, ‘목적’은 읽은 뒤 하게 할 행동으로 본문에서 설명한다.
2. **제작 요청 만들기:** 앞 기획을 요청문으로 만들고 직접 다듬는다. index.html 하나를 변경하며 다른 파일을 건드리지 않는 범위, 제목·소개·목록·버튼의 동작을 명시한다. 기획을 바꾸면 이미 쓴 요청은 자동 덮어쓰지 않으며 새 초안으로 바꾸는 버튼을 따로 제공한다.
3. **첫 화면 확인하기:** 준비된 컴퓨터의 외부 앱 실습 또는 브라우저 안 기획 미리보기를 선택한다. 컴퓨터는 본인 확인으로 변경 파일·화면·버튼을 확인한다. 미리보기는 입력한 기획을 UI에 배치하는 예시로 AI 응답·실제 파일 생성과 구분한다. 방문자 입장에서 확인한 점을 적는다.

## 완료 조건과 상태

기획의 필수 다섯 필드, 작성한 요청, 선택한 활동 방식, 확인한 점이 있어야 한다. 실제 실습은 준비 상태와 파일·화면·버튼의 본인 확인 세 항목, 예시 복습은 기획 미리보기의 내용 보기 버튼을 눌러 확인한다. 선택형 정답 퀴즈로 막지 않는다. 이번 방문의 기록은 부모 상태에 유지하며 지도 왕복·취소 후 다시 읽을 수 있다. 기록을 실제 변경하면 완료를 해제한다. 같은 버튼 반복 클릭은 완료나 기록을 중복시키지 않는다. 새로고침 초기화와 미래 회원별 서버 저장 계획은 유지한다.

## 검사 범위와 남은 범위

진행·이전·취소·요청 보존·완료 후 재방문·모바일 예시와 컴퓨터 실습 구분·키보드·빠른 반복 클릭을 E2E로 확인한다. 기존 AI 입문 5수업 회귀도 단일 worker로 확인하며 브라우저 차례는 GPU 조율 후 진행한다. 외부 앱의 실제 파일 생성·설치 검증은 자동 검사로 표현하지 않는다.

이번 단원 이후 화면 배치·반응형·사용 경험, 동작과 데이터, 공개와 운영, 선택 심화는 아직 완성되지 않았다. 다음 지도 제작은 별도 후속 작업이다.

## Q10 기획 입력과 제작 행동 연결 — 2026-10-13

기존 첫 결과물과 3활동 범위에서 `WorkbookProjectLesson.tsx`의 설명만 보완했다. 기획 입력 뒤 같은 내용을 다시 적지 않고 초안으로 이어간다는 다음 행동을 표시한다. 제작 요청 단계는 현재 독자/목적과 제목·소개·실제 내용의 전달을 보여주고 준비된 요청 틀/본인 입력/실제 AI 응답·파일 결과를 구분한다. 초안을 읽고 의도에 맞게 다듬은 뒤 준비한 외부 코드 에이전트에 전달하고 같은 index.html과 목록 이동을 확인하는 순서를 설명한다. 긴 본인 입력은 기존 문단에서 줄바꿈하도록 했고 새 입력/카드/회원·보상 기능은 없다.

## 같은 프로젝트의 자기 초안으로 이어가는 보강 원고 — 2026-10-20

아래는 승인된 2단원 목표를 반영한 후속 원고다. 위 기존 화면·판정·방문 기록 설명은 구현 이력으로 보존한다. 이번 보강은 원고이며 요청 생성기·필수 입력·완료 조건·화면·저장 구조는 바꾸지 않는다.

### 도입 — 첫 파일에 내 기획을 담아요

앞 단원에서 `my-first-web/index.html`을 만들고 제목을 바꿔봤어요. 이제 **그 파일을 그대로 이어서** 내 페이지의 첫 초안을 만들 거예요. 새 예제를 처음부터 다시 만들 필요는 없어요.

첫 파일이 없다면 앞 단원의 파일 만들기부터 이어가요. 예시 복습으로 들어왔다면 이번에도 기획 미리보기로 원리를 익힐 수 있어요. 미리보기가 자기 컴퓨터의 파일을 만드는 것은 아니에요.

### 활동 1 — 누구에게 무엇을 보여줄까요?

페이지를 처음 보는 한 사람을 떠올려봐요. 무엇을 알게 되고 어떤 행동을 할 수 있으면 좋을까요? **제목·읽을 사람·방문자가 할 일·소개·실제 내용**을 정리해요. 앞에서 쓴 소개가 맞으면 그대로 쓰고 달라진 부분만 고쳐요.

| 선택한 목적 | 기획 예시                                       | 첫 초안에서 확인할 행동                          |
| ----------- | ----------------------------------------------- | ------------------------------------------------ |
| 서비스 소개 | 도울 사람·실제로 제공하는 내용·가능한 다음 행동 | 제공 내용을 찾고 준비 자료나 실제 연락 수단 확인 |
| 포트폴리오  | 나의 소개·실제 작업·내 역할                     | 관심 작업과 맡은 역할 찾기                       |
| 개인 사이트 | 좋아하는 주제·직접 고른 항목·관련 설명          | 관심 항목을 찾고 설명이나 관련 링크 읽기         |

작업이 하나뿐이어도 괜찮아요. 아직 없는 실적이나 이용자 수를 채우지 않아요. 주제가 떠오르지 않으면 공통 카피바라 쉼 모음으로 직접 만들어도 좋아요. 연습용 내용임을 표시하고 자기 경험으로 소개하지 않아요.

**이번에 필요한 자료부터** 고른다. 제목·소개·확인할 본문은 지금 준비하고, 장식 사진이나 나중에 추가할 글은 없어도 초안을 만들 수 있다. 사진이 없으면 생략하며 확인되지 않은 이미지 주소를 넣지 않는다. 신청 수단이 없으면 작동하는 신청 버튼처럼 만들지 않는다. 다음 행동은 본문으로 이동하거나 실제 관련 링크를 여는 것으로도 충분하다.

### 활동 2 — 새 사이트 대신 같은 파일을 수정해요

기획을 요청에 담고 **현재 파일에서 바꿀 내용과 유지할 것**을 함께 적어요. 자동으로 만든 요청 초안은 읽고 고친 뒤 외부 에이전트에 직접 전달해요. 기획을 바꿨다면 이전 요청과 달라진 부분부터 확인해요. 직접 편집한 요청을 새 초안으로 덮어쓰지 않아요.

**제작 요청 틀**

> 현재 my-first-web 폴더의 index.html을 먼저 읽어줘. 앞 단원에서 만든 같은 프로젝트를 아래 기획에 맞는 한 페이지 초안으로 수정해줘. 새 폴더나 별도 예제를 만들지 마.
>
> 제목: [제목]
> 읽을 사람: [대상]
> 방문자가 할 일: [목적]
> 소개: [사실에 맞는 소개]
> 본문에 담을 실제 내용: [항목별 내용과 역할·설명·실제 링크]
>
> 방문자가 제목과 소개를 읽고 주요 내용을 찾을 수 있도록 구성해줘. 주요 버튼은 [실제 목적지 또는 페이지 안 내용]으로 연결해줘. 앞 파일의 [유지할 내용이나 동작]은 유지하고, 연습용 제목과 임시 소개 중 기획과 다른 부분만 교체해줘. 없는 실적·후기·주소·연락처는 만들지 마. 아직 로그인·결제·문의 접수·저장은 추가하지 마. 이번에는 index.html만 수정하고 설치·배포는 하지 마. 다른 파일이 꼭 필요하면 이유와 변경 범위를 먼저 알려줘. 작업 후 변경 파일과 확인할 행동을 알려줘.

대괄호를 채운 뒤 보낸다. 실제 목적지가 없다면 버튼 문구와 역할을 바꾸고, 빈 링크를 정상 동작으로 인정하지 않는다. 여기서는 첫 초안에 집중하고 상세 보기·저장 여부는 4단원에서 판단한다. 필요한 CSS·이미지·스크립트 분리는 이후 같은 폴더 안에서 이어갈 수 있지만 이번 초안 활동에서 설치나 파일 확장을 필수로 만들지 않는다.

### 활동 3 — 방문자처럼 첫 초안을 확인해요

같은 `index.html`을 브라우저로 열고 새로고침해요. 에이전트가 보여준 설명이나 미리보기만으로 끝내지 말고 **실제 파일에서** 다음을 확인해요.

1. **목적:** 제목과 소개를 읽으면 누구를 위한 어떤 페이지인지 알 수 있나요?
2. **내용:** 요청한 실제 내용이 들어갔나요? 임시 문구나 내가 알려주지 않은 실적이 남아 있지 않나요?
3. **행동:** 주요 링크·버튼을 누르면 의도한 내용이나 실제 주소로 연결되나요?

빠진 내용이나 잘못된 부분이 있다면 해당 부분만 짚어 고쳐요.

> 같은 index.html에서 [빠지거나 잘못된 내용]을 [정확한 내용]으로 수정해줘. [맞는 소개·목록·기존 버튼]은 유지해줘. 수정 후 어떤 파일을 바꿨는지 알려줘.

변경 파일을 확인하고 같은 화면을 새로고침한 뒤 해당 내용과 기존 주요 행동을 다시 확인한다. 오류가 없으면 일부러 수정할 필요는 없다. ‘더 멋지게 전부 바꿔줘’보다 관찰한 누락이나 내용 문제부터 고친다. 디자인·반응형의 세밀한 개선은 다음 단원으로 넘긴다.

**확인 결과 문장 예시**

- 서비스 소개: ‘제공 항목과 제외 범위가 실제 내용과 맞고, 안내 링크가 의도한 곳으로 열린다.’
- 포트폴리오: ‘작업에서 맡은 역할을 추가했고, 기존 작업 링크도 다시 열어봤다.’
- 개인 사이트: ‘추천 이유는 맞지만 링크 하나가 잘못되어 수정 후 다시 확인했다.’

이는 작성 형식 예시다. 본인이 하지 않은 확인을 그대로 제출하도록 요구하지 않는다. 해결되지 않은 핵심 내용·행동 문제는 남은 작업으로 기록하고 성공 표시로 바꾸지 않는다.

### 단원 마무리 — 다음에는 화면을 살펴봐요

첫 파일이 내 콘텐츠를 담은 초안이 됐어요. 다음 단원에서는 **같은 파일을 PC와 모바일 폭에서 보고**, 읽기나 탐색에 중요한 부분을 개선해요. 지금 초안과 비교할 수 있도록 필요한 경우 화면을 남겨도 좋지만 캡처는 필수가 아니에요.

인계할 결과는 기존 기획·편집한 요청·같은 폴더의 초안·확인한 주요 행동·남은 문제다. 다음 단원에서 같은 기획을 다시 작성하게 하지 않는다. 기존 방문 메모리의 새로고침 초기화는 그대로이며 이 원고의 ‘이어간다’가 회원 저장·영구 진도 저장을 약속하지 않는다. 예시 미리보기와 실제 파일 적용은 계속 구분한다.
