# 첫 맵의 4·5수업 — 2026-10-07

사용자 요청으로 첫 맵을 끝까지 연결한다. 첫 맵은 AI 입문 5개 장소이며 기존 8장소 제작 기획은 이 지도에 적용하지 않는다. 전체 클래스의 4+1 월드 구성을 변경한 것은 아니다.

## 4수업: AI와 첫 대화

대화 서재에서 소개문을 요청하고, 길이·내용·사실을 확인한 뒤 바꿀 것과 유지할 것을 짚어 수정한다. 프롬프트의 뜻과 무엇을·누구에게·어떤 조건으로 요청하는지 설명한다. 첫 요청은 답변만 하도록 하며 파일 변경은 다음 수업으로 넘긴다.

1. 설명 3단계: 프롬프트 → 요청·확인·수정 → 컴퓨터 실습/예시 복습 선택.
2. 활동: 첫 요청 작성/예시 가져오기 → 결과 확인 → 확인한 점 기록 → 수정 요청 → 수정 결과 비교.
3. 정리: 구체적인 수정 요청 확인 문제. 컴퓨터 실습은 직접 요청·답변 확인·수정 후 비교의 본인 확인 3개를 요구한다. 예시 복습은 사전 결과·수정 결과를 열고 기록을 남긴다.

## 5수업: 에이전트와 바이브코딩

첫 제작 공방에서 코드 답변과 실제 파일 변경을 구분한다. 자연어 요청 → 코드 제작 → 실행·확인 → 수정이라는 바이브코딩 흐름을 설명하고 HTML 파일 하나로 작게 경험한다.

1. 설명 3단계: 모델과 파일·실행 도구 → 바이브코딩과 사람의 판단 → 실습/복습 선택.
2. 활동: my-first-web 안의 index.html 하나만 만들기. 제목·소개·작업 목록과 목록으로 이동하는 버튼을 요청한다. 설치·외부 서비스·로그인·배포는 요구하지 않는다. Windows 파일 탐색기/Mac Finder에서 브라우저로 열고 버튼까지 확인한 뒤 제목을 바꾸고 새로고침해 재확인한다. 파일이 이미 있으면 먼저 내용을 확인한다. 막히면 오류를 전달하거나 예시 복습으로 전환한다.
3. 정리: 완료 메시지 대신 파일·화면·동작으로 판단하는 확인 문제. 실제 실습은 변경 파일·브라우저 실행/버튼·수정 후 재확인의 본인 확인을 요구한다. 예시는 사전 화면의 버튼을 누르고 수정 전후를 비교한다.

## 기록과 완료

- 3수업의 준비 설명/복습을 마치면 4수업의 예시 복습에 접근할 수 있다. 실제 실습 선택은 컴퓨터 준비 확인 상태에서만 가능하다.
- 4수업을 마치면 5수업이 열린다. 다섯 수업의 학습 정리 완료와 실제 외부 도구 실습 완료를 구분한다.
- 첫 요청·관찰·수정 요청은 지도에 나갔다 돌아와도 이번 방문 동안 유지한다. 새로고침하면 초기화한다. 회원·클라우드 동기화는 없다.
- 마지막에는 4·5수업의 기록을 펼쳐 보고, 이전 장소를 다시 방문할 수 있다. 다음 맵은 준비 중이며 열리는 것처럼 표시하지 않는다.
- 예시에는 실제 AI 호출이 없고 입력한 요청에 따른 실시간 결과가 아님을 표시한다. 실제 컴퓨터 실습은 본인 기록으로 외부 파일 자동 검사와 구분한다.

## 프로젝트 연계 보강 원고 — 2026-10-20

아래는 승인된 같은 프로젝트 흐름을 반영한 후속 원고다. 앞부분의 화면·완료·‘다음 맵 준비 중’ 설명은 당시 구현 이력이며, 아래 원고가 현재 화면에 적용됐다는 뜻이 아니다. 실제 Windows/Mac 설치·권한·파일 열기 검증은 남아 있다. 이번에는 수업 코드·판정을 변경하지 않는다.

### 1단원 앞 수업과의 연결

- AI 이해하기의 정리: “다음에는 AI의 도움으로 작은 웹페이지를 만들 거예요. 문장과 코드를 제안받아도 **사실에 맞는지, 원하는 결과인지 확인하는 일**은 우리가 해요.” 기존 예시의 작업·성과를 학습자 자신의 경험으로 넘기지 않는다.
- AI 종류와 도구의 정리: “이 클래스에서는 소개 글을 다듬고 홈페이지 파일을 만들 거예요. 파일을 만드는 단계에서는 **내 작업 폴더를 읽고 수정할 수 있는 환경**을 준비해요.” 새로운 제품명·요금·OS 조건을 추가하지 않는다.
- 도구 준비의 정리: “준비한 `my-first-web` 폴더는 다음 단원에서도 계속 써요. 지금은 폴더를 연결하고 요청할 자리를 찾으면 충분해요.” 폴더가 이미 있다면 빈 폴더로 다시 만들거나 내용을 지우게 하지 않는다.

### 4수업 보강 — 먼저 소개 글을 요청해요

**도입**

홈페이지에 담을 짧은 소개부터 부탁해볼게요. 아직 주제를 정하지 않았다면 ‘지금 배우는 내용을 기록하는 페이지’로 시작해도 좋아요. 이 소개는 다음 수업의 첫 화면에 쓸 수 있고, 기획을 정한 뒤 다시 바꿔도 돼요.

이번에는 **문장으로 답해 달라고 요청**해요. 답변이 나왔다고 홈페이지 파일까지 만들어진 것은 아니에요.

**첫 요청 예시**

> 웹페이지에 넣을 짧은 소개를 두 문장으로 써줘. 이 페이지에는 내가 앞으로 배우고 만들어볼 내용을 기록하려고 해. 아직 공개할 작업이나 실적은 없어. 없는 경험이나 숫자를 덧붙이지 말고 쉬운 말로 써줘. 지금은 문장으로만 답하고 파일은 만들거나 수정하지 마.

이미 자기 주제가 있다면 사실인 내용으로 바꿔 요청한다. 주제가 없다는 이유로 기획 다섯 항목을 먼저 완성하도록 요구하지 않는다. 공통 카피바라 예시를 사용하면 ‘연습용 설정’임을 표시한다.

**확인과 수정**

결과에서 내가 알려준 내용과 AI가 새로 덧붙인 내용을 살펴봐요. 사실이 아니거나 너무 거창한 표현은 바꿔요. 맞는 부분은 남겨두고 **바꿀 부분과 유지할 부분**을 함께 부탁해요.

> 배우는 내용을 기록한다는 뜻은 유지해줘. 마지막 문장은 더 짧게 바꾸고, 전문가처럼 보이는 표현은 빼줘. 파일은 아직 수정하지 마.

수정 전후를 읽고 뜻·길이·사실을 다시 확인한다. 실제 응답이 다를 수 있으므로 예시 문장이 그대로 나오는 것을 통과 조건으로 삼지 않는다. 확인한 소개는 다음 요청에 활용하며 워크북의 기록이 외부 앱으로 자동 전달된다고 설명하지 않는다.

**다음 연결**

소개 글을 다듬었어요. 이제 준비한 폴더에서 **브라우저로 열 수 있는 첫 파일**을 만들 거예요. 다음 수업에서는 답변 내용에 더해 실제 파일과 화면을 확인해요.

### 5수업 보강 — 같은 폴더에 첫 파일을 만들어요

**작업 위치부터 확인**

준비한 코드 에이전트에서 연결된 폴더가 `my-first-web`인지 확인해요. 이미 `index.html`이 있다면 먼저 어떤 내용인지 살펴봐요. 다른 수업이나 개인 작업 파일이라면 덮어쓰지 말고 실습 위치부터 확인해요.

`index.html`은 이번 사이트의 첫 화면을 담을 파일 이름이에요. 처음에는 파일 하나로 작게 시작해요. 이 폴더와 파일을 **2단원에서 내 주제를 담은 초안으로 계속 발전**시킬 거예요.

**제작 요청 예시**

> 현재 연결된 my-first-web 폴더를 먼저 확인해줘. index.html이 없으면 이 파일 하나로 작은 한국어 웹페이지를 만들어줘. 제목은 ‘나의 첫 웹페이지’, 소개는 아래 문장, 목록은 ‘앞으로 기록할 내용’과 사실인 항목으로 구성해줘. 목록으로 이동하는 버튼을 하나 넣어줘. 아직 항목이 없다면 준비 중이라고 표시하고 가짜 실적은 만들지 마. 다른 파일은 수정하지 말고 패키지 설치·외부 서비스·로그인·배포는 하지 마. index.html이 이미 있으면 내용을 먼저 설명하고 보존할 부분과 수정 범위를 확인한 뒤 작업해줘. 작업 뒤 바꾼 파일과 브라우저로 확인할 방법을 알려줘.
>
> 소개: [앞 수업에서 확인한 소개 문장]
> 목록에 넣을 내용: [실제로 쓸 내용 또는 준비 중]

대괄호는 전달 전에 자기 내용으로 바꾼다. 기존 파일이 있으면 무조건 새로 생성하는 요청을 보내지 않는다. 요청에 쓴 폴더 이름보다 실제 앱에 연결된 위치가 우선이므로 두 위치를 대조한다.

**파일 → 화면 → 행동 확인**

1. 에이전트의 완료 문장과 별개로, `my-first-web` 안에 실제 `index.html`이 생겼거나 변경됐는지 확인해요.
2. Windows에서는 파일 탐색기, Mac에서는 Finder에서 그 파일을 찾아 브라우저로 열어요. 코드 편집기로 열렸다면 ‘연결 프로그램’ 또는 ‘다음으로 열기’에서 브라우저를 선택하는 경로를 확인해요. 정확한 메뉴·화면은 OS별 실습 검증 후 보강해요.
3. 제목·소개·목록이 보이는지 읽고 버튼을 눌러 목록으로 이동하는지 확인해요. 파일을 연 주소는 내 컴퓨터의 파일 위치이며 다른 사람이 접속할 공개 주소는 아니에요.
4. 같은 파일의 제목을 ‘배우며 만드는 기록’ 등 원하는 문장으로 바꿔 달라고 요청해요. 소개·목록·버튼은 유지하도록 알려줘요. 파일 변경 후 같은 화면을 새로고침해 제목과 기존 버튼을 다시 확인해요.

**단원 마무리와 인계**

AI에게 요청하고, 파일을 찾고, 화면에서 확인하고, 다시 수정했어요. 지금은 디자인을 완성하지 않아도 괜찮아요. 다음 단원에서는 **같은 파일에 누구를 위한 페이지인지, 무엇을 보여줄지**를 담아요.

이어갈 것은 작업 폴더·첫 HTML·브라우저로 여는 방법·확인한 소개다. 확인할 기준은 같은 파일의 변경과 화면 반영이며 캡처나 코드 암기는 요구하지 않는다. 예시만 본 사람은 학습 확인으로 남기고 2단원 설명을 읽을 수 있지만 자기 파일 적용을 시작할 때는 이 준비와 첫 파일부터 이어간다.
