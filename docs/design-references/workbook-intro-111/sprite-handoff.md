# 워크북 1-1-1 카피바라 스프라이트 인계

2026-10-29 · 사용자 지시: 스프라이트 제작은 다른 세션에서 진행한다. 이 문서는 제작 인계이며 완성·승인 기록이 아니다.

## 기준 이미지 — 사용자 선택

- **사용자가 가장 적당하다고 선택한 이미지:** [intro-capy-pixel-v1.png](../../../public/images/workbook/intro-capy-pixel-v1.png). 이 파일은 사용자가 첨부한 `exec-b4681589-2f73-4207-a037-8aa3186ef0c1.png`과 바이트 단위로 동일하다.
- 기준은 이미지의 **카피바라 모습, 픽셀아트 톤, 둥근 검은 선글라스·검은 넥타이, 책상과 의자의 분위기, 여백 있는 배경**이다. 이 4×4 그림을 완성된 애니메이션 시트로 간주하지 않는다.
- 이후 생성한 이미지들이 책상 크기·형태와 캐릭터 위치가 들쭉날쭉해 사용자가 실망을 표현했다. 최신 후보라는 이유로 다른 이미지의 톤이나 가구를 기준으로 삼지 않는다.

## 원하는 이야기와 동작

1. 서 있는 카피바라가 인사한다.
2. 책상과 의자가 갑자기 나타난다.
3. 카피바라가 잠깐 놀란다.
4. 이내 익숙한 듯 책상에 앉아 공부를 시작한다.
5. 착석 후 타이핑, 머리를 짚으며 생각하기, 턱 괴기, 펜으로 노트에 적기 등의 동작을 차분히 반복한다.

도입은 한 번, 공부 장면은 반복한다. 오른쪽의 강의 소개 페이지가 전환되는 속도와 캐릭터 동작을 맞추지 않는다. 이미지는 조금 작고 여백이 있어도 좋다. 전체 작업실을 보여줄 필요는 없다.

## 제작·검수 기준

- 인사부터 공부까지 **하나의 전체 시트/마스터**를 먼저 만들고, 그 안의 공부 구간을 잘라 반복하는 방향을 사용자가 제안했다. 반복을 위한 별도 생성으로 캐릭터나 가구의 외형·색이 바뀌지 않게 한다.
- 고정 카메라·바닥선·캐릭터 비율·책상/의자/노트북의 크기와 위치를 프레임 단위로 맞춘다. 책상 등장 자체는 의도된 변화지만 등장 후 소품이 튀거나 바뀌면 안 된다.
- 인사, 놀람, 걷기·착석과 손을 올리고 내리는 중간 자세를 충분히 제작한다. 타이핑·머리 짚기·턱 괴기·펜 집기/쓰기의 전환이 한 프레임에서 갑자기 바뀌지 않아야 한다.
- 각 프레임은 같은 캔버스·배경·색감이고 캐릭터, 가구가 잘리지 않아야 한다. 이웃 프레임 조각이 새어 나오지 않아야 한다. 재생 중 프레임 위치·크기 흔들림이 없어야 한다.
- 첫 전체 재생에서 공부 반복으로, 반복 마지막에서 처음으로 연결되는 경계를 실제 속도로 확인한다. 정지 조작·`prefers-reduced-motion` 정지 상태와 PC·모바일도 확인한다.
- 20~30대 학습자를 위한 보조 경험이다. 캐릭터는 선생이 아니라 함께 공부하는 동료이며 읽는 내용을 방해하지 않는다.

위 사용자 선택 이미지를 열어 확인한 뒤, 동작·공통 기준점·프레임 규격부터 정하고 제작한다. 정지 이미지 몇 장의 페이드나 단순 반복을 영상 같은 중간 동작으로 보고하지 않는다. 완성 여부는 전체 프레임과 실제 재생의 흔들림·잘림·색감·도입/반복 경계로 검증한다.

## 2026-10-30 · PixelLab 레이어 방식 착수

사용자 승인으로 전체 시트 생성 대신 레이어를 나눈다. 앞선 실패의 원인이 매 프레임 가구를 다시 그리는 데 있었기 때문이다.

- **고정 레이어(한 번만 제작):** 의자(캐릭터 뒤) · 책상·노트북·공책(캐릭터 앞). 공책은 메모 동작을 위해 기준 그림에 새로 추가해야 한다. 겹침 순서: 의자 → 캐릭터 → 책상 앞면·노트북.
- **코드 연출:** 책상이 나타나는 장면은 가구 레이어의 짧은 등장, 놀람 표시는 별도 작은 그림으로 처리한다. 생성 이미지로 가구 등장을 그리지 않는다.
- **PixelLab 생성 대상:** 캐릭터만 생성한다. 먼저 앉은 중립 자세 하나를 확정하고, 타이핑·메모·머리 긁기·턱 괴기 루프는 모두 이 자세에서 시작해 이 자세로 돌아오게 한다. 루프 순서는 코드에서 섞는다.
- **착석:** 걷기·착석 전체 동작은 마지막에 판단한다. 어려우면 놀람 뒤 짧은 컷 전환으로 대체한다.
- **기준 크롭:** `pixellab-ref/`에 사용자 선택 시트의 서기·인사·앉기·타이핑 칸을 128px로 줄인 PNG와 4배 확대 미리보기를 둔다. 원본은 진짜 픽셀 그리드가 아닌 픽셀풍 그림이라(경계 안티앨리어싱) 크기를 줄인 뒤 32색으로 정리했다. 미리보기 파일은 검토용이며 PixelLab 입력에는 `*-128.png`를 쓴다.
- **막힌 것:** 이 레포 세션에는 PixelLab MCP가 연결돼 있지 않다. 연결된 뒤 앉은 중립 자세와 타이핑 루프부터 시범 제작한다.

## 2026-10-30 · 앉은 기준 자세와 타이핑 루프 시범

- PixelLab MCP 연결 후 `create_image_pro`(캐릭터만, 투명 128px)로 앉은 중립 후보 4개를 만들었다. 사용자가 **c2**를 기준 자세로 선택했다 → `pixellab-gen/seated-neutral-base.png`. 기준 그림과 달리 어두운 외곽선이 있고 앞팔이 키보드 높이까지 뻗지 않은 점은 알려진 차이다.
- 타이핑 루프: `animate_image`에서 첫·마지막 프레임을 기준 자세로 고정해 8프레임 두 벌(`typing-a/` 시드 111, `typing-b/` 시드 222)을 만들었다. 각 폴더의 `f0`은 기준 자세, `f8`은 기준과 거의 같은 복귀 프레임이라 반복 재생에는 `f0~f7`만 쓴다. 미리보기는 `typing-*-preview.gif`(120ms).
- 측정: 모든 프레임의 캐릭터 경계가 ±1~2px 안이라 위치 흔들림은 작다. A는 머리 영역이 여러 프레임에서 크게 다시 그려지고, B는 두 프레임에서만 머리가 1px 내려간다. **사용자가 B를 채택했다.** 책상 레이어와 겹친 확인은 아직이다.
- 사용량: 후보 10 + 루프 2×2 = 14생성.
- 메모·머리 짚기·턱 괴기(각 12프레임, 시드 222, 9생성)를 동작 설명만으로 시도했다(`memo/`, `think/`, `chin/`). **세 개 모두 불합격.** 메모는 펜 없이 입을 벌려 먹는 모습, 머리 짚기는 두 손으로 얼굴을 감싸는 모습, 턱 괴기는 두 손을 입에 댄 모습이 나왔다. 셋 다 몸이 3~4px 내려앉는다. 비교: `rejected-loops-keyframes.png`(기준·메모·머리 짚기·턱 괴기 핵심 프레임).
- 원인 추정: 설명만 주고 끝 자세를 기준 자세로 고정하면, 모델이 설치류의 '앞발을 입으로' 자세로 끌려간다. 다음 시도는 **목표 핵심 자세 한 장을 먼저 만들고 승인받은 뒤**, 기준 → 핵심 자세 보간으로 만들고 복귀는 역재생하는 방식을 제안했다.
- 핵심 자세 후보: `edit_image_pro_flash`로 기준 자세에서 팔만 바꾸도록 지시해 동작별 2개씩 만들었다(`keyposes/{memo,think,chin}-s{11,22}.png`, 비교 `keyposes-compare.png`). 6장 모두 몸·발 위치가 기준과 1~2px 안에서 맞고 입은 닫혀 있다. 머리 짚기는 팔이 머리를 덮어 머리 영역 변화가 크다(의도된 변화). 추천: 메모 s11(s22는 흰 선 잡티), 머리 짚기 s11, 턱 괴기 s11(s22는 손이 입 쪽). 사용자 승인 전. 사용량 누적 23 + 6장 36 = 59생성(부하 실패 2건은 재시도).
- 사용자가 핵심 자세 **s11 세 장**을 확정했다(`keyposes/{memo,think,chin}-key.png`).
- 각 동작은 `기준 → 핵심 자세` 전환(6프레임, `animate_image`에서 끝 프레임 고정)과 핵심 자세에서 시작·복귀하는 유지 루프(메모 쓰기·머리 긁기, 6프레임)로 만들었다. 턱 괴기는 핵심 자세를 정지 유지한다. 복귀는 전환의 역재생이다. 원본은 `loops/`.
- 생성기가 프레임마다 캐릭터 전체를 가로 1px 밀어 그리는 경향이 있어, 움직이지 않는 등·엉덩이·발 영역(x15–55, y70–115)을 기준 자세에 맞춰 정수 픽셀로 정렬했다 → `aligned/`. 정렬 뒤 얼굴은 동작 중 0~2px 안에서 부드럽게만 움직인다.
- 첫 메모 전환(시드 222)은 중간 프레임 내내 머리가 내려앉았다가 끝에서 튀고 펜이 마지막에 갑자기 나타나 탈락. 시드 333으로 전환·유지를 다시 만들어 채택했다.
- 채택본 모음: `aligned/final/{typing,memo-in,memo-hold,think-in,think-hold,chin-in}/f*.png`. 실제 속도 미리보기: `preview-{memo,think,chin}.gif`, 전체 순환 `preview-cycle.gif`(타이핑 3회 → 메모 → 타이핑 2회 → 머리 짚기 → 타이핑 2회 → 턱 괴기, 약 17.6초). 미리보기의 순서·시간은 임시이며 실제 페이지에서는 코드가 섞는다.
- 아직 안 한 것: 책상·의자 레이어와 겹친 확인, 실제 페이지 연결, 모션 줄이기 정지 상태, 인사·놀람·착석.

## 2026-10-30 · 책상 레이어 합성 시도와 사용자 피드백

- 책상(노트·노트북 포함)과 의자를 `create_image_pro`로 따로 만들어(`pixellab-gen/furniture/`, 채택 desk-c0·chair-c0) 의자 → 캐릭터 → 책상 순서로 겹쳤다. 시안 경로 `/demo/workbook-intro-sprite`(테스트 메뉴 등록), 아틀라스 `public/images/workbook/intro-sprite/`, 순서 로직 `src/lib/workbook-intro-sprite.ts`(테스트 포함). 재생 순서·정지·PC/모바일 폭은 확인했다.
- **사용자 판단: 카피바라와 가구가 완전히 따로 논다.** 원인: ① 캐릭터는 굵은 외곽선·큰 픽셀 덩어리, 가구는 얇은 선·작은 디테일로 화풍과 밀도가 다르다 ② 손이 키보드·노트에 닿지 않고 허공에 있다(동작을 가구 없이 만들었기 때문) ③ 의자가 몸 아래가 아니라 등 뒤에 떠 있고 접지 그림자가 없다 ④ 책상이 캐릭터에 비해 작아 장난감처럼 보인다.
- 제안(승인 전): 캐릭터 기준 자세를 고정한 채 같은 그림 안에 의자·책상·노트북·노트를 그려 넣은 **한 장의 기준 장면**을 먼저 확정하고, 동작은 이 장면을 첫·끝 프레임으로 다시 생성한다. 가구가 매 프레임 바뀌던 이전 실패는 동작 영역(머리·팔 주변) 밖의 픽셀을 기준 장면으로 덮어쓰는 후처리로 막는다.
- 사용자 승인으로 기준 장면부터 다시 시작했다(`pixellab-gen/scene/`). 입력은 앞선 겹침 합성(`input-composite.png`). 머리만 고정한 inpaint(s7)는 거의 바뀌지 않아 탈락. `edit_image_pro_flash`로 "가구를 캐릭터 화풍으로 다시 그리고, 의자는 엉덩이 아래·손은 키보드 위·바닥 그림자" 지시한 s7·s8이 한 장면으로 읽힌다(비교 `scene-compare.png`). s7은 캐릭터가 크고 의자가 등 뒤에 걸친 느낌, s8은 캐릭터가 작아지고 의자에 깊이 앉은 느낌. 둘 다 캐릭터 크기·위치가 이전 기준 자세와 달라 핵심 자세·동작은 선택한 장면 기준으로 다시 만든다. 사용자 선택 전.
- 사용자가 **s8을 기준 장면**으로 확정했다 → `scene/base-scene.png`(224×160).
- 장면 전체(224px)로 타이핑을 만들면(`typing-s222`, `typing-s333`) 머리가 프레임마다 0~2px 불규칙하게 흔들리거나 몸이 쏠렸다 튀고, 넥타이 옆 잡티가 생겼다. 탈락.
