# 강의 전용 UI 기준

2026-10-22 사용자 승인. 1~5강 전체에 적용한다. 다른 수업의 점진적 이관을 위한 기준이며 전역 브랜드 테마는 바꾸지 않는다.

## 소유권

- `WorkbookLesson.module.scss`: 강의 프레임, 헤더, 본문, 우측 목표, 진행 동작, 개념·표. 1~5강은 클래스 소개의 `.section`·`.lesson` 스타일을 사용하지 않는다.
- `WorkbookClass.module.scss`: 아직 이관하지 않은 수업의 기존 프레임과 공유 지도·선택지·이미지 등. 1강 전용 개념·표 규칙은 전용 모듈로 이동했다.
- `WorkbookLessonRecap.module.scss`: 공용 정리 컴포넌트. 강의 내부에서는 `--lesson-*` 변수를 따르고, 다른 화면은 기존 기본값을 유지한다.

## 타이포와 간격

| 역할             | 기준                             |
| ---------------- | -------------------------------- |
| 고정 수업명      | 18px / 행간 1.3                  |
| 현재 화면 제목   | PC 32px, 모바일 26px / 행간 1.25 |
| 소제목           | 16px / 행간 1.4                  |
| 본문             | 16px / 행간 1.6 / 기본 글자색    |
| 보조 설명        | 14px                             |
| 메타·진행 표시   | 12px / 낮춘 글자색               |
| 제목과 설명      | 8–12px                           |
| 같은 개념의 항목 | 8–12px                           |

| 본문 바깥        | PC 24px, 모바일 16px             |

헤더는 수업 번호·수업명·짧은 장소명과 탐색을 묶는다. 현재 진행 표시는 헤더 한 곳에만 두고 수업 번호와 설명 단계의 분모를 섞지 않는다. 좁은 폭에서는 자연스럽게 줄을 바꾸고 장소명은 숨긴다.

본문 제목은 그 화면에서 기억할 중심 문장 하나를 표현한다. 질문 제목과 답에 해당하는 개념 제목을 연달아 반복하지 않는다. 예를 들어 첫 설명은 ‘AI = 인공지능’, 세 번째는 ‘자연스러운 답변 ≠ 확인된 사실’로 통합한다. 개념명은 16px의 항목 이름으로, 코드 참고는 14px의 보조 설명으로 구분한다. 모든 문단을 흐린 글자색으로 낮추지 않는다. 영문 풀네임은 작은 보조 정보로 처리한다.

## 반복 UI

- 행동 안내: 지금 누르거나 판단할 일이 있을 때만 작은 안내로 표시한다. 설명 화면의 다음 페이지 예고는 표시하지 않는다.
- 복귀: 안내가 화면 위로 벗어났을 때만 ‘현재 안내로 돌아가기’를 표시한다. 짧은 설명 화면에서는 숨긴다.
- 표: 실제 `table`, 열·행 머리글의 `scope`, 일정한 셀 여백과 명시한 열 너비를 쓴다. 결과 예시는 같은 너비의 3열, 확인 기준은 항목 25%·질문 75%로 구성한다.
- 코드 참고: 정의·짧은 예시·현재 필요한 설명을 별도 면으로 구분한다. 추가 세부 개념을 기본 화면에 늘리지 않는다.
- 다음 동작: 주요 동작만 강조하고 이전·전체 과정 보기는 보조 텍스트 동작으로 표시한다. 최소 누름 높이는 44px이다.
- 예시 문제: PC에서는 보낸 요청과 AI 결과를 나란히 비교하고, 모바일에서는 요청→결과 순서로 쌓는다. 결과를 연 뒤 확인 질문·보기·이유를 같은 영역에 표시한다. 학습용 가상 결과임을 두 영역 아래에 명시한다.
- 정오답: 선택한 보기 자체에 색·아이콘·글자로 표시하고 이유는 본문에서 설명한다. 정답 여부와 학습 완료 로직은 유지한다.

## 검수

PC 1280×720에서 짧은 설명은 본문 스크롤 없이 읽히는지 확인한다. 모바일·좁은 화면·글자 확대에서는 자연스러운 스크롤을 허용한다. 내용 숨김·고정 높이·작은 글씨로 억지로 맞추지 않는다.

1강 설명 3개, 예시 문제의 오답→정답, 학습 정리와 완료, 단일 진행 표시, URL·뒤로 가기를 PC·모바일에서 검수한다. 실제 캡처로 제목 위계와 정렬도 확인한다.

## 전체 지도 패널

선택한 수업명 → 짧은 설명 → 접힌 학습 주제 → 수업 시작 순서로 읽는다. `WorkbookMapLessonCard`를 다섯 지도와 선택 심화에서 공유한다. 수업 시작은 주 동작 하나로 강조하고 선택 접기는 제공하지 않는다. 다른 수업은 지도에서 직접 선택한다.

목적 선택을 전제로 한 ‘내 목표·목적 바꾸기’, 다음 수업과 선택 수업의 중복 큰 제목, 선택 카드와 겹치는 도착·현재 위치 안내는 제거했다. 수업 카드가 열려 있으면 같은 패널의 ‘다음 학습 찾기’는 숨긴다. 단원 완료 뒤 다음 과정 이동은 유지한다. 기존 학습·제작 기록은 보존하고 이용 안내는 접힌 영역으로 줄인다.

지도 도움말은 실제 맵 이미지 우측 상단에 겹치는 `?` 하나로 통합한다. 호버·키보드 포커스·클릭으로 짧은 설명을 열고 Escape·포커스 이동으로 닫는다. 도움말은 우측 패널의 조작을 가리지 않도록 아이콘 왼쪽에 표시한다.

수업 주제·이용 안내·학습/제작 기록은 `WorkbookPanelDisclosure`를 공유한다. 기본 삼각형 대신 제목·개수·오른쪽 화살표로 열림 상태를 표현한다. 주제 안은 개념명(14px)과 설명(13px)으로, 이용 안내는 항목명과 설명으로 나눈다. 기록의 원문과 기존 수업 해금 조건은 유지한다.

맵 위 조작 버튼은 `WorkbookMapControls`가 소유한다. 전체 여정은 맵 좌측 상단, 도움말은 우측 상단에 겹쳐 놓는다. 물음표는 실제 28×28px·모서리 4px이며 전체 여정도 높이 28px로 맞춘다. `data-map-control`로 지도 공통 버튼의 최소 높이·패딩 규칙에서 제외하고 조작 컴포넌트에서 크기를 정의한다. 브라우저의 실제 크기와 모달 포커스 복귀를 PC·모바일에서 검증한다.

## 2강 적용

2강 전체가 공통 강의 프레임·제목·표·문제·정리 위계를 사용한다. 첫 설명은 ‘도구 이름보다 만들 결과부터 정하기’를 중심 문장으로 두고 소개 글·표지 그림·웹 화면과 필요한 기능을 2열 표로 연결한다. 캐릭터 도입 대사와 다음 설명 예고를 반복하지 않는다.

결과 예시는 세 가지를 같은 위치의 버튼으로 전환하며, 왼쪽의 예시와 오른쪽의 ‘필요한 기능·확인할 점’을 일정한 순서로 비교한다. 모바일은 같은 순서로 쌓는다. 사전 제작한 학습 예시임을 명시하고 실제 AI 실행·파일 제작과 구분한다.

모델과 도구, 웹과 데스크톱 앱, 코드 답변과 에이전트 작업은 같은 열 구조의 표로 구분한다. 도구·모델의 포함 관계는 짧은 조작 예시로 확인하고, 설치 여부만으로 파일 작업 기능을 판단하지 않도록 설명한다. 제품명·반복 예고·긴 부연은 기본 설명에서 줄인다.

확인 문제를 마친 뒤 학습 정리를 별도 화면으로 보여준다. 기존 정답 조건과 학습 기록은 유지한다. 정리에서는 결과와 기능·모델과 도구·실제 파일 작업의 핵심 세 가지 및 다음 수업의 도구 준비를 연결한다. 모바일 헤더는 메뉴 아이콘 자리를 확보하며 좁으면 동작 영역이 자연스럽게 다음 줄로 이어진다.

PC 1280×720에서 2강의 예시 세 가지·개념·확인 문제·정리가 화면 밖으로 넘치지 않는지 검사하고, PC·모바일에서 오답→정답·다음 화면 조건·학습 완료까지 검수한다.

### 2강 흐름 재검수 — 2026-10-23

소개 글·표지 그림·웹 화면은 하나의 ‘작은 쉼’ 소개 페이지로 연결한다. 표지는 강의 홍보 이미지 대신 찻잔과 돌을 담은 간단한 학습용 그림을 사용하고, 웹 화면에서는 같은 글과 그림의 배치를 보여준다. 이는 AI 실행 결과가 아니라 사전 제작한 예시다.

모델·도구 표는 ‘결과 만들기 / 요청하고 결과 다루기’를 먼저 읽고, 정의는 작은 보조 설명으로 읽는다. 결과 비교에서도 필요한 기능은 본문 크기, 확인할 점은 보조 크기로 구분한다. 접속 방식 설명은 아직 소개하지 않은 에이전트를 결론으로 끌어오지 않고 ‘접속 방식과 작업 기능은 별개’로 마무리한 뒤 에이전트 설명으로 이어진다. 관계도는 모델과 도구의 포함 관계, 표는 차이 비교, 확인 문제는 판단 연습이라는 역할을 유지한다. 도움 카드 공용 컴포넌트는 이번 수정 대상이 아니다.

### 선택지와 진행 표시 — 2026-10-23

진행 숫자는 ‘현재 화면 / 수업 전체 화면 수’이며 1강 5개·2강 11개 화면을 기준으로 한다. 설명 묶음마다 분모·번호를 초기화하지 않는다. 현재 주제를 함께 표시하고, 같은 화면 안의 예시 전환·정오답 선택은 숫자를 늘리지 않는다. 마지막 정리는 수업 완료 전의 마지막 화면이며 학습 완료는 별도 완료 동작으로 기록한다.

선택지는 기본 바탕 면·빈 선택 표시·포인터로 조작 가능성을 드러낸다. 호버는 테두리, 키보드 포커스는 외곽선, 선택은 채워진 표시로 구분한다. 정오답은 기존 색·아이콘·글자를 유지한다. 예시를 바꾸는 탭과 답을 고르는 선택지는 역할이 달라 같은 모양으로 통합하지 않는다.

### 3강 적용 — 2026-10-23

공통 프레임·단일 진행 표시·본문 위계·선택지를 사용한다. 수업 전체 12개 화면: 준비 흐름 3 → 앱과 계정 3 → 실습 폴더 3 → 흐름 확인 → 준비 상태 → 학습 정리. 없어진 목적 선택의 연결 안내와 도입 대사·반복 예고를 제거한다. 긴 설치·폴더 설명은 순서와 확인할 결과 중심으로 정리하며 OS 전환·예시 조작은 화면 번호를 바꾸지 않는다.

마지막 화면에 겹쳐 있던 확인 문제·실제 준비 상태·학습 정리를 분리한다. 기존 정답, 컴퓨터 본인 확인 3항목과 준비/대기/복습 상태 구분은 유지한다. 체크를 철회하면 준비 상태를 다시 확인한다. 모바일 복습을 실제 컴퓨터 준비 완료로 기록하지 않는다. 저장된 방문 메모리 키와 과거 기록은 유지한다.

2026-10-23 OpenAI Docs 공식 앱·작업 환경·프로젝트 안내를 확인했다. Windows 설치 방식의 Microsoft Store 단정은 제거하고 공식 OS 안내에서 다운로드·지원 조건을 확인하게 한다. Mac 칩 지원·계정 이용 조건은 공식 안내를 따르며 변경 가능한 가격·타 도구 플랜 설명은 본문에서 제거한다. 로컬 폴더와 프로젝트 연결 링크를 유지한다. 수업 검수는 외부 앱 설치 실행이나 지원 기기 검증을 대체하지 않는다.

### 4강 적용 — 2026-10-23

`WorkbookConversationLesson`이 첫 대화를 소유한다. 5강과 함께 쓰던 긴 실습 화면에서 4강만 분리했으며, 5강의 기존 파일 제작·판정 흐름은 유지한다. 공통 프레임·선택지·입력·간격을 사용하고 전체 화면은 8개: 요청의 기본 → 방식 선택 → 첫 요청 → 답변 확인 → 수정 요청 → 수정 전후 비교 → 학습 확인 → 학습 정리.

첫 요청에는 무엇을·누구에게·어떤 조건으로를, 결과 확인에는 내용·길이·사실을, 수정에는 바꿀 것·유지할 것을 대응시킨다. 요청 복사만으로 AI에 전송되지 않음을 안내하고 같은 외부 앱 대화로 보내게 한다. 예시 복습은 실시간 응답이 아님을 결과마다 밝히며 수정 전후를 나란히 비교한다. 결과를 연 뒤 중복 비활성 열기 버튼은 제거하고 포커스를 결과로 옮긴다.

기존 `PracticeRecord`와 첫 소개 선택 기록, `practice-3-answer`·`exampleStage` 방문 상태를 보존한다. 화면 위치는 새 `conversation-screen`으로 별도 관리한다. 준비 미완료에서는 예시 복습을 허용하고 실제 실습은 준비 확인 후 선택한다. 실제 실습은 기존 세 확인 항목, 예시 복습은 준비된 수정 결과 비교, 공통은 요청·관찰·수정 기록과 문제 정답을 완료 기준으로 유지한다. 기록 수정은 학습 재확인을 요구하며 외부 파일 성공으로 승격하지 않는다.

PC 1280×720에서 기본 화면의 높이와 PC·모바일의 두 실습 경로·오답 재선택·이전 이동·입력 보존·마지막 완료를 검수한다. 외부 AI의 실제 응답을 자동 검사했다고 표현하지 않는다.

### 5강 적용 — 2026-10-23

### 3-1 두 화면에서 문제 찾기 — 2026-10-23

PC·모바일에서 다섯 심화의 세 상황 선택·정오답·왕복 보존과 별도 기록의 작성·진단 안내·정리 연결을 검수한다. 기본 수업과 마지막 정리의 기존 기록 구분도 회귀검수한다. 실제 AI 실행·배포 기능 변경은 없다.

### 본문 간격 재검수 — 2026-10-24

공통 클래스를 사용해도 개별 `p`·표·박스·탭의 margin과 상위 간격이 충돌해 1-3 이후 화면에서 설명/선택지/주의 문구가 붙는 문제가 있었다. `lesson-content-flow` 믹스인으로 본문·개념 설명·실습 묶음·선택 문제·설명 박스의 직접 자식 간격을 한곳에서 정한다. 개별 컴포넌트의 내부 padding/gap과 문서의 바깥 간격을 분리한다.

- 화면 제목 → 첫 내용: 20px.
- 내용 묶음·표·입력·선택지 사이: 기본 16px. 설명 박스 내부는 12px.
- 소제목 → 관련 내용, 이어지는 문단, 보조 안내: 8px.
- 탭 하단의 별도 margin과 본문 직계의 중복 간격 규칙은 제거한다. 간격을 없애 화면에 억지로 맞추지 않고, 붙어 있던 요소를 먼저 분리한다.

1-3의 작업 흐름 박스와 환경 선택 화면을 수정 전후 캡처로 대조하고, 첫 요청·첫 파일·기획부터 후반 실습까지 실제 화면 넘침을 재검수한다. 1-4 확인 문제와 본인 체크가 한 화면에 있는 경우 소제목/체크/보조 안내의 관계를 같은 8px 기준으로 묶는다. 내용·입력·진행 조건은 변경하지 않는다.

### 내용 묶음과 이동 목적지 재구성 — 2026-10-24 후속

수치만 같은 간격으로 두지 않고 같은 행동의 입력·조작은 가까이 묶고, 다음 행동이나 확인으로 넘어갈 때 분리한다. `learningGroup`은 기본 설명/실습 묶음 안의 관련 요소를 담으며, 그 뒤 결과나 다음 절차와 구분한다.

- 1-3: 환경 선택의 안내와 선택지를 함께 읽고 복습 범위 설명은 뒤에 둔다. 설치 안내 링크는 실제로 참고할 설치 단계 안에 배치한다.
- 1-4·1-5: 요청 안내·입력·가져오기/복사를 작성 행동으로 묶는다. 답변 확인 기준과 관찰 기록을 함께 두며, 예시 판단 문제와 실제 앱에서 한 항목 확인은 나눈다.
- 2~4단원: 편집 입력과 실행 버튼, 폭 선택과 같은 페이지 미리보기, 메모 입력과 표시 버튼은 각각 같은 행동으로 묶고 결과 확인은 구분한다.
- 5-2: 주소 선택과 접속 예시 실행을 묶고 마지막으로 실행한 결과 표면은 별도로 둔다. 결과가 선택만으로 바뀌지 않는 기존 학습 동작은 유지한다.
- 본문에 중복으로 접혀 있던 선택 심화는 한 번 펼쳐 상황을 볼 수 있도록 정리한다. 기록·입력·예시/실제 구분·기본 완료 조건은 바꾸지 않는다.

이동 이름은 목적지와 일치시킨다. 수업의 `단원 지도 보기`는 현재 단원 지도, 지도 위 `전체 과정 보기`는 다섯 단원을 살피는 모달, `클래스 소개 보기`는 소개 페이지다. 소개의 `학습으로 돌아가기`는 이번 방문의 지도/수업 위치와 내부 설명 상태를 유지한다. 기존의 첫 미완료 수업으로 강제 이동하는 동작은 제거했다. 학습 위치는 기존 방문 메모리이며 새로고침 복원을 추가한 것은 아니다.

단원 완료 뒤에는 완료 안내와 다음 수업의 번호·이름·시작 버튼을 우선한다. `2단원 지도 먼저 보기`처럼 지도 탐색은 보조 행동이다. 먼저 마쳐야 할 학습이 남았다면 동작하지 않는 시작 버튼 대신 선행 학습으로 안내한다. 단원 복습 기록은 접어서 보존하고, 펼친 경우에만 넓은 완료 화면 레이아웃을 사용한다. 기본 경로 안의 다음 수업 안내도 지도 포인트를 한 번 더 고르게 하는 대신 직접 수업을 연다.

검토 화면 `/demo/workbook-navigation`은 독립된 1단원 완료 상태로 실제 클래스의 이동 UI를 검수한다. 실제 진도·보상을 기록하지 않는다. PC·모바일에서 단원 완료→2-1 직접 시작, 소개 왕복 후 단원·내부 설명 위치 보존, 전체 과정 모달 열기/닫기와 기존 수업 선행·진행·실제 결과 구분을 확인한다.
